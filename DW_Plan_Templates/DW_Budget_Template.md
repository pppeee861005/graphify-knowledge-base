## 一、預算概況

### 💡 成本單位轉換

**根據實際情況選擇單位**：

#### 選項A：Token成本（適合AI 的計算）
```
1 單位 = 100 萬 Token
總預算：    [X] 單位 = [X×100] 萬 Token
預期成本：  [Y] 單位 = [Y×100] 萬 Token（約 $1-X 美金）
應急預留：  [Z] 單位 = [Z×100] 萬 Token（約 $1-Y 美金）
```

#### 選項B：貨幣成本（適合時間/資源消耗）
```
總預算：    $[X] 美金 或 ¥[X] 人民幣
預期成本：  $[Y] 美金
應急預留：  $[Z] 美金
```

#### 選項C：時間成本（適合人力投入）
```
總預算：    [X] 小時
預期成本：  [Y] 小時（最佳估計）
應急預留：  [Z] 小時（應對變化）
```

**選擇最適合你的計劃類型**。

---

### 1.1 預算三要素

```
╔═══════════════════════════════════════════════════════╗
║ 總預算    [X] 單位 ← 絕對上限，不能超過            ║
║           (...詳細説明...)                           ║
║ 預期成本  [Y] 單位 ← 根據歷史數據的估計              ║
║           (...詳細説明...)                           ║
║ 應急預留  [Z] 單位 ← 預留率 XX%，用於應對變化        ║
║           (...詳細説明...)                           ║
╚═══════════════════════════════════════════════════════╝
```

**填寫說明**：
- **總預算**：你願意投入的最大資源量
- **預期成本**：基於過去經驗或類似項目的估計
- **應急預留**：預期成本的百分比（通常30%-70%，見下表）

---

### 1.2 預留率說明

**為什麼要預留？**

根據你的任務複雜度選擇預留率：

| 複雜度 | 預留率 | 適用場景 | 風險因素 |
|--------|--------|---------|---------|
| 簡單 | 20-30% | 單一任務，邏輯清晰 | 變數少 |
| 中等 | 40-50% | 多步驟任務，有互動 | 多個檢查維度 |
| **複雜** | **50-70%** | **涉及多個系統或並行** | **涉及外部依賴** |
| 超複雜 | 70-80% | 有對抗性或不可控因素 | 多項不確定因素 |

**你的計劃複雜度**：[ 選擇一個 ]

**預留率**：[ XX% ]

**理由**：
```
[詳細說明為什麼選擇這個預留率]

例如：
- 需要多次API調用，可能超時（+10%）
- 誤報率可能導致重檢查（+15%）
- 數據不確定性導致重試（+20%）
- 需要額外驗證步驟（+15%）
```

## 二、成本分解

### 2.1 成本構成

**你的計劃成本由哪些部分組成？**

```
總成本 = [組件1] + [組件2] + [組件3] + ... + [預留]
       = [X₁] + [X₂] + [X₃] + ... + [Z]
       = [Total] 單位
```

**填寫步驟**：

1. **識別主要成本驅動因素**
   - 是什麼導致成本？（例如：API調用、人力時間、計算資源）

2. **拆分成可衡量的組件**
   - 例如：數據處理成本 + 分析成本 + 驗證成本

3. **為每個組件估算成本**
   - 基於：頻率 × 單位成本 × 複雜度係數

---

### 2.2 成本拆解表（模版）

**按組件列出所有成本**：

| 組件 | 單位成本 | 數量 | 複雜度係數 | 小計 |
|------|---------|------|-----------|------|
| **[組件1名稱]** | [X] | [Y] | [1.0] | [X×Y×1.0] |
| **[組件2名稱]** | [X] | [Y] | [1.X] | [X×Y×1.X] |
| **[組件3名稱]** | [X] | [Y] | [1.X] | [X×Y×1.X] |
| | | | | |
| **預期成本合計** | | | | **[Total]** |

**填寫說明**：

| 欄位 | 說明 | 例子 |
|------|------|------|
| **組件** | 成本的具體項目 | "API調用"、"人力檢查"、"數據驗證" |
| **單位成本** | 一個單位的成本 | "0.001 單位/次調用" 或 "$10/小時" |
| **數量** | 預計執行多少次 | "1000次" 或 "5小時" |
| **複雜度係數** | 1.0 表示預期複雜度，> 1.0表示高於預期 | 1.0、1.2、1.5 |
| **小計** | 單位成本 × 數量 × 複雜度係數 | = |

| # | 風險場景 | 影響成本 | 備註 | 概率 |
|----|---------|--------|------|------|
| 1 | **[風險1名稱]** | +[X]% | [說明] | [H/M/L] |
| 2 | **[風險2名稱]** | +[X]% | [說明] | [H/M/L] |
| 3 | **[風險3名稱]** | +[X]% | [說明] | [H/M/L] |
| 4 | **[風險4名稱]** | +[X]% | [說明] | [H/M/L] |
| 5 | **[風險5名稱]** | +[X]% | [說明] | [H/M/L] |
| | | | | |
| **最壞情況** | **所有風險同時發生** | **~[X]%** | | |

**填寫說明**：
- **風險場景**：什麼情況下會消耗更多成本？

- **備註**：這個風險為什麼可能發生？
- **概率**：High/Medium/Low（根據過去經驗）

## 三、成本監控策略

### 3.1 四個成本階段

**在執行過程中監控成本並採取相應行動**：

| 階段 | 成本範圍 | 狀態 | 行動 | 目標 |
|------|---------|------|------|------|
| **正常** | 0 - [Y]% | 🟢 | 繼續全功能執行 | 預算充足 |
| **警告** | [Y]% - [Z]% | 🟡 | 進入節省模式 | 開始優化 |
| **臨界** | [Z]% - 100% | 🔴 | 停止新任務，返回已有結果 | 成本緊急 |
| **超限** | > 100% | 🛑 | 立即停止所有操作 | 預算耗盡 |

**根據你的計劃調整百分比**：
- 正常階段：0 到 預期成本/總預算 × 100%
- 警告階段：預期成本% 到 (預期+50%預留)/總預算 × 100%
- 臨界階段：上述% 到 100%

---

### 3.2 四個成本階段的具體行動

#### 階段1：正常運行

**狀態指示**：🟢 綠燈

**監控內容**：
- ✅ [全功能清單1]
- ✅ [全功能清單2]
- ✅ [全功能清單3]

**無需採取任何行動**，繼續運行。

**預期完成時間**：[預期時間]

---

#### 階段2：警告狀態

**狀態指示**：🟡 黃燈（成本達到預期值）

**觸發條件**：
- 成本達到預期值
- 預算消耗 ~[X]%
- 應急預留還有 ~[Y]% 可用

**自動採取的行動**：

**行動1：[優化方案1]**
- 舊：[原始狀態]
- 新：[優化後狀態]
- 效果：成本降低約 [X]%

**行動2：[優化方案2]**
- 保持：[關鍵功能]
- 暫停：[非關鍵功能]
- 確保：[安全邊界]

**這個階段的目標**：用剩餘預留撐過執行週期

**預期持續時間**：[預期時間]

---

#### 階段3：臨界點

**狀態指示**：🔴 紅燈（成本接近上限）

**觸發條件**：
- 成本達到 [X]%
- 剩餘預算只有 [Y]%
- 預留 [Z]% 已經消耗

**自動採取的行動**：

**行動1：立即停止低優先級任務**
- ❌ 停止：[低優先級功能]
- ✅ 保留：[核心功能]

**行動2：返回已有結果**
- 停止進一步的新任務
- 將現有數據編譯成報告
- 標記為「PARTIAL_COMPLETION」

**這個階段的目標**：極限節省成本，保護預算

**預期持續時間**：[預期時間]

---

#### 階段4：超限（不應該發生）

**狀態指示**：🛑 停止符

**如果發生**（說明預估有誤）：
- 🛑 立即停止所有操作
- 🛑 返回已有數據
- 📧 升級給項目經理
- 📊 分析為什麼超支（用於下次改進）

---

## 四、降級策略

### 4.1 什麼時候降級？

降級 = **簡化功能，但保留核心功能**

**不升級給人工，而是自動簡化處理**。

---

### 4.2 降級級別（根據你的計劃自定義）

#### 降級 Level 1：[優化策略1]

**觸發條件**：成本達到 [X]%

**具體做法**：
```
舊：[原始方法]
新：[優化方法]

公式：[優化效果] → 成本 ↓ [X]%
```

**影響**：
- ✅ 節省成本 [X]%
- ⚠️ 風險：[可能的後果]

**何時用**：[適用場景]

---

#### 降級 Level 2：[優化策略2]

**觸發條件**：成本達到 [X]%

**選項A**：[具體優化A]
- 效果：成本削減 [X]%

**選項B**：[具體優化B]
- 效果：成本削減 [X]%

**影響**：
- ✅ 節省成本 [X]%
- ⚠️ 風險：[可能的後果]

**何時用**：[適用場景]

---

#### 降級 Level 3：[最後手段]

**觸發條件**：成本超過 [X]%

**具體做法**：
1. 立即停止所有新的任務
2. 將現有數據編譯成最終報告
3. 標記為「PARTIAL_COMPLETION」或「BUDGET_EXHAUSTED」
4. 不做任何進一步分析

**成本削減**：100%（完全停止）

**影響**：
- ✅ 預算不超支
- ⚠️ 風險：無法保證完整功能

**何時用**：成本已經超支（預估有誤）

---

### 4.3 降級的優先順序

**應該降級的優先順序**（從低優先級開始）：

```
優先級 1（最後才降）：[停止功能1]
  ├─ 原因
  └─ 削減成本 [X]%

優先級 2：[停止功能2]
  ├─ 原因
  └─ 削減成本 [X]%

優先級 3：[停止功能3]
  ├─ 原因
  └─ 削減成本 [X]%

優先級 4（最後手段）：[停止所有功能]
  ├─ 原因
  └─ 削減成本 100%（但功能喪失）
```

## 核心要點

### ✅ 這份預算書包含

1. 明確的預算分配（總預算、預期成本、應急預留）
2. 詳細的成本估算依據（各組件的成本分解）
3. 四個成本階段和對應行動（綠→黃→紅→停止）
4. 多個降級級別（優化選項，從輕到重）
5. 升級場景（何時需要人工介入）
6. 根據實際結果的優化建議（下次改進）

### ❌ 這份文件不包含

- 成本的具體技術實現（由執行者決定）
- 實際執行時的動態成本變化（需要實時監控得出）
