# 📖 DW計劃使用指南 - 計劃7完整示例

**核心目標**：展示完整的Dynamic Workflow使用流程，幫助你从「使用現成場景」進階到「自己設計新Workflow」

**適用讀者**：
- 想快速用DW做決策的人
- 想理解DW設計方法的人
- 想自己設計新Workflow的人

## 第一章：快速開始（5分鐘）

### 🎯 我想快速監控或評估某個對象

**步驟1**：讀「場景導航」章節，找到最符合需求的場景

**步驟2**：打開相應的定義書，快速掃一遍

**步驟3**：告訴Claude Code你的需求（參考格式）

**步驟4**：等待Claude生成詳細計劃

**步驟5**：確認計劃後開始執行

**預計成本**：0.20-0.40單位
**預計時間**：20-40分鐘

## 第三章：使用步驟（標準流程）

### 🔄 完整使用流程

#### 步驟1：打開定義書

- **位置**：相應場景的定義書.md
- **目標**：快速理解場景的本質
  - 這個場景解決什麼問題？
  - 成功的標準是什麼？
  - 怎麼執行？
  - 成本預期多少？
- **時間**：10-15分鐘

#### 步驟2：打開預算控制書

- **位置**：相應場景的預算控制.md
- **目標**：理解成本構成
  - 為什麼要預留這麼多預算？
  - 成本怎麼分配？
  - 怎麼監控成本？
  - 超支怎麼辦？
- **時間**：5-10分鐘

#### 步驟3：準備你的數據

準備什麼：
- 要分析的對象（代碼、名單、指標）
- 特定參數（價位、截止日期等）
- 特殊要求（特別關心的維度）
- 預算預期

**時間**：5分鐘

#### 步驟4：告訴Claude Code你的需求（明確指令）

**格式**：
```
「我想用[場景名稱]驗證/監控[對象]，
  [具體參數]
  預算[金額]單位。

  ⚠️ 請先生成詳細的Workflow計劃，包含：
  • 執行流程分解（每個環節的具體步驟）
  • 成本明細清單（逐項成本和風險評估）
  • 時間進度預估（樂觀/標準/悲觀耗時）
  • 風險評估表（潛在風險和應對方案）

  然後提供用戶確認清單（A-E五個層面），
  等我確認無誤後再開始執行，
  不要直接執行分析。」
```

**例子**：
```
「我想用三維獵殺驗證股票AAAA，
  買入價位是150元，
  特別關心現金流，
  預算0.25單位。

  ⚠️ 請先生成詳細的Workflow計劃，包含：
  • 執行流程分解（每個環節的具體步驟）
  • 成本明細清單（逐項成本和風險評估）
  • 時間進度預估（樂觀/標準/悲觀耗時）
  • 風險評估表（潛在風險和應對方案）

  然後提供用戶確認清單，
  等我確認無誤後再開始執行，
  不要直接執行分析。」
```

**強制規則**：
✅ 先生成計劃，絕不直接執行
✅ 提供完整的「用戶確認清單」
✅ 等待用戶明確說「確認無誤」
✅ 如果用戶要求修改，生成調整後的新計劃再次確認
✅ 只有用戶二次確認後才開始執行

**時間**：1分鐘

#### 步驟4.5：Claude生成詳細計劃+用戶確認（🆕 新增）

Claude Code會生成「詳細執行計劃」，包含：

**A. 執行流程分解**
- 完整的步驟拆解
- 每步耗時估計
- 依賴關係

**B. 成本明細清單**
- 每個環節的成本
- 預計總成本
- 超支風險評估

**C. 時間進度預估**
- 樂觀/標準/悲觀耗時
- 可能延遲因素
- 應對方案

**D. 風險評估表**
- 潛在風險清單
- 影響級別
- 應對方案

**用戶確認清單**：
```
□ A.執行流程 - 順序和內容確認
□ B.成本估算 - 金額和預留確認
□ C.時間預估 - 耗時和延遲容忍度確認
□ D.風險評估 - 風險識別和應對確認
□ E.最終確認 - 準備執行或需要調整
```

**用戶可能的回應**：
1. 「完全同意，按這個計劃執行」→ 立即開始
2. 「大體同意，但我想修改[具體項]」→ 生成新計劃，再次確認
3. 「需要更詳細的解釋」→ 深度解釋，確保理解
4. 「暫停，我要重新檢查」→ 保存計劃，等待重新提交

**本步驟耗時**：3-5分鐘

**設計目的**：避免盲目執行，確保用戶完全理解即將發生什麼

#### 步驟5：等待執行（15-40分鐘）

Claude Code會：
1. 分析需求
2. 搜集必要數據
3. 進行多維度分析
4. 綜合評分
5. 生成報告
6. 提供建議

**實時監控**：
- 成本進度
- 質量檢查
- 風險監控

#### 步驟6：閱讀報告

報告包含：
- 各維度評分和判斷
- 綜合信號評級
- 風險評級
- 投資/決策建議
- 買入/實施區間
- 監控指標

**關鍵決策點**：
- 信號強度是什麼？
- 風險級別是什麼？
- 建議是什麼？

#### 步驟7：做決策

```
如果信號「強」+ 風險「低」：推薦執行
如果信號「強」+ 風險「中」：可以執行但控制規模
如果信號「強」+ 風險「高」：等風險降低後再執行
如果信號「中」：可以執行但非最佳時機
如果信號「弱」：不建議現在執行
```

## 第四章：進階使用（自定義定義書）

### 🎨 怎麼根據自己需求修改定義書

定義書的每一章都可修改，不同難度：

#### 🟢 容易修改（10分鐘）

**修改關心的指標**：
```
原: PE、ROE、負債率
新: 加入現金流、應收周期（特別關心現金流）
```

**修改評分權重**：
```
原: 維度A 33% + 維度B 33% + 維度C 34%
新: 維度A 50% + 維度B 25% + 維度C 25%（看重基本面）
```

**修改信號閾值**：
```
原: 指標 < 行業均值 → 給30分
新: 指標 < 行業均值×1.2 → 給30分（標準更寬鬆）
```

#### 🟡 中等修改（30分鐘）

**添加新決策規則**：
```
原: 規則1-5：基本評分
新: +規則6：如果是行業龍頭，升級一檔
    +規則7：如果有重大風險，降級一檔
```

**修改成功標準**：
```
原: 準確率>95%、誤報率<5%
新: 準確率>90%、誤報率<10%（容忍更多誤報）
```

#### 🔴 複雜修改（1-2小時）

**完全改寫問題定義**：
```
原: 驗證單個對象的質量
新: 驗證整個行業/領域的吸引力
```

**改變執行策略**：
```
原: Claude搜集數據和計算
新: 用戶提供數據，Claude只評分分析（節省成本）
```

## 第五章：進階設計（自己設計新Workflow）

### 🚀 怎麼設計自己的DynamicWorkflow

這是第三境界：從「用」升華到「設計」

#### 前置條件
1. 理解DW的核心概念
2. 用過至少一個現成Workflow
3. 理解定義書的基本結構

#### 設計步驟

##### 第一步：確定你的新問題

例子1：人才評估Workflow
```
問題：怎麼評估候選人的能力？
解決：用三維獵殺的邏輯，多維度評估候選人
```

例子2：供應商風險Workflow
```
問題：供應商風險大不大？
解決：用新聞獵手的邏輯，監控供應商動態
```

##### 第二步：設計你的定義書

使用8章結構：
1. 問題定義
2. 驗證標準
3. 執行策略
4. 決策規則
5. 預算分配
6. 預期產出
7. 自定義應用
8. 相關資源

##### 第三步：完整設計（人才評估為例）

**第一章：問題定義**
```
評估投資經理的三維能力：
1. 專業能力（投資知識、決策邏輯）
2. 執行能力（報告、溝通、協作）
3. 心理素質（抗壓、學習、誠信）
```

**第四章：決策規則**
```
規則1：如果(知名公司背景) AND (成功率>60%)
  → 專業評分>70

規則2：如果(高質量報告) AND (好評)
  → 執行評分>70

規則3：綜合評分 = (專業+執行+心理)/3

規則4：
- 評分>75 → 強烈推薦
- 評分50-75 → 可以錄用
- 評分<50 → 不推薦
```

##### 第四步：預算估算

```
成本項目：
- 背景信息蒐集：0.02
- 專業能力分析：0.05
- 執行能力分析：0.03
- 心理素質分析：0.04
- 綜合評分：0.01

總預期成本：0.15單位
應急預留：0.10單位
總預算：0.25單位
```

##### 第五步：交給Claude Code執行

```
「我設計了一個『人才評估Workflow』...
請根據定義書，評估這5個候選人：
[候選人名單]」

Claude Code會：
1. 理解定義書邏輯
2. 搜集候選人背景
3. 按規則評估
4. 生成評估報告
5. 給出排序建議
```

## 第六章：常見問題

### Q1：我是非[專業領域]的人，能用嗎？

**A**：完全可以。DW的方法論可遷移到任何領域。

```
投資領域的「蜂群覺醒」（監控買入信號）
  ↓ 邏輯完全相同 ↓
HR領域的「員工風險監控」（監控離職信號）

投資領域的「三維獵殺」（三維驗證）
  ↓ 邏輯完全相同 ↓
採購領域的「供應商評估」（三維評估）
```

**方法**：
1. 選擇最相似的現成Workflow作為範本
2. 按「進階設計」章節改寫定義書
3. 交給Claude Code執行

### Q2：我修改了定義書，不確定合理性？

**A**：先用小規模測試驗證。

```
步驟1：選1-2個小樣本測試
步驟2：執行，看結果合不合理
步驟3：根據結果調整定義書
步驟4：再跑一次確認
步驟5：擴大規模使用
```

### Q3：預算估算怎麼會準確？

**A**：通過反覆執行不斷優化。

```
第1次：預算0.25，實際用0.22 → 下次改0.23
第2次：預算0.23，實際用0.20 → 下次改0.22
第3-5次：不斷精煉，最終會很準確
```

### Q4：可以組合多個Workflow嗎？

**A**：完全可以，這是進階用法。

```
例1：蜂群覺醒 → 三維獵殺 → 決策

例2：三維獵殺 → 執行 → 新聞獵手+末日推演 → 風險管理

組合優勢：比單獨執行便宜（有重複的數據搜集）
```

## 第七章：最佳實踐

### ✅ 怎麼更有效地使用DW

#### 1️⃣ 定義清晰的問題

❌ 「幫我分析一個對象」
✅ 「監控這20個對象，當出現買入信號且風險<中等時提醒」

清晰 = 更少Token浪費 = 更低成本

#### 2️⃣ 先用小樣本測試

❌ 「評估我500個候選人」
✅ 「先評估5個，驗證可行，再擴展」

小樣本 = 發現問題 = 優化 = 更好結果

#### 3️⃣ 保存定制版本

❌ 「每次用時都從頭修改」
✅ 「保存『定義書_我的版本.md』，下次直接用」

版本管理 = 快速複用 = 效率提升

#### 4️⃣ 定期回顧和優化

❌ 「設計好就永遠不改」
✅ 「每月回顧一次，看是否需要調整」

持續優化 = 符合實際 = 更高決策質量

#### 5️⃣ 記錄修改清單

❌ 「改完就忘了改了什麼」
✅ 「在定義書開頭記錄所有修改」

```
修改1：加入現金流分析
  原因：更好識別盈利質量
  影響：成本+0.01

修改2：權重改為50-25-25
  原因：看重基本面
  影響：評估周期+3分鐘
```

## 第八章：保存、精進、分享

### 🌟 核心理念

```
生成 → 保存 → 精進 → 分享 → 社群共進化

一個人的力量有限，
一群人的力量無限。
```

### 💾 第1步：保存你的定義書

**為什麼保存**：
1. 版本管理：追蹤演進歷史
2. 快速複用：下次直接用
3. 知識傳承：分享給團隊

**怎麼保存**：
```
我的Workflows/
├─ 01-人才評估/
│  ├─ 定義書.md
│  ├─ 預算控制.md
│  └─ 執行記錄.md
├─ 02-供應商評估/
└─ README.md
```

**命名規則**：
```
定義書_[名稱]_v[版本].md
例如：定義書_人才評估_v1.0.md
     定義書_人才評估_v1.1.md（加入心理測試）
     定義書_人才評估_v2.0.md（重構邏輯）
```

### 📈 第2步：精進你的定義書

**迴圈1：執行→檢驗**
```
執行 → 檢驗結果 → 發現問題 → 改進 → 再執行
```

**迴圈2：成本→優化**
```
預算 vs 實際 → 分析超支 → 優化流程 → 控制成本
```

**迴圈3：結果→規則改進**
```
執行多次 → 發現模式 → 加入新規則 → 驗證準確度
```

**記錄改進日誌**：
```
## 2026-06-04 v2.0 → v2.1
問題：預算超支20%
原因：市場研究環節成本高
改進：簡化為「行業排名查詢」
效果：預算正常，準確度無影響

## 2026-07-04 v2.1 → v2.2
問題：評分50-75區分度不夠
原因：沒有充分區分
改進：加入「過往年化回報」判斷
效果：區分度提升30%
```

### 🤝 第3步：分享你的定義書

**分享給團隊**：
1. 準備定義書
2. 準備使用指南
