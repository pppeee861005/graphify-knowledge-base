## 💫 核心金句

### 🎯 人生很多答案，不是在計劃中出現，而是在 Workflow 中浮現

```
計劃（Plan）是靜止的：
  • 定義書 → 你對問題的靜態理解
  • 預算書 → 成本的靜態估算
  • 計劃 → 執行路徑的靜態設計

Workflow（執行）是流動的：
  • 執行時，問題會重新定義
  • 投入時，資源使用會改變
  • 面對現實時，計劃需要調整
  ✨ 真實的洞察在這裡浮現

例子：
✓ 計劃說「PE < 10x 就是買點」
✓ Workflow 中發現「現金流 > 淨利潤」才是真信號
✓ 結果：定義書升級，準確度提升
```

**這就是為什麼 DW 不是「完美計劃」，而是「有意識的 Workflow」**

## ⚡ Claude Code 最新一鍵激活：Ultracode

### 🎯 一句話理解

在 Claude Code 對話框輸入 **Ultracode** 指令，系統自動進入 **Dynamic Workflow 模式**（先展示計畫，不執行）。

```
Ultracode 我的定義書+預算書

↓ 自動進入 Dynamic Workflow 模式
↓ 展示完整計畫（免費）
↓ 等你確認後才執行（計費）
```

### 🚀 三步完成

**步驟 1**：打開 Ultracode
```
🔗 https://ultracode.io （推薦）
或
🔗 https://claude.new （備用）
```

**步驟 2**：準備你的定義書和預算書
```
複製你修改後的：
• 定義書.md（問題、驗收標準、決策規則）
• 預算書.md（成本估算、降級/升級規則）
```

**步驟 3**：輸入 Ultracode 指令
```markdown
Ultracode 我的定義書+預算書

[貼上定義書]

[貼上預算書]
```

✅ **完成！** 系統自動進入 Dynamic Workflow 模式，先展示計畫，等你確認無誤後再執行。

### 💡 為什麼用 Ultracode？

| 優勢 | 說明 |
|------|------|
| **規劃優先** | 先看完整計畫，確認無誤再執行（避免浪費 Token） |
| **完全免費** | 規劃階段零成本，只有執行時才計費 |
| **決策掌控** | 你有完全的決策權：執行、修改或取消 |
| **一句話激活** | 不需要複雜提示詞，系統自動進入正確模式 |

### 📊 四階段工作流

```
階段 A：上傳定義書 + 預算書
  ↓ 🟢 免費分析

階段 B：Claude Code 展示計畫
  ↓ 🟢 免費設計（規劃階段不消耗 Token）

階段 C：你確認或修改
  ↓ 三種選擇：
    ✅ 「確認無誤，執行」→ 進入階段 D（開始計費）
    🔄 「需要修改」→ 回到階段 B（再次免費）
    ❌ 「取消」→ 零成本退出

階段 D：執行 Workflow 並生成報告
  ↓ 🔴 開始計費
```

### 🎯 核心規則：「計畫優先於執行」

**最關鍵的點**：
- 📋 **規劃時間** = 零成本（充分利用）
- ⚡️ **執行時間** = 開始計費（確保無誤再執行）
- 🔄 **修改時間** = 零成本（計畫階段可無限修改）

**實戰好處**：
```
❌ 舊方式（無計畫）：
   上傳 → 執行 → 發現問題 → 修改 → 重新執行
   成本：2 倍 Token 消耗

✅ 新方式（Ultracode）：
   上傳 → 展示計畫 → 確認 → 執行
   成本：1 倍 Token 消耗（省 50%）
```
