## 💫 核心金句

### 🎯 人生很多答案，不是在計劃中出現，而是在 Workflow 中浮現

```
計劃（Plan）是靜止的：
  • 定義書 → 你對問題的靜態理解
  • 預算書 → 成本的靜態估算
  • 計劃 → 執行路徑的靜態設計

Workflow（執行）是流動的：
  • 執行時，問題會重新定義
  • 投入時，資源使用會改變
  • 面對現實時，計劃需要調整
  ✨ 真實的洞察在這裡浮現

例子：
✓ 計劃說「PE < 10x 就是買點」
✓ Workflow 中發現「現金流 > 淨利潤」才是真信號
✓ 結果：定義書升級，準確度提升
```

**這就是為什麼 DW 不是「完美計劃」，而是「有意識的 Workflow」**

## ⚡ DW 與 Claude Code Ultracode

### 核心區別

**DW（Decision Workflow）** 是決策框架理念，強調「定義書 + 預算書 + 計畫確認」。

**Ultracode** 是 Claude Code 的技術功能，用多個 Agent 並行執行複雜任務。

兩者可以結合，但不完全相同。

---

## 📋 DW 的標準工作流（推薦所有用戶）

這是 DW 系統本身推薦的四階段工作流，**不依賴 Ultracode**：

### 階段 A：準備定義書 + 預算書

```
你的操作：
• 寫清楚「問題定義」（what）
• 制定「預算控制」（cost）
• 列出「決策規則」（how）
```

### 階段 B：展示計畫

```
你的操作：
上傳定義書和預算書到 Claude Code

Claude 的操作：
✅ 分析你的需求
✅ 設計最優方案
✅ 展示完整計畫（架構圖、流程圖、成本、風險）
✅ 提供確認清單

費用：0 Token（僅分析和規劃）
```

### 階段 C：確認或修改

```
你的選擇：
✅ 「計畫無誤，執行」
   → 進入階段 D

🔄 「需要修改 X 部分」
   → 回到階段 B（重新規劃，仍然零成本）

❌ 「取消執行」
   → 安全退出，計畫保留供未來參考
```

### 階段 D：執行並生成報告

```
Claude 執行完整計畫：
• 生成代碼
• 執行 Workflow
• 監控成本和進度
• 生成最終報告

費用：開始計費（根據實際執行量）
```

### 🎯 DW 的核心原則

**「計畫優先於執行」**：
- 📋 計畫階段 = 零成本（充分利用，無限修改）
- ⚡️ 執行階段 = 開始計費（一次到位）
- ✅ 決策權 = 完全掌握（你決定執行、修改或取消）

## 🚀 進階：用 Ultracode 加速大規模任務

如果你的任務需要「真正的並行代理」，可以配合 Ultracode：

### 什麼時候用 Ultracode？

| 場景 | 用 DW（逐輪） | 用 Ultracode（並行） |
|------|----------|------------|
| 監控 5-20 檔股票 | ✅ 推薦 | ❌ 過度工程 |
| 監控 100+ 檔股票 | ⚠️ 可行 | ✅ 推薦 |
| 三維交叉驗證 | ✅ 推薦 | ✅ 也很好 |
| 複雜風險模擬 | ⚠️ 較慢 | ✅ 更快 |

### 使用 Ultracode 的方式

```markdown
ultracode: 根據我的定義書+預算書，並行監控 100 檔股票

定義書：[...]
預算書：[...]
```

**Ultracode 執行流程**：
```
1. Claude 規劃多代理工作流
2. 系統展示計畫 → 需要你批准
3. 你批准後
4. 16+ 個 Agent 並行執行
5. 實時監控進度（/workflows）
6. 完成後返回結果
```

### ⚠️ Ultracode 的成本警告

> **「一個 Ultracode 工作流會消耗遠多於逐輪對話的 tokens。」**

- 多代理並行 = 成本指數增長
- 適合大規模、時間敏感的任務
- 不適合簡單或成本敏感的任務

### 📖 Ultracode 完整文檔

官方文檔：https://code.claude.com/docs/en/workflows

**核心要點**：
- 需要 Claude Code v2.1.154+
- 支持最多 1,000 Agent / 16 並發
- 工作流在後台執行，會話保持響應
