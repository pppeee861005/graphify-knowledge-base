## 🎯 計劃願景

### 核心目標
建立一個**企業內部 AI HR Agent 系統**，透過 RAG（檢索增強生成）技術，讓員工可以：
- ✅ 直接向 AI 請假（系統自動理解公司政策、計算假期天數、提交審批）
- ✅ 詢問薪資、福利、晉升政策（系統即時檢索公司手冊）
- ✅ 自助報銷、申請培訓（系統自動驗證流程、生成表單）
- ✅ 查詢公司政策（系統自動理解並解釋）

### 系統架構
```
員工 → 自然語言查詢（語音/文字）
  ↓
AI HR Agent
  ├─ 理解意圖模塊（這是請假、報銷還是查詢政策？）
  ├─ RAG 檢索模塊（從企業職訓手冊檢索相關政策）
  ├─ 工作流執行模塊（自動生成表單、提交流程）
  └─ 決策模塊（何時需要人工審批）
  ↓
完整的行政處理（自動化 80%，人工審批 20%）
```

## 📚 職訓手冊的新定位

### 🔄 從「靜態文檔」→「動態知識庫」

**傳統職訓手冊**：
- 📄 靜態 PDF/Word
- 🔴 員工必須手動查閱
- 🟡 容易過期、信息不一致
- ❌ 無法被 AI 系統自動理解

**新式 RAG 職訓手冊**：
- 🗂️ 結構化知識庫（Markdown + 元數據）
- 🟢 AI 自動檢索與理解
- ✅ 實時更新、版本控制
- 🤖 驅動 AI HR Agent 決策

## 🎯 我們最務實的選擇

### 核心原則：不重複造輪子，專注落地

在開始構建 HR Agent 系統之前，我們的首選策略是：

**先評估：最前沿的 LLM 是否已經有原生能力支持我們的計劃？**

例如：
- ✅ **Claude 3.5** 能直接理解自然語言意圖 → 不需要自建 NLP 引擎
- ✅ **Claude 的 RAG 能力** 能直接嵌入知識庫進行檢索 → 不需要自建向量搜索
- ✅ **Claude 的推理能力** 能直接執行業務邏輯計算 → 不需要自建規則引擎
- ✅ **Claude 的工作流能力** 能直接驅動多步驟流程自動化 → 不需要自建工作流引擎

**我們的落地策略**：
1. 🔍 **充分調查**：查詢最新 LLM 文檔，看是否有直接支持的原生能力
2. 🛠️ **優先使用**：優先用前沿 LLM 的官方能力，而非自建輪子
3. ⚡ **快速驗證**：快速原型與驗證，質量有保障（社區驗證）
4. 🌉 **站在巨人肩膀**：真正的「站在巨人肩膀上」而不是重新發明輪子

**具體執行**：
- HR 系統的意圖識別、RAG 檢索、業務邏輯執行 → **直接用 Claude API + RAG**
- 不需要自建 LLM、不需要自建向量數據庫、不需要自建複雜規則引擎
- 節省 80% 開發時間，專注於「業務邏輯」而非「基礎設施」

### 層級 2：具體政策（RAG 檢索對象）

**例子：假期政策**

```markdown
# 假期與休息 > 年假

## 基本信息
- **政策代碼**：HR-LEAVE-001
- **最後更新**：2026-05-24
- **適用範圍**：全體正式員工

## 政策詳情

### 年假天數
- 服務年限 0-2 年：12 天
- 服務年限 2-5 年：15 天
- 服務年限 5+ 年：20 天

### 計算規則
- 年假在每年 1 月 1 日重置
- 未使用年假**不可**轉結至次年
- 若員工在年底未休完，企業補償 = 日薪 × 剩餘天數

### 申請流程
1. 員工提交申請（至少提前 5 個工作日）
2. 直屬主管審批
3. HR 確認並更新假期系統
4. 不需額外附件或理由

### AI 系統需要的元數據
```yaml
policy_id: HR-LEAVE-001
type: leave_policy
category: annual_leave
approval_required: true
approver_role: direct_manager
days_limit:
  - condition: "0-2年服務"
    days: 12
  - condition: "2-5年服務"
    days: 15
  - condition: "5+年服務"
    days: 20
advance_notice_days: 5
carryover: false
compensation_method: "daily_wage_x_remaining_days"
```
```

### 層級 3：AI 可執行的操作

**當員工說「我想請假」時，AI 需要執行**：

```
1️⃣ 意圖理解
  ├─ 假期類型判定（年假/病假/事假？）
  ├─ 假期天數推論（從「下周一到周三」推出 3 天）
  └─ 緊急度判定（提前多久提出的？）

2️⃣ RAG 檢索
  ├─ 檢索 HR-LEAVE-001（年假政策）
  ├─ 檢索員工檔案（服務年限、已用假期）
  └─ 檢索審批規則（誰是直屬主管？）

3️⃣ 業務邏輯計算
  ├─ 計算剩餘假期天數
  ├─ 驗證是否超過限額
  ├─ 驗證是否符合提前通知要求
  └─ 檢查是否需要人工審批

4️⃣ 工作流執行
  ├─ 生成假期申請表單
  ├─ 自動提交給直屬主管
  ├─ 記錄在假期系統中
  └─ 發送確認郵件給員工

5️⃣ 反饋
  ├─ 「您的年假申請已提交給 [主管名]，預計 1 個工作日內得到審批」
  └─ 提供查詢連結
```

## 🤖 AI HR Agent 的具體應用場景

### 場景 1：員工請假

**員工**：「我想從下周一到周三請年假，可以嗎？」

**AI HR Agent**：
```
✅ 意圖識別：年假申請（3天）
✅ 檢索政策：HR-LEAVE-001（年假政策）
✅ 檢索檔案：李明，服務 3 年，今年已用 5 天年假
✅ 計算結果：
   - 李明可用年假：15 天（2-5年標準）
   - 已用：5 天
   - 剩餘：10 天
   - 申請：3 天 ✅ 符合資格
✅ 流程檢查：提前 7 天提出 ✅ 符合「提前 5 天」要求
✅ 生成申請表
✅ 提交給直屬主管「王芳」
✅ 回覆員工：「您的年假申請已提交給王芳，預計明天得到審批。您還有 7 天年假剩餘。」
```

### 場景 2：員工報銷

**員工**：「我上次出差的酒店費用是 800 元，怎麼報銷？」

**AI HR Agent**：
```
✅ 意圖識別：差旅費報銷
✅ 檢索政策：HR-EXPENSE-001（差旅費政策）
✅ 檢索規則：
   - 酒店費用額度：800元/夜 ✅ 符合
   - 所需文件：發票、出差證明
   - 審批人：財務部
✅ 生成報銷單據
✅ 引導員工上傳發票
✅ 自動驗證：「發票日期、金額都符合政策」
✅ 提交給財務部
✅ 回覆員工：「您的報銷申請已提交，預計 3-5 個工作日處理」
```

### 場景 3：員工查詢政策

**員工**：「公司的培訓預算是多少？我想學 AI 課程。」

**AI HR Agent**：
```
✅ 意圖識別：培訓政策查詢
✅ 檢索政策：HR-TRAINING-001（培訓與發展）
✅ 回覆員工：
   「根據公司政策，每位員工年度培訓預算是 5,000 元。
    您今年已使用 2,000 元，還有 3,000 元可用。
    AI 課程如果是公司認可的（需在認可清單中），
    可以全額報銷。需要我幫您查一下您想學的課程嗎？」
```

### 場景 4：員工詢問晉升標準

**員工**：「我今年能晉升嗎？有什麼標準？」

**AI HR Agent**：
```
✅ 意圖識別：晉升資格查詢
✅ 檢索政策：HR-PROMOTION-001（晉升標準）
✅ 檢索員工檔案：
   - 當前職級：P4
   - 晉升要求：P5 需滿足「2年服務 + 績效評分 ≥ B」
   - 您的服務年限：1.8 年（不足 2 年）
   - 去年績效：A 級（✅ 符合）
✅ 回覆員工：
   「根據政策，您要晉升到 P5 需要滿足：
   1. 服務年限 2 年（您目前 1.8 年，還需 2.4 個月）
   2. 績效評分 ≥ B（您是 A 級，✅ 符合）

   預計今年 7 月末可以申請晉升。要我設置提醒嗎？」
```

## 📊 RAG 知識庫的技術規範

### 知識庫檔案格式

**標準化 Markdown + YAML 元數據**

```markdown
---
policy_id: HR-LEAVE-001
policy_name: 年假政策
category: leave
subcategory: annual_leave
last_updated: 2026-05-24
version: 2.3
applicable_to: [正式員工, 合約員工]
deprecated: false
related_policies: [HR-LEAVE-002, HR-LEAVE-003]
---

# 年假政策

## 概述
本政策規範公司所有員工的年假制度...

## 政策詳情
[詳細內容]

## 特殊情況處理
[邊界情況與例外]

## 常見問題
Q: 年假可以轉結嗎？
A: 不可。[詳細解釋]

## 更新日誌
- 2026-05-24：更新假期計算規則
- 2026-01-15：初次發佈
```

### RAG 系統如何使用知識庫

```
員工查詢：「我的年假還有多少？」
  ↓
向量化 → 在知識庫中搜索「年假 + 計算」
  ↓
檢索 HR-LEAVE-001（相關度 0.95）+ 員工檔案
  ↓
提取關鍵信息：
  - 政策：15天/年（2-5年服務）
  - 員工信息：服務3年，已用5天
  - 計算結果：15 - 5 = 10天
  ↓
生成回覆：「您還有 10 天年假可用」
```
