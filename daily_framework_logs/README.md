# 📋 Daily Framework Logs - 日誌標準說明

**用途**：追蹤每日使用的框架、模型、工具及其產出成果。

**目錄位置**：`daily_framework_logs/`

---

## 📌 日誌命名規則

**格式**：`YYYYMMDD_[框架/模型名稱]_[主要模型].md`

**範例**：
- `20260522_Antigravity2.0_Gemini3.5FlashHigh.md`
- `20260521_Software3.0_Claude3Sonnet.md`
- `20260520_AgentFramework_GPT4Turbo.md`

**說明**：
- `YYYYMMDD` = 日期（2026-05-22 → 20260522）
- `[框架/模型名稱]` = 主要使用的框架或系統名稱
- `[主要模型]` = 核心生成模型（去空格、簡化版本號）

---

## 📝 標準日誌結構

每份日誌應包含以下五大板塊：

### 1️⃣ **標題與基本信息**
```markdown
# YYYY-MM-DD 框架與模型日誌

## 今日使用情境
- **框架/工具**：[使用的框架名稱]
- **生成模型**：[模型名稱]
  - 用途：[這個模型用於什麼任務]
- **輔助模型**：[可選的第二、第三模型]
  - 用途：[它們的職責]
```

**範例**：
```markdown
# 2026-05-22 框架與模型日誌

## 今日使用情境
- **工具/框架**：Antigravity 2.0
- **生成模型**：Gemini 3.5 Flash (High)
  - 用途：撰寫《Agent-First 基礎》文章草稿
- **日誌管理模型**：GPT‑OSS 120B (Free)
  - 用途：記錄與管理本日誌
```

### 2️⃣ **內容摘要**（Content Summary）
```markdown
## 內容摘要
> [簡述今日工作成果，用一段話概括核心產出]

**關鍵產出**：
- 產出 1（檔名或簡述）
- 產出 2（檔名或簡述）
- 產出 3（檔名或簡述）
```

**範例**：
```markdown
## 內容摘要
> 寫作任務已完成，生成的文章位於
> `ANTIGRAVITY_第一篇_Agent-First基礎_draft.md`，
> 內容涵蓋四大核心架構、雙階段計畫範式、
> 多智能體協同調度等。

**關鍵產出**：
- `ANTIGRAVITY_第一篇_Agent-First基礎_draft.md`（2,500字初稿）
- 框架架構圖（4大層級 + 12個模塊）
- 實踐案例檔案（3個）
```

### 3️⃣ **模型表現評價**（Model Performance）
```markdown
## 模型表現評價

| 模型 | 任務類型 | 績效評級 | 備註 |
|------|--------|--------|------|
| Gemini 3.5 Flash | 文章初稿生成 | ⭐⭐⭐⭐ | 速度快、品質穩定 |
| GPT‑OSS 120B | 日誌記錄 | ⭐⭐⭐ | 準確但偶有冗長 |
```

### 4️⃣ **待辦事項與下一步**（Next Steps）
```markdown
## 待辦事項

- [ ] 待審核 `[檔名]` 內容
- [ ] 若通過，執行 [下一步流程]
- [ ] 若需調整，進行 [修改方向]

## 下一步計劃
- **明天**：[下一階段工作]
- **本週**：[本週目標]
```

**範例**：
```markdown
## 待辦事項

- [ ] 待審核 `ANTIGRAVITY_第一篇_Agent-First基礎_draft.md` 內容
- [ ] 若通過，使用 Antigravity 2.0 進行發布流程準備
- [ ] 補充第 2、3 篇的框架規劃

## 下一步計劃
- **明天**：優化第一篇內容，加入實踐案例驗證
- **本週**：完成三篇連載的初稿
```

### 5️⃣ **簽名與元數據**（Footer）
```markdown
---

**日期**：YYYY-MM-DD HH:MM
**時長**：[工作耗時]
**模型成本**：[可選，記錄 API 成本或資源消耗]
**品質評分**：⭐⭐⭐⭐✨ [1-5星]

*此日誌由 [模型名稱] 自動生成，屬於 [付費/免費] 模型。*
```

---

## 🎯 何時記錄

✅ **應該記錄**：
- 使用特定框架完成重要創意任務
- 對比不同模型的表現
- 生成重要文章、代碼或規劃文檔
- 發現有效的工作流組合
- 模型表現異常（很好或很差）

❌ **不需要記錄**：
- 簡單的文件查閱或編輯
- 日常代碼調試（除非涉及新框架）
- 臨時的對話或測試

## 🔗 與其他檔案的關係

```
daily_framework_logs/
  ├─ 每日框架評估與模型選擇記錄
  │
  └─→ work_log_YYYYMMDD.md
      ├─ 更詳細的任務執行記錄
      ├─ 決策依據與反思
      └─ 與 MEMORY.md 索引連接

  └─→ agent.md
      ├─ 定義記錄本日誌的指導原則
      └─ 當寫 framework_logs 時，參考本 README
```

## 💡 最佳實踐

1. **及時記錄**：工作完成後立即記錄（熱感記憶更準確）
2. **具體化**：避免模糊描述，用檔名和數字說話
3. **對比視角**：如果使用多個模型，對比其表現
4. **連結追蹤**：記錄產出檔案的具體路徑
5. **後續計劃**：每份日誌都指向下一步行動
