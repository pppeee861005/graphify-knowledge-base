### 任務 1.3：掌握「三大範式轉變」
**時間**：1 小時
**資源**：0_核心速查.md 中的「三大範式轉變」 + 文章深度解析

#### 三大範式轉變詳解

**1️⃣ 指令式（Imperative）→ 聲明式（Declarative）**

| | 指令式（舊） | 聲明式（新） |
|---|---|---|
| **思維方式** | 告訴 AI「怎麼做」 | 定義「結果應該是什麼結構」 |
| **例子** | 「先檢查語法，再檢查安全，再生成報告」 | 「定義 Stage 1、Stage 2、Stage 3 的數據流」 |
| **控制力** | 細微控制，但易出錯 | 結構清晰，邏輯可驗證 |

**2️⃣ 黑箱（Black-box）→ 透明盒（Transparent Box）**

| | 黑箱（舊） | 透明盒（新） |
|---|---|---|
| **可觀測性** | 輸入 + 等待 + 輸出，無中間過程 | 每個 Stage 都有監控點 |
| **調試困難** | 出錯時難以定位 | 精確定位到哪個 Stage |
| **性能優化** | 無法優化 | 可針對性地優化某個 Stage |

**3️⃣ 一次性（Ad-hoc）→ 可複用資產（Reusable Asset）**

| | 一次性（舊） | 可複用資產（新） |
|---|---|---|
| **存儲格式** | 文本 Prompt，難以版本控制 | JavaScript 代碼，支援 Git |
| **複用方式** | 複製粘貼，易變質 | Import/Export，可測試 |
| **企業價值** | 臨時工具 | 企業資產庫 |

#### 學習練習
- [ ] 用生活類比解釋「指令式 vs 聲明式」（類似：食譜 vs 廚房系統）
- [ ] 說明為什麼「透明盒」對工業級應用至關重要
- [ ] 想象一個企業有 100 個 Workflow，為什麼「可複用資產」很重要？

#### 驗收標準
✅ 能用生活類比清楚地解釋三大範式
✅ 理解「聲明式不是不控制，而是控制結構而非細節」

### 任務 1.4：理解「Software 3.0」的信號
**時間**：0.5 小時
**資源**：0_核心速查.md 中的軟件演進圖 + Agent E04 Part 1 尾聲

#### 軟件演進的三個時代

```
【Software 1.0】手寫代碼時代
  編程對象：像素、變數、指針
  方式：開發者手工編寫每一行邏輯
  例子：C、Java、Python 代碼

【Software 2.0】機器學習時代
  編程對象：數據和神經網絡
  方式：通過數據訓練替代手寫算法
  例子：深度學習、GPT

【Software 3.0】AI 工作流編排時代
  編程對象：智慧本身的組織結構
  方式：用代碼編排多個 Agent 的協作
  例子：Workflow、蜂群系統
```

#### 為什麼 Workflow = Software 3.0 的信號？

**Software 1.0 遺留的問題**：
- 手寫代碼難以應對複雜邏輯
- 維護成本高，容易出 Bug

**Software 2.0 的進步**：
- AI 可以學習規律，不用手寫邏輯
- 但 AI 是一個「黑箱」，難以工業應用

**Software 3.0 的革命**：
- Workflow 讓 AI 從「隨性助手」變成「可控系統」
- 多個 Agent 可以像軟件模塊一樣被組織、測試、複用
- 這才是 AI 成為工業級生產力的關鍵

- [ ] 對標：Prompt 屬於哪個時代？為什麼？
- [ ] 說出「Workflow 是 Software 3.0 的開始」背後的邏輯
- [ ] 想象：10 年後，企業最值錢的資產是什麼？

#### 驗收標準
✅ 理解三個軟件時代的區別
✅ 能說清楚為什麼 Workflow 代表 Software 3.0

### 任務 1.5：學習「六種核心執行模式」
**時間**：1.5 小時
**資源**：Agent E04 Part 2 中的「六種核心模式」詳解 + 實踐案例

#### 六種模式速覽

| 模式 | 特點 | HR 應用場景 |
|-----|------|-----------|
| **1. Pipeline** | A→B→C 線性順序 | 新員工入職流程 |
| **2. Sync Aggregation** | 並行→聚合 | 年終績效評估 |
| **3. Adversarial Validation** | 對抗驗證 | 晉升合規檢查 |
| **4. Best-of Mode** | 多版本選優 | JD 撰寫風格選擇 |
| **5. Cumulative** | 逐步累積 | 離職交接追蹤 |
| **6. Nested** | 流程套流程 | 差旅審批+稅務 |

#### 深入理解每種模式

**1️⃣ Pipeline（流水線）**
- 核心：順序執行，前一步完成後才觸發後一步
- 適用：有明確依賴關係的流程
- 例子：新員工審查 → 帳號創建 → 設備發放（必須按順序）

**2️⃣ Synchronous Aggregation（同步聚合）**
- 核心：多個 Agent 並行工作，結果聚合
- 適用：需要多個獨立角度的評估
- 例子：員工自評 + 同事評價 + 主管評價（同時進行，最後融合）

**3️⃣ Adversarial Validation（對抗驗證）**
- 核心：兩個 Agent 互相審查，若衝突則升級
- 適用：需要平衡不同視角（如法律 vs 業務）
- 例子：公司政策 vs 法律合規（衝突時升級給 HRVP）

**4️⃣ Best-of Mode（末尾篩選）**
- 核心：多個版本，選最優
- 適用：創意類工作（文案、設計）
- 例子：3 個 JD 草稿（熱情吸睛型、專業嚴謹型、簡潔條理型），選最適合

**5️⃣ Cumulative Pattern（累積式）**
- 核心：信息逐步累積到事件日誌
- 適用：過程型工作（需要記錄每一步）
- 例子：離職面談（提交申請 → 面談記錄 → 交接清單 → 結案報告，每步都有痕跡）

**6️⃣ Nested Workflow（嵌套式）**
- 核心：Workflow 內部調用其他 Workflow
- 適用：複雜流程的模塊化
- 例子：差旅審批 Workflow 內，外幣匯率 + 稅務申報是子流程

#### 企業應用場景練習

為以下場景選擇合適的執行模式，並說明理由：

- [ ] 招聘流程（發佈 JD → 收簡歷 → 篩選 → 面試 → 錄取）

- [ ] 付費訂閱（用戶註冊 → 驗證 → 支付 → 激活）
