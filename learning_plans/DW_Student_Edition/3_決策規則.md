# 第 3 章：決策規則

**預期時間**：8-9 分鐘
**學完後你會**：知道什麼是決策規則，為什麼很重要

---

## ⚔️ 用漫畫故事開始

### 故事場景：咒術回戰的戰鬥

想象虎杖在戰鬥：

```
敵人突然發動攻擊！

虎杖的大腦立刻做決定：

「敵人快速移動」
  → 用直拳（快速反應）

「敵人防禦強」
  → 用特殊技能（破防）

「敵人逃跑」
  → 追上去（不能讓他逃）

「血量剩 30%」
  → 切換到最強模式（賭命）

「對手等級遠高於我」
  → 升級給五條老師幫忙（不能硬拼）
```

這些「若...則...」的邏輯 = **決策規則**

---

## 🎯 什麼是決策規則？

### 一句話定義

> **決策規則（Decision Rules）= 「在什麼情況下應該怎麼做」的規則**

### 用簡單的詞解釋

- **決策**= 做選擇、做決定
- **規則**= 標準、原則
- **合在一起**= 「什麼情況下選擇怎麼做」

### 基本格式

```
若 [條件] → [行動]

例子：
若 Bug 很嚴重 → 優先修複
若 客戶滿意度 < 70% → 升級處理
若 成本超過預算 → 停止
```

---

## 💡 4 種決策規則

### 1️⃣ **判斷規則**（怎麼判斷情況）

```
「這個情況是什麼？」

例子：
若 Bug 影響核心功能 → 嚴重
若 Bug 只影響外觀 → 輕微

若 申請符合所有條件 → 通過
若 申請缺少必要文件 → 拒絕
```

### 2️⃣ **優先級規則**（什麼優先做）

```
「應該先做什麼？」

例子：
若 有 Critical 級 Bug → 優先處理
若 有一般 Bug → 其次
若 只是優化 → 最後

若 VIP 客戶申請 → 最優先
若 普通客戶申請 → 正常處理
```

### 3️⃣ **升級規則**（什麼時候升級給人工）

```
「什麼時候需要人來決定？」

例子：
若 無法自動決策 → 升級給人工
若 有衝突意見 → 升級給管理層
若 成本超過上限 → 升級給財務
若 涉及法律問題 → 升級給律師

升級很重要！AI 知道自己的限制。
```

### 4️⃣ **降級規則**（什麼時候簡化）

```
「什麼時候可以簡化流程？」

例子：
若 已知答案正確 → 跳過驗證
若 時間緊張 → 只做最重要的檢查
若 資源不足 → 用備用方案
```

## 🎬 現實例子

### 例子 1️⃣：代碼審查的決策規則

```
規則 1：判斷 Bug 嚴重程度
  若 Bug 導致系統崩潰 → Critical
  若 Bug 導致功能不可用 → High
  若 Bug 影響體驗 → Medium
  若 Bug 只是不美觀 → Low

規則 2：優先級
  若 Critical → 立刻修複
  若 High → 24 小時內修複
  若 Medium → 一週內修複
  若 Low → 按時間允許修複

規則 3：升級
  若 無法自動修複 → 升級給開發者
  若 涉及架構改動 → 升級給架構師
  若 無法確定根本原因 → 升級給技術主管

規則 4：降級
  若 Similar Bug 之前修過 → 用舊方案
  若 時間緊張 → 只修 Critical
```

### 例子 2️⃣：員工請假審批

```
規則 1：判斷是否符合政策
  若 有效期內且天數符合 → 符合
  若 超出限額 → 不符合

規則 2：判斷是否合法
  若 符合勞動法 → 合法
  若 違反法律規定 → 不合法

規則 3：決定結果
  若 符合政策且合法 → APPROVED（通過）
  若 違反政策或法律 → REJECTED（拒絕）
  若 符合政策但法律衝突 → ESCALATED（升級給 VP）
  若 政策和法律衝突 → ESCALATED（升級給律師）

規則 4：通知
  若 APPROVED → 通知員工、更新系統
  若 REJECTED → 通知員工、說明原因
  若 ESCALATED → 通知管理層、提供詳細分析
```

### 例子 3️⃣：投資審核

```
規則 1：評估財務
  若 ROI > 30% → 高收益
  若 ROI 15-30% → 中等收益
  若 ROI < 15% → 低收益

規則 2：評估風險
  若 風險評分 < 3/10 → 低風險
  若 風險評分 3-7/10 → 中風險
  若 風險評分 > 7/10 → 高風險

規則 3：決定
  若 高收益 + 低風險 → 立刻投資
  若 中等收益 + 中風險 → 深入分析
  若 低收益或高風險 → 否決
  若 無法評估 → 升級給投資委員會

規則 4：金額限制
  若 < 100 萬 → AI 決定
  若 > 1000 萬 → 升級給 CEO
```

## 🧠 為什麼決策規則很重要？

### 原因 1️⃣：讓 AI 知道怎麼做

```
❌ 沒有規則：
AI 不知道該怎麼決定
結果：經常出錯、需要人工修正

✅ 有規則：
AI 清楚知道什麼情況怎麼做
結果：自動決定、很少出錯
```

### 原因 2️⃣：保護人工判斷的邊界

```
規則告訴 AI：
「這種情況你無法決定，升級給人工」

例子：
✓ AI 能決定：Bug 是什麼級別
✗ AI 不能決定：這個員工該不該升職（需要人判斷）

所以規則說：「升級給人力資源」
```

### 原因 3️⃣：確保一致性

```
沒有規則：
A 天批准了申請，B 天拒絕了類似申請
→ 不公平、容易被投訴

有規則：
每個類似的申請都用同樣的標準
→ 公平、可信任
```

### 原因 4️⃣：提前預防問題

```
規則可以說：「危險情況立刻停止」

例子：
若 成本達到預算 80% → 警告
若 成本達到預算 100% → 停止
→ 不會超支
```

## ✏️ 怎麼寫決策規則？

### Step 1️⃣：列出所有可能的情況

```
代碼檢查的情況：
- 有沒有語法錯誤？
- 邏輯有沒有問題？
- 有沒有安全漏洞？
```

### Step 2️⃣：對每種情況定義結果

```
語法錯誤 → 標記為「語法錯誤」
邏輯問題 → 標記為「邏輯問題」
安全漏洞 → 標記為「嚴重」（升級）
```

### Step 3️⃣：定義如何匯總

```
若 有「嚴重」問題 → 立刻報告
若 有 > 5 個問題 → 分優先級
若 所有檢查通過 → 完成
```

### Step 4️⃣：定義升級條件

```
若 無法自動修複 → 升級給開發者
若 涉及重大架構 → 升級給架構師
```

## 🎯 好的決策規則 vs 差的決策規則

### ❌ 差的規則

```
「若 Bug 很多就優先處理」
❌ 「很多」是多少？不清楚

「若 代碼質量不好就拒絕」
❌ 「不好」怎麼定義？太模糊

「若 客戶不滿意就解決」
❌ 「不滿意」程度多少？不明確
```

### ✅ 好的規則

```
「若 Bug 數量 > 10 個就優先處理」
✓ 明確的數字邊界

「若 代碼複雜度 > 15 就拒絕」
✓ 可測量的標準

「若 客戶滿意度 < 70% 就升級」
✓ 清晰的衡量方式
```

**記住：規則越清楚，AI 的決定越準確！**

## 🚀 決策規則的層次

### Level 1：簡單判斷
```
若 [條件] → [是/否]

例子：
若 符合政策 → 通過
若 超出期限 → 拒絕
```

### Level 2：優先級判斷
```
若 [條件 A] → [動作 A（優先）]
若 [條件 B] → [動作 B（次優先）]

例子：
若 Critical Bug → 優先處理
若 High Bug → 其次處理
```

### Level 3：複合判斷
```
若 [條件 A] AND [條件 B] → [動作]
若 [條件 A] BUT [條件 C] → [不同動作]

例子：
若 符合政策 AND 合法 → 通過
若 符合政策 BUT 法律不允許 → 升級給律師
```

### Level 4：動態調整
```
根據實時情況調整規則

例子：
若 系統負載 > 80% → 降級（簡化流程）
若 已完成 50% 目標 → 停止（預算控制）
```
