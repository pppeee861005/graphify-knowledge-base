## 💰 用漫畫故事開始

### 故事場景 1️⃣：極限返航（The Martian）

想象一個太空人被困火星：

```
太空人的狀況：
- 食物有限
- 水有限
- 燃料有限
- 電力有限

他的決策規則：
「每天只能吃固定的食物」
「不能浪費任何水」
「必須計算燃料能走多遠」

為什麼？
因為資源用完了就死定了！

所以他：
✓ 計算還有多少資源
✓ 計劃每天用多少
✓ 預留緊急用的
✓ 不能超支！
```

**預算 = 太空人的食物和燃料**

### 故事場景 2️⃣：THE MANDALORIAN

```
曼達洛人帶著小尤達出逃：

他的考慮：
- 燃料夠不夠？
- 補給夠不夠？
- 錢夠不夠？

他必須做決定：
「往哪裡逃？」
「要怎樣才能活下去？」

不能說：「我要無限制地逃」
必須說：「在這些資源內，我怎樣活下去」
```

**這就是預算的概念！**

## 🎯 什麼是預算？

### 一句話定義

> **預算（Budget）= 完成一個任務最多花多少成本，以及預留多少應急**

### 用簡單的詞解釋

- **預算**= 預先計劃的花費
- **成本**= 做任務需要花的資源
- **預留**= 留給意外的部分

### 預算的三部分

#### 1️⃣ **總預算**
```
「我最多能花多少？」

例子：
「總預算：1.0 單位」
「總預算：100 小時」
「總預算：1000 元」
```

#### 2️⃣ **預期成本**
```
「我預計要花多少？」

例子：
「預期成本：0.5 單位」
「預期成本：50 小時」
「預期成本：500 元」
```

#### 3️⃣ **預留**
```
「我留多少作為應急？」

預留 = 總預算 - 預期成本

例子：
總預算 1.0 - 預期 0.5 = 預留 0.5（50%）
總預算 100h - 預期 50h = 預留 50h（50%）
總預算 1000元 - 預期 500元 = 預留 500元（50%）
```

**重要：預留最好 ≥ 50%！**

---

## 💡 為什麼要預留預算？

### 原因 1️⃣：情況比預期複雜

```
預期：簡單的 Bug 修復
實際：Bug 比想象多，有些很複雜

預期成本：0.3
實際需要：0.45

如果預留足夠（預留 0.5）✓
  → 沒問題，能完成

如果預留不足（預留 0.1）✗
  → 超支了，無法完成
```

### 原因 2️⃣：出現意外情況

```
預期：按計劃進行
意外：發現安全漏洞，需要額外檢查

預留足夠 → 能應對
預留不足 → 無法應對
```

### 原因 3️⃣：質量要求更高

```
預期：基本質量檢查
現實：客戶要求更高質量

預留足夠 → 能升級質量
預留不足 → 無法完成高質量
```

### 原因 4️⃣：AI 不確定時需要試驗

```
有些問題 AI 不能 100% 確定
需要嘗試多種方案
預留足夠 → 能試驗
預留不足 → 不能試驗
```

---

## 📊 預留比例的建議

### 根據複雜度選擇預留比例

| 複雜度 | 預留率 | 例子 |
|--------|--------|------|
| 簡單 | ≥ 30% | 單純檢查任務 |
| 中等 | ≥ 50% | 多維度評估 |
| 複雜 | ≥ 70% | 多 Agent 對抗、升級 |

### 實際例子

#### ✅ 安全的預算

```
複雜：代碼檢查（多個 Agent，可能有衝突）
總預算：1.0 單位
預期成本：0.3 單位
預留：0.7 單位（70%）
→ 預留足夠，能應對任何情況
```

#### ⚠️ 危險的預算

```
複雜：代碼檢查（多個 Agent，可能有衝突）
總預算：1.0 單位
預期成本：0.9 單位
預留：0.1 單位（10%）
→ 預留不足，可能超支
```

## 🎬 預算在工作流中的作用

### 例子：代碼檢查

```
預算分配：
┌────────────────────────┐
│ 總預算：1.0 單位       │
├────────────────────────┤
│ 語法檢查：0.1 單位     │
│ 邏輯檢查：0.15 單位    │
│ 安全檢查：0.05 單位    │
│ 測試生成：0.2 單位     │
├────────────────────────┤
│ 預期成本：0.5 單位     │
│ 預留：0.5 單位（50%）  │
└────────────────────────┘

進行中的監控：
- 已用 0.2 → 20%（綠色 ✓）
- 已用 0.4 → 40%（綠色 ✓）
- 已用 0.7 → 70%（黃色 ⚠️ 開始節省）
- 已用 0.9 → 90%（紅色 ❌ 警告）
- 達到 1.0 → 100%（停止）
```

### 成本控制的決策規則

```
規則 1：監控
  每個 Agent 運行前，檢查預算是否充足

規則 2：預警
  若 成本達 80% → 警告，準備降級

規則 3：降級
  若 成本達 90% → 停止低優先級任務
  若 成本達 95% → 只完成最必要的部分

規則 4：停止
  若 成本達 100% → 停止所有新任務，返回已完成結果
```

## 🎯 預算的真實故事

### 故事 1️⃣：預留充足的成功案例

```
任務：檢查 2000 行代碼
預期：0.3 小時
總預算：1 小時
預留：70% (0.7 小時應急)

進行中：
- 發現的 Bug 比預期多 (0.4 小時)
- 安全檢查發現漏洞 (0.2 小時)
- 生成高質量測試 (0.3 小時)
- 實際成本：0.9 小時

結果：
預算 1 小時 > 實際成本 0.9 小時 ✓
成功完成，還有預留！
```

### 故事 2️⃣：預留不足的失敗案例

```
任務：檢查 2000 行代碼
預期：0.3 小時
總預算：0.5 小時
預留：40% (0.2 小時應急)

進行中：
- 發現的 Bug 比預期多 (0.4 小時)
- 需要升級給人工 (0.15 小時)
- 實際成本：0.55 小時

結果：
預算 0.5 小時 < 實際成本 0.55 小時 ✗
超支 10%，必須停止，交給人工，浪費了時間和成本！
```

**故事 2 的 AI 會說：「成本超支，無法完成，升級給人工」**

## 💻 預算在 Dynamic Workflows 中的實現

### AI 怎麼監控預算？

```
開始任務：
預算：1.0 單位
├─ Agent 1 執行 → 花費 0.1 → 剩餘 0.9
├─ Agent 2 執行 → 花費 0.2 → 剩餘 0.7
├─ Agent 3 執行 → 花費 0.15 → 剩餘 0.55 ⚠️ 進入警告
├─ 決策 Agent → 花費 0.05 → 剩餘 0.5
├─ 如果還要更多檢查？
│  檢查預算是否足夠
│  若足夠 → 繼續
│  若不足 → 停止或降級
└─ 任務完成，花費 0.5，還有預留 0.5
```

### AI 的三個預算決策

#### 決策 1️⃣：要不要開始新 Agent？
```
規則：若 預算足夠 → 開始
      若 預算不足 → 停止或跳過

效果：不會無限制地增加成本
```

#### 決策 2️⃣：低優先級任務要不要做？
```
規則：若 預算充足 → 做低優先級
      若 預算緊張 → 跳過低優先級

效果：優先完成重要的
```

#### 決策 3️⃣：什麼時候停止？
```
規則：若 預算用完 → 停止
      若 目標達成 → 停止

效果：不會超支
```
