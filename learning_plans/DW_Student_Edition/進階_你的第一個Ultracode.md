## 🎬 回顧：基礎版本 5 - 你的第一個 DW

在基礎章節中，你寫過一個「你的第一個 DW」

**例子**（假設你寫的是關於股票監控的）：

```markdown
# 我的第一個 DW：股票監控蜂群

## 目標
監控我關注的 5 檔股票，早點發現異動

## Agent 定義
- Agent 1：監控台積電
- Agent 2：監控輝達
- Agent 3：監控蘋果
- Agent 4：監控美超微
- Agent 5：監控昇達科技

## 決策規則
IF 股價變化超過 3%
THEN 發送警報 + 記錄時間、股價、漲幅

## 預算
每個 Agent 每小時最多 50 次 API 查詢
共 5 個 Agent，一天 24 小時

## 執行計劃
每 5 分鐘檢查一次股價
```

## 📚 常見問題（Q&A）

### Q：我不是學 DW 時寫的，現在能用不同的 DW 嗎？
**A**：當然可以！
- 你可以改變監控對象（5 檔股票 → 商品價格 → 天氣）
- 你可以改變規則（3% → 5%）
- 你可以改變檢查頻率（5 分鐘 → 10 分鐘）
- Claude Code 會自動調整

### Q：我的 DW 不完美怎麼辦？
**A**：完全沒關係！
- 實際執行時會暴露問題 ← 這很好
- 你看到結果，發現問題
- 你調整 DW，系統自動執行新版本
- 這叫「迭代改進」

### Q：執行過程我需要做什麼？
**A**：只需要三件事：
1. 看儀表板（了解發生了什麼）
2. 思考（「這個結果對嗎？」）
3. 調整（「我要改變規則」）

### Q：Ultracode 會不會出錯？
**A**：執行層面基本不會（系統很可靠）
但決策層面可能有：
- 你的規則定得不好 → 調整規則
- 你遺漏了什麼 → 加入新規則

### Q：我需要學代碼嗎？
**A**：不需要！
- 寫 DW：只需要「邏輯清楚」
- Claude Code 自動把 DW 變成代碼
- 你的工作是「設計」，代碼是「工具」

### Q：這和普通的「自動化」有什麼區別？
**A**：很大區別：
```
❌ 普通自動化：
   系統自動做 → 你看結果 → ？
   （你不知道為什麼，改不了）

✅ DW + Ultracode：
   你設計 → 系統執行 → 你看全過程 → 你調整
   （完全透明，你掌控）
```
