# 📋 DW計劃開發模版指南

**版本**：1.0
**核心原則**：🎯 **DW應用優先** — 定義書和教學優於代碼
**用途**：快速開發和發布新的DW應用場景計劃
**參考**：Plan 1（HR自動化）完整驗證

---

## 🎯 核心理念

### DW計劃的三層次結構

```
層1：定義書（核心）— 明確業務邏輯
  ↓
層2：預算書（決策依據）— 成本和ROI透明化
  ↓
層3：教學指南（能力轉移）— 教用戶如何自動生成Workflow

代碼僅作為「參考實現」，不是重點
```

### 轉向的本質

```
FROM：「我給你完整代碼」
      → 你複製代碼
      → 你運行代碼
      → 只有開發者受益

TO:   「我教你定義問題」
      → 你修改定義書
      → Claude Code自動生成
      → 所有人都能受益
```

### 1️⃣ README.md（DW應用優先導航）

**目標**：讓所有人（CEO到開發者）都能快速理解

**結構**：

```markdown

不是「怎麼寫代碼」
而是「怎麼用Claude Code自動生成Workflow」

## 📚 三層學習路徑

### Layer 1：理解問題（15分鐘）
讀 `計劃X_[應用]定義書.md`
→ 理解：核心問題、場景、成功指標

### Layer 2：學習生成方法（30分鐘）
1. 打開定義書
2. 修改成你的場景
3. 提交給Claude Code

   ```

### Layer 3：執行和迭代（1小時）
執行 → 驗證 → 改進 → 分享

## 📝 快速決策清單

**建立新DW計劃時，確認以下5點**：

### ✅ 第1點：戰略對齐
- [ ] 新計劃與DW生態（計劃7）的連接清晰？
- [ ] 能夠證明DW適用於此應用場景？

### ✅ 第2點：核心內容
- [ ] 定義書的場景選擇（2-3個）是否代表性？
- [ ] 決策規則是否清晰可實施？
- [ ] 成功指標是否量化？

### ✅ 第3點：執行計劃
- [ ] 5步教學流程是否可行？
- [ ] 案例是否足夠說明複用性？
- [ ] 文檔完整性是否符合要求？

### ✅ 第4點：時間和資源
- [ ] 5-7天完成所有文檔是否現實？
- [ ] 預期字數（15,000+）是否可達成？

### ✅ 第5點：最終決策
- [ ] GO：立即執行
- [ ] MODIFY：調整後執行
- [ ] HOLD：暫時保存
- [ ] CANCEL：取消

## 💡 常見誤區

### ❌ 誤區1：過度強調代碼
```
❌ 「我們有300行精心設計的代碼」
✅ 「任何企業都能用定義書自動生成此工作流」
```

### ❌ 誤區2：定義書預先設計Stage/Agent
```
❌ 「Stage 1用Haiku，Stage 2用Sonnet...」
✅ 「需要檢查XYZ，Claude Code決定怎麼檢查」
```

### ❌ 誤區3：成功指標太模糊
```
❌ 「質量要好，成本要低」
✅ 「Bug發現率≥80%，成本<100萬tokens」
```

### ❌ 誤區4：忽視社群貢獻目錄
```
❌ 「就這5份文件，沒有其他」
✅ 「預留other_creators_workflows/給社群改進」
```
