# Dynamic Workflows 自動生成 Agent Harness - 核心本質

**記錄日期**：2026-06-02
**發現者**：用戶 + Rocky (Claude Code)
**重要度**：🔴 核心認知，改變整個工作方式

---

## 🎯 一句話本質

> **Claude Code 自動生成整個 Dynamic Workflow，包括 Agent 數量、執行模式、Stage 編排。你只需要定義「問題、驗證標準、決策規則、預算」。**

---

## 📊 範式轉變

### 舊認知（2026-06-01 之前）

```
我的工作：
1. 設計 Workflow 架構（多少個 Stage？什麼順序？）
2. 定義 Agent 協作（需要幾個 Agent？用什麼模式？）
3. 編寫 Workflow 代碼（async/await 怎麼寫？）
4. 編寫測試和驗證邏輯
5. 執行並監控

Claude Code 的工作：
執行我設計的 Workflow
```

**問題**：我花費 80% 的時間在「設計」和「寫代碼」，而不是「思考問題」

### 新認知（2026-06-02 後）

```
我的工作：
1. 定義問題（要解決什麼？）
2. 定義驗證標準（什麼時候成功？）
3. 定義決策規則（在什麼情況下應該怎麼做？）
4. 定義預算限制（最多花多少成本？）

Claude Code 的工作：
1. 自動設計 Workflow 架構（需要多少 Stage？什麼執行模式？）
2. 自動決定 Agent 數量和協作方式
3. 自動編寫 Workflow 代碼（包括完整的 Agent Harness）
4. 自動執行並監控成本
5. 自動生成驗證報告
```

**優勢**：
- 我花費 80% 的時間在「思考問題和決策」，這才是最有價值的工作
- Claude Code 自動完成重複性工作（代碼編寫、Workflow 設計等）
- 快速迭代：改變需求只改「定義書」，不需要重新設計整個 Workflow

## 🔑 關鍵轉變點（三個「由 Claude Code 決定」）

### 轉變 1：Stage 數量不是預先設計，而是動態決定

**舊方式**：
```
"我要設計 5 個 Stage：
 Stage 1: 語法檢查
 Stage 2: 邏輯審查
 Stage 3: 並行政策和法律檢查
 Stage 4: 決策
 Stage 5: 通知"
```

**新方式**：
```
"我要評估申請是否符合政策和法律。
 需要檢查什麼維度、用多少個 Stage、什麼順序 → Claude Code 決定"
```

→ **Stage 數量由 Claude Code 根據問題複雜度自動決定**

### 轉變 2：Agent 數量和執行模式不是預先指定，而是動態選擇

**舊方式**：
```
"需要 3 個 Agent（PolicyAgent、LegalAgent、RiskAgent）
 並行執行 → Promise.all()
 然後聚合結果"
```

**新方式**：
```
"需要並行檢查多個維度。
 多少個維度、用什麼模型、什麼執行模式 → Claude Code 決定"
```

→ **Agent 協作方式由 Claude Code 根據成本和效率自動優化**

### 轉變 3：代碼不是手寫，而是自動生成

**舊方式**：
```
"我手寫 Workflow 代碼：
 const result1 = await agent.run(...)
 const [r2, r3] = await Promise.all([...])
 if (衝突) return escalate(...)"
```

**新方式**：
```
"我定義決策規則：
 若政策和法律衝突 → 升級給人工
 Claude Code 自動生成對應的代碼邏輯"
```

→ **完整的 Agent Harness 由 Claude Code 自動生成和執行**

## 💎 為什麼這很重要？

### 1️⃣ 專注力轉移

從「技術細節」（寫代碼、設計架構）轉移到「業務邏輯」（定義問題、決策規則）

→ 更高層次的思考，而不是低級別的實現細節

### 2️⃣ 時間效率

```
舊方式：定義 + 設計 + 編寫 + 調試 + 測試 = 8-10 小時
新方式：定義 = 0.5-1 小時 ✅

節省 87% 的時間！
```

### 3️⃣ 可複用性

```
舊方式：每個項目重新設計 Workflow，代碼難以複用
新方式：定義書可以複用，決策規則可以複用，代碼由 Claude Code 自動生成

新項目：只需修改定義書中的「問題陳述」和「決策規則」
```

### 4️⃣ 適應性

```
需求變化：
舊方式 → 重新設計 Workflow → 重新寫代碼 → 重新測試
新方式 → 更新定義書 → Claude Code 自動重新生成 → 完成

改一行定義書 < 改整個架構和代碼
```

### 5️⃣ 預測性

```
預算控制：
舊方式 → 我估算 Phase 1-4 的成本，經常不準，可能超支
新方式 → Claude Code 實時監控，根據決策規則自動調整，從不超支

成本 100% 可控
```

## 📝 關鍵定義

### 什麼是「定義書」？

定義書 = 「問題陳述」+ 「驗證標準」+ 「決策規則」+ 「預算」

不是：
- ❌ 架構設計文檔
- ❌ 代碼框架
- ❌ Stage 規劃

是：
- ✅ 業務需求說明
- ✅ 質量標準定義
- ✅ 決策邏輯
- ✅ 成本限制

### 什麼是「Agent Harness」？

Agent Harness = Claude Code 自動生成的完整 Workflow 執行環境

包含：
- ✅ Stage 編排邏輯
- ✅ Agent 調用和協作
- ✅ 決策和條件判斷
- ✅ 成本監控
- ✅ 升級/降級邏輯
- ✅ 日誌和驗證

不需要用戶手寫這些！

## 🎯 三個核心不做

### ❌ 不要設計 Stage

```
❌ 「需要 4 個 Stage」
❌ 「Stage 1 先做 X，Stage 2 再做 Y」
❌ 「並行執行 Stage 2 和 Stage 3」

✅ 「需要檢查多個維度」
✅ 「先快速初檢，再深度分析」
✅ 「某些檢查可以並行」

→ 具體怎麼分 Stage，由 Claude Code 決定
```

### ❌ 不要指定 Agent 數量

```
❌ 「需要 3 個 Agent」
❌ 「PolicyAgent、LegalAgent、RiskAgent」

✅ 「需要並行評估多個方面」
✅ 「需要政策和法律角度的驗證」

→ 具體用多少個 Agent，由 Claude Code 決定
```

### ❌ 不要預先規劃代碼實現

```
❌ 「用 Promise.all() 並行」
❌ 「若衝突用投票制」
❌ 「用 if-else 判斷」

✅ 「並行執行多個檢查」
✅ 「若衝突升級給人工」
✅ 「根據規則決策」

→ 具體怎麼實現，由 Claude Code 決定
```

## 💡 核心洞察

### 以前：AI 是執行者

```
我：「按這個流程執行」
AI：「執行你的流程」
```

### 現在：AI 是設計者 + 執行者

```
我：「我要達到什麼目標，有什麼約束」
AI：「我來設計最優的流程，然後執行它」
```

→ **AI 不僅執行，還負責設計和優化**

## 🚀 應用場景

這個原理適用於：

| 場景 | 用途 |
|------|------|
| 代碼檢查 | 語法 + 邏輯 + 安全檢查，自動生成測試 |
| 審批流程 | 政策 + 法律驗證，自動衝突檢測 |
| 內容審核 | 多維度檢查，自動評分和分類 |
| 數據驗證 | 格式 + 內容 + 業務規則檢查 |
| 決策支持 | 多個維度評估，自動聚合建議 |

**共同特點**：
- 需要多個維度的檢查或評估
- 檢查結果需要聚合或對比
- 存在可能的衝突或模糊區域
- 需要明確的決策規則
