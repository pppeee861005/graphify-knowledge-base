## 🔍 詳細轉向方案

### 第一部分：理論基礎

#### 1.1 為什麼要轉向？

**3 個戰略理由**：

**理由 1：符合「人類共好」理念**
```
現在：「我有 HR 代碼，你可以用」
  └─ 只有開發者能用
  └─ 知識停留在「代碼」層面

轉向：「我教你怎麼自己生成 HR Workflow」
  └─ 任何人都能用
  └─ 知識升級到「方法論」層面
  └─ 「人類共好」從言語變為行動
```

**理由 2：強化 DW 的戰略地位**
```
現在：
  計劃7（DW 應用示範）
    └─ ai-swarm-triangulate（投資場景）
    └─ （還缺企業應用場景）

轉向：
  計劃7（DW 應用示範）
    ├─ ai-swarm-triangulate（投資場景 ✅）
    ├─ 計劃1（企業HR場景 ✅）← 新增
    └─ 其他計劃（持續擴展）

效果：證明「DW 不只適用於投資，適用於所有企業場景」
```

**理由 3：激發社群無限創新**
```
現在：
  社群看到計劃1 的代碼
    └─ 「這個 HR 代碼不錯，但我的企業不同」
    └─ 「我需要修改代碼... 太複雜了」
    └─ 放棄參與

轉向：
  社群看到計劃1 的定義書
    └─ 「我可以修改定義書」
    └─ 「提交給 Claude Code，自動生成」
    └─ 「我的企業 Workflow 生成了！」
    └─ 「我分享給其他企業」
    └─ 社群創新指數級增長
```

#### 1.2 轉向的核心假設

```
假設 1：「定義書比代碼更有價值」
  驗證：ai-swarm-triangulate 的 README 強化已證明這一點 ✅

3. 外部系統（API）

   ├─ 發送給員工（結果通知）
   ├─ 發送給經理（如需人工審批）

4. 監控和審計日誌

### 1.6 約束條件和限制

```
1. 政策約束
   - 必須遵守國家勞動法（如年假上限）
   - 必須遵守公司內部政策
   - 必須審計追蹤（誰批准的，為什麼）

2. 系統約束
   - 只能修改 Google Workspace 中的數據
   - 不能修改薪資系統（只能發送修改申請）
   - 不能自動刪除數據（只能標記為"已處理"）

3. 人工介入約束
   - 超出政策的情況必須轉人工
   - 政策模糊的情況必須轉人工
   - 異常請求（如重複提交）必須轉人工

4. 性能約束
   - 單個請求的自動化不能超過 30 秒
   - 批量處理（100 個請求）不能超過 5 分鐘
   - API 調用不能超過 Google Workspace 配額
```

### 2.2 決策規則（場景 A：請假審批）

```
rule_1: "自動批准 - 標準請假"
條件：
  AND: [
    request.type == "leave",
    request.days <= 3,
    employee.leave_balance >= request.days,
    department.budget >= (request.days * daily_cost),
    today != 法定假期前一天,  // 不能在法定假期前夕請假
    !employee.黑名單
  ]
執行：批准請假，自動更新工資條

rule_2: "轉人工審批 - 長期請假"
條件：
  AND: [
    request.type == "leave",
    request.days > 3,
    request.days <= 30
  ]
執行：發送給經理審批

rule_3: "自動拒絕 - 超出額度"
條件：
  AND: [
    request.type == "leave",
    employee.leave_balance < request.days
  ]
執行：拒絕請假，通知員工

rule_4: "警報異常 - 重複提交"
條件：
  AND: [
    request.type == "leave",
    員工在 24 小時內提交超過 3 次請假
  ]
執行：發警報給 HR 主管

[類似規則用於場景 B、C]
```

### 2.3 人工介入流程

```
當觸發「轉人工審批」規則時：

1️⃣ 發送審批請求
   接收人：員工的經理（自動查詢）
   內容：請假申請摘要 + 建議（自動生成）
   方式：Google Chat 消息 + Email

2️⃣ 經理審批
   經理在 Google Chat 上點擊「批准」或「拒絕」
   系統等待 48 小時，如未回覆則自動升級

3️⃣ 自動升級
   若經理未在 48 小時內回覆
   → 發送給部門總監
   → 如還未回覆，自動批准（避免請假被卡住）

4️⃣ 更新系統
   無論經理批准或拒絕
   系統自動更新 Google Sheets 和薪資系統
```

### 2.4 異常處理

```
異常情況 1：員工信息不完整
  └─ 發送郵件給 HR，請求確認
  └─ 人工確認后重新執行

異常情況 2：政策有歧義
  └─ 發警報給 HR 主管
  └─ 轉人工審批
  └─ HR 更新政策后重新執行

異常情況 3：系統無法連接（Google Workspace API 超時）
  └─ 等待 30 秒后重試
  └─ 重試 3 次仍失敗
  └─ 發警報給系統管理員
  └─ 轉人工審批

異常情況 4：請求內容可疑（可能詐欺）
  └─ 例：員工 A 請假，但同時出現在 Calendar 上的會議
  └─ 系統發警報
  └─ 轉人工審批
```
