📋 什麼是 Schema 設計？

  简单说法

  Schema = 「規則的形狀」或「資料的模板」

  就像：
  - 📋 Excel 表格的「列標題」決定了你能記錄什麼信息
  - 🏠 房屋的「戶型圖」規定了每個房間的位置和大小
  - 📝 申請表單的「欄位」決定了要填什麼內容

  W1 計劃中的 Schema 是什麼？

  在租約哨兵 W1 中，Schema 設計 就是定義：

  「我用什麼樣的結構來記錄每一條法規條文？」

  ---
  🔍 具體例子

  舊方式（沒有 Schema）

  假設你要記錄第 6 點「電費」：

  混亂狀態：
  - 官方說：「每度電費不得超過當期平均電價」
  - 我的理解：「房東不能隨便漲電費」
  - 實例：「小王的房東每度收8元，但台電只要3.5元」
  - 嚴重程度：「很嚴重」
  - 從哪裡來的：「114年4月18日」

  → 每個人記錄的方式都不一樣，亂成一團

  新方式（有 Schema）

  用統一的模板記錄：

  {
    "id": "6",
    "type": "應記載",
    "original": "租賃期間相關費用之約定(三)電費：□由出租人負擔。□由承租人負擔。□以用電度數計費者，每度電費不得
  超過該租賃標的電費單『當期每度平均電價』...",
    "plain": "房東如果向承租人收電費，價格不能超過台灣電力公司當月的平均電價。不能按「最高級距」來超收。",
    "violations": [
      "房東按『最高級距』計費（109年舊版允許的做法，現在違法）",
      "房東不提供電費單據，承租人無法驗證",
      "房東將公共設施電費額外收費"
    ],
    "severity": "高",
    "source_ver": "114年4月18日"
  }

  看到差別了嗎？

  - ✅ 信息結構化了
  - ✅ 每個欄位的意思清楚
  - ✅ 便於對比、驗證、交給 AI 處理

  🎯 Schema 設計在 W1 中的 3 個重要作用

  1️⃣ 統一語言

  所有 23 條應記載 + 10 條不得記載，都用同一套格式記錄

  → 方便比對、發現遺漏

  2️⃣ 讓 AI 能工作

  告訴 Agent：「按照這個模板，把官方原文轉成我們的格式」

  Agent 會做的事：
  原文 → 按 Schema 格式整理 → 輸出 JSON

  比如：
  官方原文（亂七八糟的法律用語）
      ↓
  Agent 結構化為 Schema 格式
      ↓
  {id, type, original, plain, violations, severity, source_ver}

  3️⃣ 人類能驗收

  你逐條檢查時有統一的檢查清單：

  ☐ 官方原文逐字抄錄？（original 欄位）
  ☐ 白話解釋清楚嗎？（plain 欄位）
  ☐ 違規樣態夠全面嗎？（violations 欄位）
  ☐ 嚴重度分對了嗎？（severity 欄位）

  ---
  📊 W1 中 Schema 的 7 個欄位詳解

  | 欄位           | 用途           | 例子                      |
  |--------------|--------------|-------------------------|
  | id           | 條號           | 6、18                    |
  | type         | 類型           | 應記載 或 不得記載              |
  | original     | 官方原文（一字不差）   | 「租賃期間相關費用之約定...」        |
  | plain        | 白話版（給19歲看得懂） | 「房東不能亂收電費」              |
  | violations[] | 常見違規樣態       | ["房東按最高級距超收", "不提供電費單"] |
  | severity     | 嚴重程度         | 高（金錢損失）、中（可救濟）、低（程序瑕疵）  |
  | source_ver   | 資料來源日期       | 114年4月18日               |

  📝 W1 中你現在要做的 Schema 設計

  D2（今日）的任務就是：

  定稿這個 JSON 模板：

  {
    "id": "條目編號",
    "type": "應記載 | 不得記載",
    "original": "官方原文",
    "plain": "白話解釋",
    "violations": ["違規樣態1", "違規樣態2"],
    "severity": "高 | 中 | 低",
    "source_ver": "版本號"
  }

  具體需要定稿的問題

  1. violations 怎麼寫？
    - 每個違規樣態是一句話嗎？
    - 要不要附現實例句？（例：「房東說『小王每度收8元』」）
  2. severity 怎麼判？
    - 高 = 直接金錢損失 / 居住權喪失
    - 中 = 權益受損但可事後救濟
    - 低 = 程序瑕疵
  3. 格式確認
    - violations 是陣列 [] 嗎？
    - source_ver 要精確到日期嗎？（114年4月18日 或 114/04/18）
