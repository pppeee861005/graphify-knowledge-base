Severity = 嚴重程度

  在計劃13的規則庫中，每個違法條款都有一個 severity（嚴重程度） 等級。

  📊 三個等級

  | 等級   | 中文  | 定義             | 例子                      |
  |------|-----|----------------|-------------------------|
  | 🔴 高 | 高風險 | 直接金錢損失 / 居住權喪失 | 房東電費超收（年損失$2,400-6,000） |
  | 🟡 中 | 中風險 | 權益受損但可以救濟      | 房東延遲修繕（可向法院要求）          |
  | 🟢 低 | 低風險 | 程序瑕疵           | 審閱期不足3日（但簽約還有效）         |

  ---
  🔴 高 = 立即風險

  特徵：一旦違法，馬上有金錢或權利損失，且很難追回

  例子：
  電費超收：
    • 房東按「級距最高價」計費（不是「平均電價」）
    • 每月超收 $400-600
    • 一年損失 $4,800-7,200
    • 😡 承租人：即使打官司也很難追回所有錢
    • 🔴 severity = 高（直接金錢損失）

  行動：承租人簽約前必須檢查，發現就要拒簽或改約

  ---
  🟡 中 = 可救濟風險

  特徵：違法後有損害，但可以透過法律手段救濟

  例子：
  房東延遲修繕：
    • 房屋漏水，房東要求「修繕自費」（違法）
    • 承租人可以：
      1. 自費修繕，拿單據向房東索賠
      2. 向法院要求房東賠償
      3. 中止支付租金
    • 🟡 severity = 中（權益受損但可救濟）

  行動：簽約時要求改約，簽約後發生馬上記錄

  ---
  🟢 低 = 程序瑕疵

  特徵：違法但不會直接傷害雙方

  例子：
  審閱期不足：
    • 房東只給2日審閱期（法律要求3日）
    • 後果：承租人可主張契約無效（但實際很少用）
    • 大多數狀況：雙方都簽了，契約繼續有效
    • 🟢 severity = 低（程序瑕疵，實質無害）

  行動：建檔記錄，但不必急著處理

  ---
  💼 在計劃13中怎麼用？

  Schema欄位：
  {
    "id": "6",
    "violations": ["房東按最高級距超收", "不提供電費單"],
    "severity": "高"  ← 這個欄位
  }

  優先級排序：
  高 (🔴) → 優先檢查、優先警告、優先修正
  中 (🟡) → 次要檢查、可緩慢修正
  低 (🟢) → 記錄為主、處理優先級最低

  ---
  🎯 簡單判斷法

  問自己：「這個違法條款，對承租人的危害有多大？」

  - 會馬上掉錢嗎？ → 🔴 高
  - 要打官司才能救濟？ → 🟡 中
  - 就是寫得不規範，實質無害？ → 🟢 低
