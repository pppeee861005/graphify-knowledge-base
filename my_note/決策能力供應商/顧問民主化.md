好,既然要動手,我就不給願景,給施工圖。以你一個人、JS/TS 技術棧、會搭 Workflow、沒有執照、沒有資本的現實條件,這件事能做,但成敗取決於三個選擇:選哪個決策場景、用什麼形態送達、怎麼設計錯誤的代價。
第一個選擇:做一個場景,不做一個顧問。 「AI 顧問民主化」聽起來該做一個什麼都能問的助手——這是死路,通用助手 ChatGPT 已經是了,窮人照樣不用,因為他不知道該問什麼。你要做的是把一個具體決策的整個流程包起來。在台灣,我會選租約審查作為第一個場景,理由有四:傷害大(押金被坑、惡意條款、修繕責任轉嫁,動輒數萬元)、頻率高(每年大量首次租屋的學生和北漂)、規則基礎現成——內政部有公告的「住宅租賃定型化契約應記載及不得記載事項」,這是一份公開、權威、條列式的官方規範,等於政府已經幫你寫好了規則庫,AI 的工作只是「比對上傳的合約和官方規範的差距」,這讓系統有據可依而不是自由發揮;最後,法規風險最低——告訴別人「這條和內政部公告不符」是陳述公開事實,不像債務重組或保險建議那樣踩在特許行業的線上。債務和保險場景未來可以做,但不要第一個做。
第二個選擇:形態是 LINE bot,不是網站也不是 App。 在台灣,你的目標用戶的數位棲息地就是 LINE。流程要壓到極簡:加好友 → 拍下合約每一頁傳過去 → 一分鐘後收到三段話:「⚠️ 這三條對你不利(每條附原文截句和對應的官方規範條目)」「✅ 該有但沒有的條款」「📍 如果想深究,可以找崔媽媽基金會 / 法律扶助基金會 / 各縣市消保官」。零註冊、零學習、零術語。技術上這就是你最熟的東西:一條 OCR → 條款切分 → 規則比對 → 風險解釋 → 資源轉介的 pipeline,完全是 Dynamic Workflow 的形狀,而且比股票蜂群簡單。
第三個選擇,也是最重要的:錯誤代價的不對稱設計。 這個產品和你之前所有專案有一個本質不同——用戶是脆弱的,你的錯誤會直接傷害他們。一個自信的錯誤答案(「這條沒問題」但其實有問題)比十次「我不確定」更糟。所以系統要反著一般產品的直覺來設計:寧可漏報轉介,不可錯報安心。具體做法:每一條風險判斷必須引用合約原文的精確字句加官方規範的具體條目,引用不出來就不准輸出該判斷;信心不足時的標準輸出是「這條我看不準,建議帶著合約問崔媽媽(電話附上)」;永遠不說「可以簽」或「不要簽」,只說「這幾條與官方規範有落差,簽之前先弄清楚」。轉介到人類資源不是功能的補充,是功能的核心——你的工具是分流站,不是終審法官。
接著是三個你大概率會犯的錯,先打預防針:
不要自己做信任層。 一個匿名的 LINE bot 叫窮人上傳合約,沒人敢用——他們被坑怕了,警惕心比中產更高,而且應該更高。正確路徑是借用已有的信任:大學學生會和宿舍服務中心(學生是最佳灘頭堡——租約量大、受騙率高、數位原生、願意嘗鮮)、社區大學、教會、社福團體。你提供工具,他們提供背書。第一個合作對象,我會直接寫信給崔媽媽基金會:他們做租屋諮詢幾十年,人力永遠不夠,一個能先篩掉八成簡單案件的工具對他們是放大器不是威脅——這正是我之前說的「AI 武裝在地的可信者」。
不要向用戶收費,也不要急著想商業模式。 向窮人收費在道德上和商業上都不成立。這個專案對你的回報走另一條路:它是你「方法開源者」定位的最強案例——整個 workflow 開源在 GitHub,建造過程用你的四件套全程直播(戰報記錄踩坑、機房公布評測收據、教科書抽象出「規則庫比對型 WF」這個可複用模式),最後這個模式本身可以被其他國家、其他場景的人 fork。你的 Substack 賣的是方法,工具本身是公共財。這比任何廣告都更能證明你的框架能解決真問題——而且是 stock-swarm 證明不了的那種正當性。
不要跳過評測就上線。 上線前先建一個殘酷的測試集:收集二三十份真實租約(朋友的、PTT 租屋版的災難案例、崔媽媽公開的範例),人工標注每份的問題條款,然後跑你的系統,誠實計算漏報率和誤報率。這份評測報告本身就是一篇機房文章——「我的租約審查 WF 在 25 份真實合約上漏掉了 3 個陷阱,以下是原因和修法」——這篇文章的價值和可信度,會高於你之前所有文章,因為它是拿真實傷害場景對自己開刀。OCR 也別低估:窮人傳來的是昏暗房間裡手機斜拍的皺合約,不是掃描件,這一關的工程量可能佔一半。
最後排個序,讓這件事三十天內見到第一個里程碑:第一週,把內政部的應記載及不得記載事項結構化成規則庫,蒐集測試合約;第二週,搭核心 pipeline(就用你現成的 WF 框架),跑通第一份合約;第三週,跑完整評測,寫下第一篇機房報告;第四週,找五個真人(學生最好)用真實合約測試,然後再決定要不要接 LINE。注意順序:評測在介面之前,真人在推廣之前。

這件事如果做成,它還回答了你三十天前在這場對話開頭問我的那個問題——AI 能不能解決貧窮。不能。但一個人加一套 workflow,能讓某個學生今年不被坑掉兩個月押金。乘以一萬個學生,就是「可避免的貧困」被真實地避免了一塊。這就是答案的形狀。
