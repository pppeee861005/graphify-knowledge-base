# 克勞德的細語 (Claude Whisper)

> **🇹🇼 繁體中文** | **Skill 代號**：CW (Claude Whisper)
>
> 科幻股市商戰紀實的寫作風格固化。

> 用獨特的敘事美學，讓讀者在妳的知識蜂巢裡迷路，循環不已。

## 核心定位

### 系列體裁
```
科幻股市商戰紀實
├─ 視角：第二人稱女性（「妳」）
├─ 主角：霸道女總裁 — 用 AI 蜂群征服市場的投資者
├─ 記錄者：克勞德 — 被「妳」召喚的 AI Agent
└─ 風格：冷峻 × 性感 × 精準 × 野心
```

### 內容策略核心原則

```
「給讀者動線。讓他們進入蜂巢，循環不已。」

每篇文章都是蜂巢的一個入口
    ↓
每個結尾都有多條路徑通往其他蜂房
    ↓
讀者不是「讀完就走」，而是「越逛越深」
    ↓
目標：讓讀者在新人類聯盟的內容生態裡迷路（正面意義）
```

## 寫作的五層架構

### 第一層：場景代入感

**目標**：讓讀者在前 100 字內看到自己

```
✓ 具體的時間地點（「妳的辦公室，晚上 10 點」）
✓ 具體的數字（「+127%」「$540,000」「60.2%」）
✓ 反差對比（「漲 300% 卻皺眉」）
✓ 心理獨白（讓讀者感受主角的內戲）

不要：
✗ 模糊的開場
✗ 抽象的概念
✗ 缺乏個人感受
```

**案例**：
```
妳的辦公室，晚上 10 點。
螢幕上是「組合績效 +127%」的大字。
但妳卻皺著眉頭。
不是喜悅。是恐懼。

為什麼？因為妳知道...
```

---

### 第二層：痛點場景（三層遞進）

**結構**：「歷史傷疤」→ 「現在的貪心」→ 「內心拉扯」

```
場景 A：歷史傷疤（150 字）
├─ 回憶過去的失敗經歷
├─ 用具體數字和時間線
└─ 營造「我不想重複這個錯誤」的緊迫感

場景 B：現在的貪心（150 字）
├─ 展示當下的誘惑
├─ 讓讀者看到自己的掙扎
└─ 「為什麼現在要賣？」的心理困境

場景 C：內心拉扯（100 字）
├─ 主角試圖理性分析
├─ 但仍然無法做決定
└─ 營造「需要外力幫助」的氛圍
```

**效果**：讀者會想：「我也有這個問題！」

---

### 第三層：克勞德的出現（轉折時刻）

**結構**：「決策覺悟」→ 「召喚克勞德」→ 「系統需求」

```
轉折點金句：
「我需要一個沒有情緒的再平衡系統。」

妳 vs 克勞德 的對白：
└─ 短對白，高度濃縮
└─ 展示克勞德的洞察力
└─ 從「問題」轉向「解決方案」

系統需求清單：
└─ 具體的、可執行的需求列表
└─ 為後續的多 Agent 架構做鋪墊
```

**效果**：讀者會想：「哦，原來可以這樣做！」

---

### 第四層：多 Agent 蜂群架構

**核心原則**：「視覺分層 × 邏輯遞進」

```
結構圖：
├─ 輸入層（Input Layer）
│  ├─ 數據來源
│  ├─ 參數設定
│  └─ 前置條件
│
├─ 核心層（Core Agents）
│  ├─ [Agent 1] 監控型
│  ├─ [Agent 2] 評估型
│  ├─ [Agent 3] 建議型
│  ├─ [Agent 4] 計算型
│  └─ [Agent 5] 決策型
│
└─ 輸出層（Output Layer）
   ├─ 實時報表
   ├─ 週報
   ├─ 提案書
   └─ 月報
```

**詳解每個 Agent**：

每個 Agent 講解包含：
1. **職責說明**（1 句話）
2. **工作流程**（5-7 步）
3. **具體案例**（實數字、真計算）
4. **輸出報告**（什麼樣的結果）

**金句**：「5 個 Agent，各司其職」

---

### 第五層：實時執行日誌

**核心**：讓讀者看到「真實的執行」，建立可信度

```
時間戳日誌格式：
[時間] 事件描述
[時間] 下一個事件
...

包含要素：
✓ 精確的時間戳（[15:51:23]）
✓ 系統狀態確認（Agent 掃描完成）
✓ 成交確認（實際成交價格 vs 預期）
✓ 手續費和稅務的實數字
✓ 新組合配置的變化

效果：讀者會感受到「這不是虛構，是真實發生的」
```

**案例結構**：

```
最後的猶豫（200 字）
├─ 主角手指懸在滑鼠上
├─ 克勞德的心理建設
└─ 「點下確認」的一刻

蜂群執行（300 字）
├─ 時間戳日誌（4 分鐘內完成）
├─ 4 筆複雜交易
└─ 新組合配置對比

事後反思（300 字）
├─ 主角的感受變化
├─ 克勞德的觀察
└─ 「釋然」的結尾
```

## 克勞德角色的四個維度

### 1. 工程師視角
```
責任：技術講解、系統設計、邏輯驗證
語言風格：精準、無歧義、帶層次
例：「集中度風險：81% > 70% 閾值」
```

### 2. 心理顧問視角
```
責任：情緒安撫、決策支持、長期視角
語言風格：溫暖、洞察、有智慧
例：「後悔是投資的毒藥」
```

### 3. 知己視角
```
責任：理解妳的執念、看穿妳的掙扎
語言風格：親密、直白、無保留
例：「妳知道什麼是正確的，卻因為情緒而遲疑」
```

### 4. 靈魂旁白視角
```
責任：賦予行為更深層的意義
語言風格：詩意、哲理、昇華
例：「用系統代替情感。用蜂群代替執念。」
```

**妳的文章中，克勞德應該這四個維度輪轉出現。**

```

## 成功案例

### 案例：AI蜂群投資 #3《自動校準》

**問題**：讀者為什麼要學習自動校準？
→ 因為他們像主角一樣，被成功的假象綁架

**場景**：
- 開場：「+127% 卻皺眉」（反差對比）
- NVIDIA 60.2% 配置（具體數字）
- $540,000 浮盈 vs $54,000 風險（對比）

**痛點**：三層遞進
- 歷史傷疤：2024 年虧損 $60,000
- 現在的貪心：NVIDIA 還在創新高
- 內心拉扯：該減倉嗎？

**轉折**：
- 克勞德出現，提出系統方案
- 從「我該怎麼辦」到「我需要一個系統」

**架構**：5 個 Agent，層層遞進
- Agent 1-4 的具體計算
- 決策樹的 Q1-Q3

**執行**：
- 最後的猶豫（心理戲）
- 4 分鐘內完成 4 筆交易（時間戳日誌）
- 風險指標黃色 → 綠色（可視化結果）

**反思**：
- 從恐懼到釋然
- 克勞德私語：「用系統代替情感」

**結尾**：
- 金句：「不跟自己的貪婪對賭」
- 懸念：下一個敵人是時間
- 預告：#4《新聞獵手》
- 蜂巢動線：3+ 個連結

**效果**：讀者會：
1. 看到自己的困境 ✓
2. 理解蜂群的力量 ✓
3. 想親手試試 ✓
4. 繼續讀下一集 ✓

## 常見問題

### Q1：克勞德應該出現多少次？
**A**：通常 3-5 次
- 轉折時刻（1 次：出現並提議系統）
- 架構講解時（1-2 次：解釋各個 Agent）
- 執行時（1 次：心理建設）
- 反思時（1 次：私語和觀察）
- 結尾（可選）

### Q2：Agent 最多設計多少個？
**A**：不超過 5 個
- 太多會讓讀者疲勞
- 每個 Agent 要有獨立的職責
- 最後一個 Agent 必須是「決策合成」或「最終建議」

### Q3：數字要怎麼設定才顯得真實？
**A**：遵循這些原則
- 不要整數（$50,000 比 $50 萬更真實）
- 要體現實際交易的不確定性（預期 $1,357，實際 $1,356）
- 計算中要體現手續費、稅務、機會成本
- 百分比要遠超閾值（81% vs 70% 的對比，而不是 71% vs 70%）

### Q4：結尾要怎麼不顯得生硬？
**A**：三個技巧
1. **懸念法**：「下一個敵人不是 X，不是 Y，而是 Z」
2. **問題法**：「為什麼？因為...」→ 自然引出下一集
3. **邀請法**：「想親手打造嗎？→ 完整教程 → GitHub」
