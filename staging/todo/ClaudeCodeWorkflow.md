這段來源詳細介紹了 **Claude Code** 最新推出的 **Workflow** 功能，這項創新讓 AI 代理（Agent）的協作從模糊的自然語言指令進化為**精準可控的 JavaScript 腳本**。透過自動生成的程式碼，使用者可以定義複雜的多階段任務，例如程式碼審查或深度研究，並實現**可觀測、可結構化驗證且能重複使用**的自動化流程。該功能支持多個代理並行運作，並允許使用者對腳本進行手動調整、存檔與分享，大幅提升了開發效率。相較於過往的子代理模式，這種**編程化的工作流編排**被視為繼 MCP 與 Skills 之後的又一顛覆性突破。使用者只需透過特定的關鍵字即可啟動這些精密設計的腳本，將複雜的技術研究轉化為穩定產出的標準化作業。

Claude Code 的 **Workflow** 功能（透過 `ultraWork` 關鍵詞觸發）是其在 V2.1.47 與 V2.1.48 版本中新增的一項突破性功能，它將 AI 的「Agent 編排」從傳統的自然語言描述，升級為**以 JavaScript (JS) 腳本驅動的結構化工作流**。

以下為其詳細定義與優勢：

### 什麼是 Workflow 功能？
這項功能的核型在於 **「用代碼定義流程」** 而非僅靠 Prompt。當使用者在 Claude Code 中輸入 `ultraWork` 指令後，Claude 不會立即執行任務，而是先編寫一段 JavaScript 腳本，明確定義任務的各個階段（Stages）以及每個階段所需的專業 Agent。例如，一個 PR 審查流程可以被分解為「審查 (Review)」、「驗證 (Validation)」與「報告生成 (Report)」三個階段。

### Workflow 的主要優勢
1.  **精準可控的編排 (Precision & Control)**：
    相較於先前 Subagents 或 Agent Teams 的臨時派生，Workflow 透過 JS 代碼實現了**精準控制**。這種方式讓 Agent 的行為不再僅依賴模型的「臨場發揮」，而是遵循可觀測、可驗證的結構化路徑。

2.  **高度的可複用性 (Reusability)**：
    這是 Workflow 最核心的優勢。一旦生成並跑通了一個工作流腳本，使用者可以將其保存並**分享給其他用戶**。其他用戶只需直接調用該腳本，即可複用這套成熟的自動化流程，無需重新編寫指令。

3.  **強大的可觀測性 (Observability)**：
    使用者可以透過 `/workflows` 命查查看任務的詳細進度。系統會顯示每個 Agent 的**執行時長、消耗的 Token 數量、調用的工具**以及具體的狀態。這讓複雜的多 Agent 協作過程變得透明且易於調試。

4.  **支持多種複雜形態**：
    Workflow 支持六種不同的執行模式，包括：**流水線、同步聚合、對抗驗證、末尾制、累積式以及嵌套式**，這使其能處理多維度代碼審查、漏洞掃描、跨多文件重構等複雜生產級任務。

5.  **可迭代與自定義**：
    使用者可以對生成的 JS 腳本進行修改與迭代。如果對某個環節不滿意，可以直接編輯腳本中的邏輯，從而實現對工作流的持續優化。

總結來說，Workflow 將 Claude Code 從一個簡單的 AI 助手提升為一個具備**「Harness Engineering（腳本化工程控管）」**能力的自動化平台，讓複雜的 AI 協作任務變得可編程、可重複且可管理。

開啟 Claude Code 的 **Workflow** 功能（這是一個在 V2.1.47 和 V2.1.48 版本中新增的隱藏功能）主要分為三個步驟：環境變數設定、啟動程式以及使用特定關鍵詞。

以下是具體的開啟流程：

1.  **在終端機設定環境變數**：
    首先，你需要打開終端機（Terminal），並在啟動 Claude Code 之前，輸入一個特定的 `export` 指令來開啟權限。雖然官方在更新日誌中移除了解說，但該功能在代碼層面依然存在。你需要輸入：
    `export CLAUDE_CODE_WORKFLOWS_ENABLED=1`（註：來源提到需輸入 `export` 加參數，此為該功能通用的環境變數設定）。

2.  **啟動 Claude Code**：
    完成環境變數設定後，在同一個終端機視窗中輸入 `claude`（或你啟動 Claude Code 的命令）來執行程式。

3.  **使用關鍵詞觸發**：
    進入 Claude Code 的對話介面後，輸入 **`ultraWork`** 這個關鍵詞。當你正確輸入時，這個詞會變成**彩色且具備漸層效果**，代表 Workflow 功能已成功激活。接著在關鍵詞後面加上你想要執行的任務（例如：`ultraWork 為當前 PR 生成 review workflow`），Claude 就會開始自動編寫 JavaScript 腳本並執行工作流。

**後續管理提示：**
*   **查看進度**：你可以輸入 `/workflows` 命查來即時查看所有 Agent 的運行狀態、進度與資源消耗。
*   **腳本持久化**：預設生成的腳本只會保存三天，若想長期使用，可以透過指令將其複製到用戶自定義路徑下，以便日後重複調用。

根據來源所述，Claude Code 的 Workflow 腳本確實支援六種執行模式，但需要注意的是，來源中僅**列出了這六種模式的名稱**，並表示具體的運作演示將在後續的影片中提供。

這六種模式分別為：
1.  **流水線 (Pipeline)**
2.  **同步聚合 (Synchronous Aggregation)**
3.  **對抗驗證 (Adversarial Validation)**
4.  **拼尾製 (可能是指末尾淘汰或結果篩選)**
5.  **累積式 (Cumulative)**
6.  **嵌套式 (Nested)**

雖然來源未詳細拆解每一種模式的內部代碼邏輯，但說明了 Workflow 腳本**運作的通用核心機制**，這也是這些模式能夠執行的基礎：

*   **以 JavaScript 代碼定義流程**：Workflow 的運作不再僅靠自然語言提示詞（Prompt），而是將 Agent 的編排「固化」成一段 JS 腳本。這讓流程變得**精準可控**，且能實現結構化的驗證。
*   **階段化管理 (Stages)**：一個工作流會被拆解為多個明確的階段。例如在來源提供的「深度研究」案例中，運作流程包含三個階段：**搜索 (Search)、驗證 (Validation)、合成報告 (Synthesis)**。
*   **專業 Agent 協作**：在腳本中會定義多個具備特定技能的 Agent。例如，「深度研究」模式會同時啟動研究官方文件、研究論文及研究社群的 Agent。
*   **最小化代碼要素**：一個 Workflow 腳本要能運作，必須包含三個核心元素：**元數據 (Metadata)**（名稱與描述）、**Agent 方法調用**（至少調用一次），以及**結果回傳**（透過 `return` 或 `retain` 將結果傳回）。

總結來說，這六種模式代表了 Claude Code 處理複雜任務的不同**邏輯結構**。雖然來源目前僅給出清單，但強調了這些模式能處理如「多維度代碼審查」、「跨文件重構」或「自動漏洞掃描」等高階生產級任務。
