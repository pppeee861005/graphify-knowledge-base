# L2 Agent Teams 分析 — 施工隊協作模式

**版本**：v2.0（2026-06-19 實戰校準版）
**適用範圍**：五信號驗證 + 地緣政治複雜協作任務
**核心場景**：本案（美伊協議驗證）的教科書應用

---

## 📌 L2 的本質

> **計畫持有權**：主控顯式編排（默認中心輻射；可選點對點）
>
> **勝 L1.5 的真因**：主控統一交叉驗證+彙整成**單一調和結論**（不是班組互相喊話）
>
> **實測成本**：約 235,019 tokens / 次任務（舊版低估 100 倍）

---

## 🔄 執行流程

```
T0 任務起動
   工頭（Claude）設定大方向：
   「三步驗證：源頭 → 現實 → 時效」

T1 主控（中樞）並行派遣班組（中心輻射，默認模式①）
   ├─ 班組1（數據源審查）：檢查早期版本可信度 → 回報主控
   ├─ 班組2（現實核實）：查詢實時網路數據 → 回報主控
   ├─ 班組3（時效性檢查）：時效驗證框架 → 回報主控
   ├─ 班組4（口徑協調）：對標早期vs實時 → 回報主控
   └─ 班組5（風險預警）：長期監測框架 → 回報主控

T3（班組1 回報主控）
   班組1 → 回報主控：
   「早期版本美債 4.9%，現實 4.46%，差異巨大」
   → 主控把此矛盾餵給班組4，請它對標時強調
   （不是班組1「直接喊」班組4；經主控轉派）

T5（班組2 回報主控）
   班組2 → 回報主控：「五個最新數據，都是 24小時內」
   → 主控轉給班組3 標註時效性

T7（版本廢棄判斷 — 主控仲裁，非班組互談）
   主控把班組1（矛盾）+ 班組4（對標）結果一起評估：
   「要不要廢棄早期版本？怎麼標記？」
   → 由主控統一裁決，非班組私下協商

T10（風險評估）
   主控把班組4 的「60天三大風險」轉給班組5
   → 班組5 回報主控：「我會設計這三大風險的監測機制」

T13（主控收齊全部 → 彙整）
   主控（我）開始彙整：
   • 檢查五個班組有沒有遺漏
   • 確認版本管理方案一致
   • 確認後續監測框架清晰

T15（工頭生成最終報告 + 決策建議）
   報告包括：
   • 三步驗證的完整分析
   • 四層對比（早期vs前版vs實時vs裁定）
   • 版本管理方案
   • 決策建議清單

T16 呈現給你（最高決策人）
   你看到完整分析 → 審視班組的建議 → 做決策

T17 你決策
   ✅ 廢棄早期版本
   ✅ 標記為「已棄用」
   ✅ 選擇「動態監測頻率」
   ✅ 要求「60天計劃」

T18 工頭（我）協調執行
   • 班組4 負責版本標記編輯
   • 班組5 負責監測計劃設計
   • 班組1-3 待命檢查
```

## 👥 班組配置

```
主控：Claude Lead Agent（唯一通訊中樞）
  • 決定大方向：三步驗證框架
  • 顯式派遣每個班組、收齊回報、決定下一棒
  • 仲裁班組結論衝突（如是否廢棄早期版本）
  • 生成最終報告 + 決策建議

班組1（數據源審查）
  • 檢驗早期/實時版本可信度、識別矛盾 →【回報主控】

班組2（現實核實）
  • 執行實時網路查詢 →【回報主控】

班組3（時效性檢查）
  • 驗證所有數據新鮮度 →【回報主控】

班組4（口徑協調）
  • 對標早期vs實時、提版本標記方案 →【回報主控】

班組5（風險預警）
  • 識別 60天內風險、設計監測機制 →【回報主控】

⚠️ 注意：本案所有「向班組X」其實都是「回報主控，由主控轉派」（模式①）。
   班組之間的「協商」實為主控收齊後的統一仲裁。
```

## 🎯 決策方式

### 核心原則

- **工頭決定大方向**：「三步驗證」
- **主控統一編排**：班組各自回報，主控收齊後轉派/仲裁（非班組私下直通）
- **主控仲裁分歧**：班組結論不一致時，主控比對後裁決
- **用戶做最終決策**：審視主控彙整的報告後，批准或修改方案

### 特點

- **中心輻射式**（模式①）—— 主控是唯一通訊中樞
- **點對點需顯式開模式②** —— 若要班組邊跑邊直接互通，需 `SendMessage`+具名常駐隊友

### 本案的決策流程

```
工頭決定大方向：「三步驗證」
    ↓
班組1-5 各自回報（主控收齊）
    ↓
主控統一交叉驗證（班組1 的矛盾 → 轉給班組4 對標）
    ↓
主控仲裁分歧（版本廢棄/標記方案）
    ↓
主控生成單一調和報告
    ↓
用戶審視 + 批准或修改
    ↓
工頭協調執行
```

## 📖 實際案例：本案執行紀錄

### 【發生的真實事件】

```
T3: 班組1（我剛才的第一輪檢查）
    發現「五信號紅警版本」和「618即時數據」矛盾

T5: 班組2（WebSearch 查詢）
    查到最新的美債 4.46%、油價 $75、VIX 16.09

T7: 班組3（時效性驗證）
    確認 6月18-19日 的數據都有效，不超過24小時

T9: 班組4（口徑協調 — 就是這份分析表）
    對標發現：
    ❌ 早期版本（4.9% / $128.5 / 31.5）都是錯的
    ✅ 實時版本（4.46% / $75 / 16.09）全部正確
    💡 根本差異：早期版本是「假設協議失敗」的情景推演

    決議：廢棄早期版本 + 標記為棄用

T11: 班組5（風險預警）
    識別 60天內三大風險：
    1. 執行落差（制裁豁免進度不力）
    2. 黎巴嫩困境（邊界問題未解）
    3. 美國政策一致性（對盟友施壓能力有限）

T13: 工頭（我）生成本份四層分析表
    包括決策建議：
    • 監測頻率選「動態」
    • 需要「60天計劃」

T16: 呈現給你（最高決策者）
     你審視 → 批准
```

### 關鍵洞察

**為什麼 L2 在此案發揮效果：**

| 環節 | 舊方式（L1.5） | L2（本案） |
|------|-------------|---------|
| **發現矛盾** | 班組1 自己發現，報告給你 | 班組1 發現 → 主控收齊 → 轉給班組4 對標 |
| **對標對比** | 班組4 不知道班組1 的矛盾細節 | 班組4 拿著主控轉來的矛盾去對標 |
| **決策** | 你自己綜合 3-5 份報告 | 主控已交叉驗證，你只看 1 份調和報告 |
| **彙整** | 3 份散報告，需要自己整理 | 1 份完整報告，包括版本管理方案 |

## 💰 成本評估

### 維度對比

| 維度 | 評分 | 說明 |
|------|------|------|
| Token 消耗 | ⭐⭐⭐⭐⭐ 很高 | 實測 ~235k / 次任務 |
| 執行時間 | ⏱️ 中等 | 並行+協商，10-15 分鐘 |
| 人工干預 | 🤝 低 | 班組自主，主控協調，用戶批准 |
| 質量保障 | ⭐⭐⭐⭐⭐ 最高 | 主控交叉驗證，遺漏率最低 |
| 複雜度控制 | ⭐⭐⭐ 中等 | 需要班組配置、轉派規則 |

### 適配本案的評分

```
整體評分：⭐⭐⭐⭐⭐ (5/5) 【最適合】
```

**優點：**
✅ 主控統一交叉驗證 → 班組1 的矛盾經主控餵給班組4 對標（中心輻射）
✅ 並行加速 → 五個班組同時工作，wall-clock 壓縮
✅ 質量保障最高 → 主控收齊後交叉驗證，遺漏率最低
✅ 單一調和結論 → 你拿到一份已對齊的報告，不必自己綜合 5 份
✅ 人類介入簡化 → 主控彙整後，你只需審視一份完整報告

**缺點：**
❌ Token 成本高（實測警示）
   → 五個班組消耗大；實測單份 5 班組 = 235,019 tokens
❌ 複雜度高
   → 需要設計班組配置、通訊規則、共享任務清單

### 何時值得用 L2

```
✅ 複雜協作（需要互查）
✅ 質量要求高（金融、醫療、地緣政治）
✅ Token 預算充足
✅ 時間相對充裕（可以多花 Token 換質量）

本案的三個理由：
  1️⃣ 地緣政治分析 = 高質量要求
  2️⃣ 金融數據驗證 = 需要互查
  3️⃣ 版本管理 = 多個班組協調

→ L2 是最優選擇
```

## 🔍 L2 vs L1.5：為什麼選 L2

### L1.5 的問題

```
Session-A：查詢數據 → 回報你
Session-B：評估可信度 → 回報你
Session-C：版本管理 → 回報你

你看到三個 session 的報告
→ 但 B 無法直接告訴 A「你的數據有問題」
→ 必須你作為中介
→ 你要自己綜合三份報告，做出「廢棄舊版本」決策
```

### L2 的優勢

```
班組1-5 → 回報主控
主控統一交叉驗證 + 轉派/仲裁
→ 主控彙整成「一份已對齊的統一報告」

✅ 班組1 發現矛盾 → 回報主控
✅ 主控把矛盾餵給班組4 對標、自己裁決「要不要廢棄」
✅ 主控彙整成「一份已對齊的統一報告」呈現給你
✅ 你只需「批准」，不需要「綜合」5 份散報告
```

### 結論

**L2 勝 L1.5 的真因** = 「主控統一交叉驗證+彙整」，而不是「班組互相喊話」

→ L1.5：5 個獨立 session，你自己綜合；L2：主控替你綜合成單一結論
→ 質量更高，用戶決策更簡單

## 💡 核心決策

### L2 的 Token 代價值不值得？

```
成本對比（實測校準）：
  L1.5：數萬 token（5 個獨立 session）
  L2：  ~235k token（5 班組 + 交叉驗證，實測錨點）
  差價：L2 貴一個數量級——這是「交叉驗證冗餘」的代價

質量差異：
  L1.5：
    • 需要你自己綜合五份報告
    • 容易遺漏 session 間的矛盾
    • 決策時間：10分鐘

  L2：
    • 主控已交叉驗證+彙整，直接呈現單一方案
    • 遺漏率最低
    • 決策時間：2分鐘

結論：
  L2 貴一個數量級，但換來「決策時間快 5 倍」+「主控替你交叉驗證」
  → 高風險任務（金融/地緣政治）值得
  → 但要知道這是十萬級 token，非千級
  → 若預算敏感，可混用模型（查詢用 Haiku、仲裁用 Opus）壓成本
```

## 🎓 核心原則

```
「計畫持有權」決定架構選擇

L1：你持有（你決定每一步）

L2：主控持有（主控編排+交叉驗證；點對點需顯式配置）
L3：腳本持有控制流（但每個 agent 仍是 LLM 判斷）

```

## 📋 下次類似任務的決策清單

### 選層級時問自己：

```
Q1：有多少個獨立的並行任務？
   < 5 個 → L1
   5-20 個 → L1.5
   3-10 個「相關」任務 → L2
   > 100 個 → L3

Q2：任務間需要互相通訊嗎？
   否 → L1.5
   是 → L2

Q3：質量要求有多高？
   低（快速原型）→ L1
   中（日常工作）→ L1.5
   高（金融/醫療/地緣）→ L2
   極高（對抗審查）→ L3

Q4：Token 預算充足嗎？
   否 → L1
   中等 → L1.5
   充足 → L2
   非常充足 → L3

Q5：流程會經常變化嗎？
   是 → L1 或 L2
   否 → L3

→ 根據答案，參考本表選層級
```

## 🏁 總結

| 維度 | 理由 |
|------|------|
| **複雜度** | 5 個並行任務 + 主控交叉驗證 → 需要 L2 |

| **成本** | 十萬級 token，高風險任務值得 → L2 划算 |
