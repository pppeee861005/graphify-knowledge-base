# CC Agent 架構指南

**適用專案**：中東戰爭五信號板監測系統
**推薦架構**：L1.5 Agent View
**更新日期**：2026年6月18日

---

## 🔑 核心洞察：「誰持有計畫？」

在日常生活中，**計畫的持有權**決定了協作的方式：

| 層級 | 場景 | 計畫持有者 | 角色設定 |
|:----:|------|-----------|---------|
| **L1** | 家庭烹飪 | 主廚（你） | 主人翁 + 幫手們 |
| **L1.5** | 多個廚房同步 | 你（人類監督） | 中央監控台 |
| **L2** | 施工隊協作 | 工頭 + 各班組 | 平等議論 + 互相檢查 |
| **L3** | 大規模工廠流程 | 流程本身（代碼） | 自動化機器 |

> 💡 **重要原則**：這四層不是「選哪一個」，而是「能力逐級升級」。

## ✅ 本專案推薦：L1.5 Agent View

### 為什麼是 L1.5？

#### 📊 多源並行查詢（多個廚房同步）

| 蜂群 | 監測目標 | 數據源 |
|:----:|---------|-------|
| A | 美債殖利率 | Trading Economics / FRED |
| B | WTI原油 | CME / NYMEX |
| C | VIX恐慌指數 | CBOE / Yahoo Finance |
| D | USD/IRR匯率 | Investing.com |
| E | 黃金現貨 | Kitco / JM Bullion |

#### 🧠 人類決策仍是核心

- 風險評估需要人類判斷（地緣政治不是純數據）
- 紅警發布需要人類審核
- 預警時機需要人類決定

#### ⚠️ 為什麼不是 L2/L3？

| 層級 | 不適用原因 |
|:----:|-----------|
| L2 | 蜂群不需要「議論」數據，只需查詢回報 |
| L3 | 地緣政治無法完全自動化，需人類判斷 |

## 🔍 網上驗證協議（新增）

### 驗證三步法

每個數據點必須通過以下驗證：

| 檢查項 | 方法 | 通過標準 |
|--------|------|---------|
| **1. 來源可信度** | 核對官方/權威數據源 | 至少1個官方來源（央行/交易所） |
| **2. 交叉比對** | 查詢2-3個獨立來源 | 數據偏差 < 2% |
| **3. 時效性** | 確認數據時間戳 | 數據更新 < 1小時 |

### 驗證輸出格式

```
📍 [指標名稱]
├─ 查詢值：[數值]
├─ 來源1：[名稱] → [數值] ✅/❌
├─ 來源2：[名稱] → [數值] ✅/❌
├─ 時間戳：[UTC時間]
└─ 驗證結果：✅ 確認 / 🟡 偏差 / ❌ 異常
```

### 驗證範例

```
📍 十年期美債殖利率
├─ 查詢值：4.45%
├─ 來源1：Trading Economics → 4.439% ✅
├─ 來源2：Investing.com → 4.45% ✅
├─ 來源3：FRED → 4.43% ✅
├─ 時間戳：2026-06-18 12:30 UTC
└─ 驗證結果：✅ 確認（偏差 < 0.5%）
```

### 異常處理

| 情況 | 處理方式 |
|------|---------|
| 數據偏差 > 5% | 🔴 標記異常，人類介入確認 |
| 單一來源無法訪問 | 🟡 使用備用來源，標註 |
| 數據時效 > 6小時 | 🟡 標記陳舊，建議重查 |

## 🚫 何時升級到 L2/L3？

| 條件 | 升級目標 | 觸發場景 |
|------|:--------:|---------|
| 信號需要交叉驗證 | L2 | 蜂群A發現異常 → 蜂群B/C確認 |
| 全自動化預警發布 | L3 | 紅警閾值觸發 → 自動推送通知 |
| 24/7無人值守監測 | L3 | 持續監測 + 自動報告生成 |
