**任務背景**：中東戰爭後續影響分析 — 黃金走勢與新秩序推演（2026-06-19）
**核心需求**：情景推演 + 關鍵指標建立 + 監測報告框架
**實際執行**：L1 對話式迭代（人機協作）

## 🔍 詳細方案對比

### L1：Subagents（廚房型）— 【本案現用】

#### 執行流程

```
T0 你說「讀這份黃金走勢文件，我們來聊聊」
   ↓
T1 我（Claude）收到任務 → 讀取文件 → 理解框架
   ↓
T2 我提出三個思考角度，邀請討論
   ↓
T3 你說「討論兩個假設：美國強 vs 美國弱」
   ↓
T4 我展開兩條連鎖反應路徑 → 對比分析
   ↓
T5 你追問「歐洲派兵意義？」
   ↓
T6 我深層解讀 → 提出區分指標
   ↓
T7 你追問「歐洲無作為 = 硬實力弱化？」
   ↓
T8 我展開三層級分析（軍事產能/投射能力/戰略自信）
   ↓
T9 你要求「展開後美國時代推演」
   ↓
T10 我生成完整情景分析 + 12個關鍵指標
   ↓
T11 你說「生成 .md」
   ↓
T12 我輸出靜態報告：後美國時代_新秩序展開推演.md
```

#### 班組配置

```
本案實際上只需要 1 個 Claude（我）
  • 讀取文件
  • 理解用戶假設
  • 展開分析
  • 迭代深化
  • 生成報告

無需 Subagent 的原因：
  • 任務是「思考型」而非「數據搜集型」
  • 不需要並行查詢多個數據源
  • 核心價值在「邏輯推演」而非「信息聚合」
```

#### 決策方式

- **用戶主導方向**：每次追問決定下一步
- **Claude 展開分析**：根據追問深入展開
- **迭代式深化**：每輪對話都比上輪更深
- **特點**：完全序列化，但正是本案所需

### L1.5：Agent View（監控台型）

#### 執行流程

```
T0 你起動 3 個 background agent sessions
   ├─ Session-A: 負責「黃金走勢分析」
   ├─ Session-B: 負責「地緣政治推演」
   └─ Session-C: 負責「指標體系建立」

T1-T15 三個 session 各自獨立運行
   • Session-A 執行：分析黃金歷史走勢 + 影響因素
   • Session-B 執行：推演三種可能結局
   • Session-C 執行：建立 12 個監測指標

T16 你監看三個 session 的進度條
   • A：✅ 完成黃金分析
   • B：⏳ 正在推演（70%）
   • C：⏳ 建立指標（40%）

T20 全部 session 完成
   你看到三份報告

T21 你做決策：綜合三份報告
   ↓ 但無法讓 A、B、C 互相討論
   ↓ 你要自己發現他們的邏輯是否一致
```

#### 適配本案的評分

```
整體評分：⭐⭐ (2/5) 【不適合】

原因：
❌ 本案需要「邏輯連貫」
   → 黃金走勢 ← 地緣政治 ← 指標體系
   → 三者必須互相參照，L1.5 無法做到

❌ 並行無意義
   → 本案不是「數據搜集」，是「邏輯推演」
   → 推演必須序列化（先假設 → 再推論 → 再指標）

❌ 用戶需要「引導式對話」
   → 本案的價值在於「邊問邊想」
   → L1.5 變成「等報告出來再看」，失去互動

✅ 可能的用途
   → 如果要同時分析「台海」「歐洲能源」「中東」三個案例
   → 可以用 L1.5 並行三個獨立分析
   → 但單一案例不適合

適合場景：多個獨立案例並行分析
不適合場景：單一案例的深度推演（本案）
```

### L3：Dynamic Workflows（工廠自動化型）

#### 適配本案的評分

```
整體評分：⭐⭐ (2/5) 【本推演不需，但監測自動化可用】

✅ 事實校準（L3 不是只配做 100+ 大工廠）：

   → 控制流由腳本決定，但每個 agent 仍是 LLM 判斷

❌ 但「本推演」確實不該用 L3（這個結論成立）：
   → 本案是「單人對話式思考推演」，價值在「邊問邊想、動態轉向」
   → 確定性腳本會凍結這種靈活性，L1 對話才是對的工具
   → 註：這跟租約「25 份批次評測」不同——那種固定流水才適合 L3 小 workflow

❌ Token 成本（修正舊估）：
   → 舊版「L3 ~50000 token」嚴重低估
   → 真實多代理任務屬十萬～百萬級（實測單份 5 班組＝235k）
   → 但這正是「思考推演不該用 L3」的另一個理由：殺雞用牛刀

何時該用 L3（監測階段，非推演階段）：
  ✅ 長期自動化監測（每日自動報告，配 CronCreate 排程）
  ✅ 12+ 指標的固定流水（pipeline 各指標獨立流過查詢→評估→預警）
  ✅ 需要對抗性審查（紅隊挑戰）

結論：
「本推演」用 L1（對話迭代）；「未來監測」可用 L3 小 workflow（非大工廠）。
工具沒有過度設計問題，是「對話推演」這個任務本就該用對話。
```

## 🎯 本案的層級選擇邏輯

### 為什麼選 L1 而不是 L2？

```
L2 假設：
  班組1：黃金走勢分析
  班組2：地緣政治推演
  班組3：指標體系建立
  班組4：數據驗證
  班組5：風險預警

  五個班組並行 → 生成完整報告 → 你審批

問題：
  ❌ 失去「對話式發現」的價值
     → 本案的突破點（歐洲派兵 → 歐洲衰弱 → 黃金邏輯）
     → 是通過「你的追問」發現的
     → 如果用 L2，班組不會自動發現這個邏輯鏈

  ❌ 失去「方向調整」的靈活性
     → 本案從「黃金走勢」開始
     → 但最後走向「後美國時代推演」
     → 這個轉向是對話中自然發生的
     → L2 無法支持這種動態調整

L1 實際：
  ✅ 每輪對話都是「發現新問題」的機會
  ✅ 你的追問決定分析方向
  ✅ 最終產出比「預設框架」更有價值
  ✅ Token 成本最低

結論：
L1 的「低效率」恰恰是「高價值」
→ 對話的「慢」讓思考更深入
→ 人類參與讓方向更準確
```

### 何時應該升級到 L2？

```
觸發條件：
  ✅ 進入「定期監測」階段（每週生成報告）
  ✅ 需要同時監測 12 個指標的實時狀態
  ✅ 需要「班組互查」確保數據準確
  ✅ 用戶時間有限，希望直接看結果

升級方案：
  班組1（數據查詢）：查詢 12 個指標的最新數據
  班組2（狀態評估）：判斷每個指標的當前狀態
  班組3（趨勢分析）：與上期對比，識別變化
  班組4（警示檢測）：識別需要關注的異常
  班組5（報告生成）：生成結構化監測報告

  工頭（Claude）協調 → 生成完整報告 → 用戶審閱

預計成本：
  Token：~8000/次
  時間：~20分鐘
  頻率：每週一次

建議：
  當監測需求確立後，再升級到 L2
  推演階段繼續用 L1
```

## 🎓 學習收穫

### 本案學到的核心原則

| 原則 | 說明 |
|------|------|
| **任務類型決定層級** | 數據型→L2，思考型→L1 |
| **對話本身就是價值** | L1 的「慢」讓發現更深 |
| **人類參與 = 質量保障** | 追問本身就是檢查點 |
| **靈活性 > 並行性** | 方向調整比速度更重要 |

### 層級選擇決策樹（本案版）

   思考推演 → L1 ✓

Q2：需要班組互查嗎？
   是 → L2
   否 → L1.5

Q3：需要長期自動化嗎？
   是 → L3
   否 → 維持當前層級
