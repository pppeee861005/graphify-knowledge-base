## 📋 Task 1：建立系列文章 Plan（規劃期，1-2 天）

### 🎯 目標
建立清晰的「系列定位」和「單篇差異化」，為後續的創作提供方向

### 📝 具體步驟

#### Step 1.1：系列大定位（30 分鐘）

```
問題清單：

1️⃣ 這個系列要解決什麼問題？
   回答範例（Agent 系列）：
   「前三篇講理論，但讀者不知道怎麼寫代碼」

2️⃣ 系列要涵蓋多少篇？
   回答範例：「E05-E07 共 3 篇，形成『實踐→應用→生態』的完整鏈條」

3️⃣ 最終讀者會獲得什麼能力？
   回答範例：「從『理解蜂群概念』到『能寫完整的 Workflow 系統』」

4️⃣ 系列的商業目標？
   回答範例：「驗證付費課程的可行性，為 6 月的『Agent 完整指南』鋪墊」
```

**輸出**：系列定位文檔（1-2 段話）

#### Step 1.2：單篇差異化規劃（45 分鐘）

```
為系列的每一篇規劃不同角色：

篇次    定位           讀者痛點              核心觀點            轉折點
──────────────────────────────────────────────────────────────────
E05   實踐入門        怎麼開始寫？         Step-by-step教程     代碼示例
E06   應用案例        怎麼用在我身上？     5個行業案例          ROI數據
E07   生態整合        怎麼跟其他工具協作？  系統架構設計         技術架構圖

你的規劃表：
篇次    定位           讀者痛點              核心觀點            轉折點
E__   ________      ______________       ____________       ________
E__   ________      ______________       ____________       ________
E__   ________      ______________       ____________       ________
```

**輸出**：「系列規劃表」（篇次 × 定位）

#### Step 1.3：目標讀者精化（30 分鐘）

```
對於「這一篇」的讀者定位：

主要讀者：
  - 身份：[e.g., 軟體工程師 / 技術主管 / AI 創業者]
  - 痛點：[最真實的一個困境]
  - 知識水位：[已知什麼，不知什麼]
  - 預期動作：[讀完後要做什麼]

次要讀者：
  - 身份：[e.g., 產品經理、HR 主管]
  - 為什麼也會讀：[哪個角度對他們有價值]

反面讀者（排除）：
  - 身份：[e.g., 完全非技術背景者]
  - 為什麼不適合：[內容難度太高 or 不相關]
```

**輸出**：「目標讀者定位」（主/次/反面）

#### Step 1.4：預期轉化率預測（30 分鐘）

```
基於內容定位的轉化率預測：

轉化率要素      E04 數據       你的預測      依據
─────────────────────────────────────────────────
內容定位命中度   95%            ___%        [痛點匹配度]
標題點擊率      40%+            ___%        [對比詞設置]
讀者完讀率      80%+            ___%        [字數控制]
訂閱轉化率      2-5%            ___%        [行動號召強度]

最終預期轉化率：
低估：__%  |  目標：___%  |  樂觀：__%
```

**輸出**：「轉化率預測」（作為發布後的對標基準）

#### Step 1.5：發布時間和社團規劃（30 分鐘）

```
發布週期：
  Substack 發布時間：美東 _________ AM / PM
  FB 社團 PM 6:00 發布：是 □  否 □

目標社團（3-5 個）：
  🥇 核心社團（必發，監測仔細）：
     1. ________________
     2. ________________
     3. ________________

  🥈 補充社團（用不同文案）：
     4. ________________

  Substack 新訂：__-__ 人
  FB 社團轉化：__-__ 人
  總新訂：__-__ 人
```

**輸出**：「發布計劃表」（時間、社團、預期數據）

### ✅ Task 1 完成檢查清單

```
☐ 系列大定位已清晰（目標問題 + 最終能力）
☐ 單篇差異化已規劃（5 篇系列表完成）
☐ 目標讀者已精化（主/次/反面明確）
☐ 轉化率已預測（有具體的預期數字）
☐ 發布計劃已制定（社團、時間、預期績效）

🚨 必需檢查：獨特的新視角見解
✓ 這篇文章的「核心新視角」是什麼？（不是重複 E04 的成功套路）
✓ 和前一篇文章有什麼「思想上的進階」或「角度上的突破」？
✓ 讀者讀完能學到「別人沒講過的洞察」嗎？
✓ 避免陷阱：用「相同結構公式」但「不同内容」≠ 獨特新視角

  檢查方法：
  1. 寫出這篇的「一句核心新觀點」
  2. 對比前序篇章，找出「創新點在哪」
  3. 問自己：「如果沒有這個新視角，這篇文章有價值嗎？」
  4. 若答案是「no」，回到 Step 1.1 重新定位

若以上全部 ✅（包含新視角檢查），進入 Task 2
```

## 🎨 Task 2：編大標題、綱要（大綱期，1-2 天）

### 🎯 目標
用「黃金標題公式」和「5 層結構綱要」為文章奠定成功基礎

### 📝 具體步驟

#### Step 2.1：標題 3 版本競爭（1 小時）

```
根據 Task 1 的「讀者痛點」，寫 3 個不同角度的標題

版本 A（對比式）：
「[舊做法] vs [新做法]：[讀者利益]」
範例：「Google Apps Script vs Workflow：HR 審批如何提速 24 倍」
長度：___ 字  ✓ / ✗ (目標 8-12 字)

版本 B（問題式）：
「[讀者的真實問題]？你可能需要 [解決方案]」
範例：「Workflow 怎麼在企業級應用中落地？5 個核心問題解答」
長度：___ 字  ✓ / ✗

版本 C（成果式）：
「[工具/方法] 如何帶來 [具體成果]」
範例：「用 Workflow 編排，讓 AI 應用的轉化率提升 300%」
長度：___ 字  ✓ / ✗

評分對標（參考 E04 的 11 字標題）：
版本 A：______ 字，對比詞 ✓/✗，具體化 ✓/✗  → 評分：8/10
版本 B：______ 字，對比詞 ✓/✗，具體化 ✓/✗  → 評分：_/10
版本 C：______ 字，對比詞 ✓/✗，具體化 ✓/✗  → 評分：_/10

最終選擇：版本 ___（最高評分）
```

**輸出**：最終標題 + 副標題（40-80 字）

## ✍️ Task 3：依大綱擬初稿、編正文、配圖（成稿期，3-4 天）

### 🎯 目標
根據綱要寫出「爆款規範」的完整正文，配套圖片和代碼

### 📝 具體步驟

#### Step 3.1：初稿快速寫作（1-2 天，2,000-3,000 字）

```
寫作指南：

【Don't】
❌ 完美主義卡頓（「第一句要完美」）
❌ 邊寫邊編輯（停止無效的改來改去）
❌ 查資料耗時（預先準備好所有素材）

【Do】
✅ 快速成稿（寫出骨架，不求完美）
✅ 先「多」後「精」（寫 3,000 字，後期精簡到 1,200）
✅ 按 5 層順序逐層寫（開場→對比→深掘→案例→結尾）

分配時間：
  開場（100 字）：30 分鐘
  對比（300 字）：1 小時（含類比設計）
  深掘（400 字）：1.5 小時（含三層邏輯推敲）
  案例（300 字）：1 小時（含數據驗證）
  結尾（100 字）：30 分鐘

  總耗時：約 4-5 小時

寫作工具：
  ✅ Google Docs（易分享、版本控制）
  ✅ 本地 Markdown（易排版、易 git）
  ⚠️ 邊寫邊在 Substack 編輯（容易被分散注意力）
```

#### Step 3.2：精簡 + 調色（0.5 天，1,200-1,500 字最終版）

```
精簡原則：

第 1 遍：刪除「重複的例子」和「多餘的修飾詞」
  目標：3,000 字 → 1,800 字

第 2 遍：合併「相似的論點」和「冗長的解釋」
  目標：1,800 字 → 1,400 字

第 3 遍：檢查「每一句是否必要」
  問題：「如果刪掉這句，讀者會不懂嗎？」
  是 → 保留
  否 → 刪除

  目標：1,400 字 → 1,200-1,500 字（理想範圍）

精簡檢查清單：
☐ 開場是否在 100-150 字？（現在 ___ 字）
☐ 對比部分是否清晰有力？
☐ 三層為什麼的邏輯是否通暢？
☐ 代碼/案例是否能證明觀點？
☐ 金句是否在文中出現過 1-2 次？
☐ 結尾號召是否清晰？
```

```javascript

```

代碼檢查清單：

☐ 有中文註解（幫助理解）
☐ 邏輯清晰（展示核心思想）
☐ 長度合適（Level 2 不超過 25 行）

```

```
