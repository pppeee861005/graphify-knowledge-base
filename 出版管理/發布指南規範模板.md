# 發布指南規範模板 | 適用於 E05+ 系列

**模板版本**：v1.0
**基於實踐**：AGENT_S01E04 發布指南成功案例
**用途**：為後續系列（E05、E06、深度對話、AI實驗室等）提供可複製的發布指南框架
**維護者**：AI 指揮官（Claude Code）

---

## 📋 使用說明

### 何時使用此模板？

✅ **必須使用**：
- 發布新系列的首篇時（E05、AI實驗室第1篇等）
- 發布期望成為爆款的文章時
- 需要在多個平台（Substack + 社群）推廣時

❌ **可選使用**：
- 輕量級碎片文章（500字以下）
- 內部工作筆記
- 快速新聞評論

### 使用流程

```
第 1 步：複製此模板
  ↓
第 2 步：填入「文章信息」部分（標題、副標題、日期等）
  ↓
第 3 步：根據「Substack 後台設定」部分填入後台信息
  ↓
第 4 步：根據「社群推廣文案」部分填入三平台文案
  ↓
第 5 步：根據「排版指南」部分進行 Substack 排版
  ↓
第 6 步：檢查「發布前檢查清單」的所有項目
  ↓
第 7 步：發布並進行「社群互動」
```

#### 規範要求

| 項目 | 規範 | 範例 |

#### 規範要求

```

✅ 文字可讀性高（18pt+ 字體）
✅ 邏輯清晰（不超過 3 個核心元素）
```

## 📐 部分三：Substack 排版與發布規範

### 排版原則

```
目的：讓讀者在 Substack 編輯器中獲得最優的視覺體驗
工具：Markdown 基本格式 + Substack 原生元件
```

### 關鍵排版要素

#### 1. 頂部區域設定

```
Substack 編輯器頂部應填入：
- Title：[你的文章標題]
- Subtitle：[你的副標題]
- Preview：[文章開頭 1-2 句]
- Section：AI 指揮官筆記 / [系列名稱]

正文第一行應包含：
**《蜂群 Agent 系列｜第 X 篇》**
*新人類聯盟 · Homo Coalitio*

目的：讓讀者清楚知道這是系列的哪一篇
```

#### 2. 引言區塊最佳化

```
Markdown 語法：
> 引言文本

Substack 化：
將 Markdown 引言複製進 Substack 編輯器
選中引言文本 → 點擊「Block Quote」or「Pull Quote」
→ 自動放大為視覺強調區塊

效果：
✅ 引言文字更大、更突出
✅ 層次感提升
✅ 讀者更容易掃讀核心觀點
```

#### 3. 流程圖/示意圖處理

```
不支持：Substack 直接渲染 SVG

解決方案：
1️⃣ 有 SVG 向量圖草稿
2️⃣ 用瀏覽器打開 SVG 文件
3️⃣ 截圖為 PNG 格式
   或用 Figma 匯出為 PNG（高保真）
4️⃣ 在 Substack 編輯器插入 PNG 圖片
5️⃣ 在圖片下方加 Caption（說明圖片含義）

Caption 範本：
*「基於 Workflow 的智慧請假審批流程視覺化」*
```

#### 4. 代碼塊語法高亮

```
Markdown 語法：
```javascript
// 代碼內容
```

Substack 支持：
✅ JavaScript、Python、Java 等主流語言自動高亮
✅ 代碼顏色、縮排自動優化
⚠️ 發布前檢查：確認代碼顏色是否正常渲染

中文註解：
✅ 代碼中應包含中文註解
✅ 幫助非英文環境的讀者理解
```

#### 5. 比較表格

```
Markdown 語法：

```

替代時間（若 10AM 有特殊考慮）：
✅ 周一 10:00 AM（週週期開始，期待感高）
✅ 周二-周三（週中活躍度最高）
⚠️ 避免周五發布（週末活動干擾）
⚠️ 避免周六日發布（讀者可能不開郵件）
```

✅ Facebook 演算法最高峰（每日活躍度最高）

### 社團選擇規範

#### 社團評估的 4 大維度

| 維度 | 評估標準 | 達標 ✅ | 不達標 ❌ |
|------|---------|--------|---------|
| **主題相關** | 社團主題是否與內容高度相關 | AI、技術、創業社團 | 日常閒聊、美妝社團 |
| **活躍度** | 日均互動量、社員規模 | 日均 30+ 互動, 3K-50K人 | 日均 <10 互動或 >100K人 |
| **社團氛圍** | 版主是否活躍、內容質量 | 版主管理嚴格、有審核 | 垃圾廣告多、無人管 |
| **推廣接納度** | 是否允許推廣、有無外鏈禁令 | 允許知識分享 | 禁止外鏈或純廣告社團 |

#### 目標社團池建立

```
第一步：收集目標社團
  ✅ 中文 AI/技術相關社團 5-10 個
  ✅ 包括：
    - AI 愛好者社團
    - 軟體工程師論壇
    - Claude/大模型討論社團
    - Agent 系列社團（新興）
    - Tech 創業社團
    - HR Tech 社團（針對案例相關）

第二步：社團排序（核心 + 補充 + 備選）
  🥇 核心社團：3 個（主力）
     → 每次必發，監測數據最仔細
  🥈 補充社團：4-5 個（加強）
     → 用不同文案發布，測試變體
  🥉 備選社團：2-3 個（備用）
     → 若核心社團反應差，替換低效社團

第三步：建立社團資料表
  - 社團名稱
  - 社團 ID/連結
  - 社員規模
  - 日均互動數
  - 版主名稱
  - 最後發布日期
  - 最近轉化數
  - 下次發布計劃
```

#### 社團文案差異化

```
同一篇文章，3 種不同社團要用不同文案

✅ AI 愛好者社團
   文案重點：「技術的優雅」
   強調：Workflow 的代碼美感、架構設計

✅ HR Tech 社團
   文案重點：「實際應用」
   強調：HR 審批案例、業務價值

✅ 創業者社團
   文案重點：「商業潛力」
   強調：Agent OS 的商業化、競爭優勢
```
