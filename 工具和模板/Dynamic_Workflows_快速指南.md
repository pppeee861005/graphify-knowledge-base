# Dynamic Workflows 快速指南

**目的**：3 分鐘理解如何使用 Dynamic Workflows
**不需要**：學習任何代碼、Workflow 架構、Stage 設計

---

## 🎯 核心概念（一句話）

> **你定義「問題和預算」，Claude Code 自動生成 Workflow 並執行。**

---

## 📋 你需要做的：2 件事

### 1️⃣ 寫「問題與預算定義書」（30-60 分鐘）

**包含 4 個部分**：

| 部分 | 說明 | 例子 |
|------|------|------|
| **問題定義** | 要解決什麼問題？ | 「檢查代碼的語法、邏輯、Bug，生成測試」 |
| **驗證標準** | 什麼時候認為成功了？ | 「Bug 發現率 ≥ 80%，測試覆蓋率 ≥ 15%」 |
| **決策規則** | 在什麼情況下應該怎麼做？ | 「若 Bug 嚴重度為 Critical → 優先處理」 |
| **預算限制** | 最多花多少成本？ | 「總預算 1 單位，預留 50%」 |

**用途**：讓 Claude Code 理解你的需求

### 2️⃣ 告訴 Claude Code（5 分鐘）

```
"根據這份問題與預算定義書，
自動生成 Dynamic Workflow 並執行"
```

| 步驟 | Claude Code 做什麼 | 你不需要做什麼 |

## 📝 「問題與預算定義書」長什麼樣？

### 超簡潔版（1 頁）

```markdown
# [項目名稱] 問題與預算定義書

## 一、問題定義

**問題**：[一句話說清楚]

**輸入**：[什麼數據進來]

**輸出**：[什麼結果出去]

## 二、驗證標準

**成功指標**：
- 指標 1：[預期值]
- 指標 2：[預期值]

**驗收條件**：
- [ ] [條件 1]
- [ ] [條件 2]

## 三、執行策略

**限制條件**：
- [邊界 1]
- [邊界 2]

**決策規則**：
- 若 [條件 A] → [怎麼做]
- 若 [條件 B] → [怎麼做]

## 四、預算

**總預算**：[X] 單位
**預留率**：[Y]%（建議 ≥ 50%）

**成本監控**：
- 若成本達到 80% → [警告]
- 若成本達到 100% → [停止]
```

### 實際例子

```markdown
# 新世界 HR 系統 Phase 1 - 問題與預算定義書

## 一、問題定義

**問題**：評估員工請假申請是否符合公司政策和法律要求

**輸入**：員工提交的請假申請表（申請人、天數、原因、部門等）

**輸出**：審批決策（APPROVED / REJECTED / ESCALATED）+ 原因說明

## 二、驗證標準

**成功指標**：
- 政策檢查準確率 ≥ 90%
- 法律合規檢查準確率 ≥ 90%
- 衝突檢測準確率 ≥ 95%

**驗收條件**：
- [ ] 能識別所有政策違規
- [ ] 能識別所有法律不合規
- [ ] 能檢測政策和法律的衝突
- [ ] 能給出清晰的理由說明

## 三、執行策略

**限制條件**：
- 不能修改公司政策文件
- 不能修改法律要求
- 衝突情況必須升級給人工（不能自動決策）

**決策規則**：
- 若政策檢查 PASS 且法律檢查 PASS → APPROVED
- 若政策檢查 FAIL 或法律檢查 FAIL → REJECTED
- 若政策與法律衝突 → ESCALATED（升級給 HR VP）

## 四、預算

**總預算**：0.5 單位
**預留率**：50%（預期成本 0.25，預留 0.25）

**成本監控**：
- 若成本達到 0.4 單位 → 進入節省模式
- 若成本達到 0.5 單位 → 返回已完成的結果
```

## 💡 5 條黃金規則

### ✅ 要做

1. **清晰定義問題** — 不要含糊，說清楚「要解決什麼」
2. **具體的成功指標** — 用數字定義，例如「≥ 80%」而不是「要好」
3. **明確的決策規則** — 說出「在什麼情況下應該怎麼做」
4. **充足的預算預留** — 預留 50% 以上作為應急
5. **信任 Claude Code** — 不要預先設計 Workflow，讓它自動決定

### ❌ 不要做

1. **預先設計 Agent 數量** — 「需要 3 個 Agent」❌，改說「需要多個維度的檢查」✅
2. **預先規劃 Stage 順序** — 「Stage 1 → Stage 2」❌，改說「先 X 再 Y」✅
3. **指定執行模式** — 「用 Pipeline 模式」❌，改說「目標是什麼」✅
4. **預估具體成本** — 「0.05 + 0.2 + 0.15 = 0.4」❌，改說「預期 0.3-0.5」✅
5. **過度詳細** — 文檔應該 1-2 頁，不要超過 5 頁

## ❓ 常見問題

### Q1：我應該預先決定用幾個 Agent 嗎？

**A**：不應該。只說「需要檢查 X 個維度」，Claude Code 會自動決定用多少 Agent。

### Q2：如果任務中途失敗怎麼辦？

**A**：在「決策規則」中定義「如果失敗應該怎麼辦」：
- 重試？
- 使用降級方案？
- 升級給人工？

Claude Code 會按你的規則自動處理。

### Q3：怎樣預測成本？

**A**：根據輸入規模和複雜度做粗略估計，預留 50% 以上作為緩衝。Claude Code 會實時監控並調整。

### Q4：如果我改變了需求怎麼辦？

**A**：只需要更新「問題與預算定義書」，不需要重新設計整個 Workflow。Claude Code 會根據新的定義重新生成。

### Q5：怎樣確保質量？

**A**：在「驗收條件」中清晰地列出質量要求。Claude Code 會按照這些條件驗證結果。
