## 📋 定義書檢查清單

在提交之前，確保你的定義書包含：

### 一、問題定義 ✅
- [ ] 問題陳述清晰（一句話）
- [ ] 輸入明確（什麼數據進來）
- [ ] 輸出明確（什麼結果出去）
- [ ] 背景和約束已說明

### 二、驗證標準 ✅
- [ ] 成功指標具體（都是數字，可衡量）
- [ ] 驗收條件完整（可驗證）
- [ ] 失敗標準明確（什麼時候停止）

### 三、執行策略 ✅
- [ ] 執行思路清晰（不涉及 Stage / Agent 設計）
- [ ] 限制條件明確（邊界是什麼）
- [ ] 決策規則完整（若...則...邏輯）
- [ ] 降級和升級條件明確

### 四、預算分配 ✅
- [ ] 總預算明確
- [ ] 預留率 ≥ 50%
- [ ] 成本監控策略清晰

## 💡 常見誤區

### ❌ 誤區 1：把定義書寫成「設計書」

```
❌ 「需要 5 個 Stage，Stage 1 用 Haiku...」
✅ 「需要評估申請，檢查多個維度」

Claude Code 負責設計 Stage，你只負責定義問題
```

### ❌ 誤區 2：成功指標太模糊

```
❌ 「Bug 發現要好，測試要充分」
✅ 「Bug 發現率 ≥ 80%，測試 ≥ 20 個」

要用數字定義，這樣 Claude Code 才能自動驗證
```

### ❌ 誤區 3：決策規則不明確

```
❌ 「若有問題就處理」
✅ 「若 Bug 嚴重度為 Critical → 優先處理」

要清晰具體，不要讓 Claude Code 猜測
```

### ❌ 誤區 4：預算預留不足

```
❌ 「預定 0.5，預留 0.05（10%）」→ 容易超支
✅ 「預定 0.5，預留 0.25（50%）」 → 安全

預留 ≥ 50% 才能應對變化
```

## ✨ 核心要點

**你需要記住的三件事**：

1. **定義問題，不設計方案**
   - 你定義「要解決什麼」
   - Claude Code 決定「怎麼解決」

2. **明確決策規則，不預測代碼**
   - 你定義「若...則...」的邏輯
   - Claude Code 實現「具體怎麼判斷」

3. **給予充足預算，不預估成本**
   - 你給定預算上限和預留率（≥ 50%）
   - Claude Code 實時監控並自動優化
