# Dynamic Workflows in Claude Code

## 📋 完整定義

**Dynamic Workflows** 是 Claude Code v2.1+ 引入的**多代理協作系統**，允許一個 Lead Agent 在執行任務時動態生成、調度和協調多個 Sub-agents。

### 一句話總結
> 把蜂群 AI 用動態戰術編排，讓代理自動化並互相協調，即時適應任務變化。

---

## 🔧 技術機制

### 基本架構
```
Lead Agent（主指揮）
    ↓
動態召喚 Sub-agents（子任務執行者）
    ↓
Sub-agents 完成任務並回報
    ↓
Lead Agent 根據結果調整下一步
```

---

## 🌊 動態的三個層次

### 1️⃣ 數量動態
需要幾個 Sub-agent，執行中才決定。任務簡單用兩個，任務複雜再召喚更多。

### 2️⃣ 方法動態
用什麼工具、走什麼路徑，看中間結果再定。不是開始前就寫死「一定用這個 API」。

### 3️⃣ 結構動態
甚至連誰指揮誰都可以變。某個 Sub-agent 回傳的結果，可能讓 Lead Agent 決定重組整個分工。

**核心原則**：
> 任務開始時只有目標，其餘全部由執行現實決定。

---

## 💡 與傳統方式的對比

| 維度 | 靜態（Skill 時代） | 動態（Workflow 時代） |
|------|-------------------|---------------------|
| **流程** | A → B → C（寫死） | Lead 看情況決定走 A/B/D |
| **分支** | 事先窮舉所有可能 | 執行中動態生成 |
| **失敗處理** | 報錯中斷 | 召喚新 agent 重試 |
| **複雜度適應** | 固定資源 | 任務複雜就加更多 agent |
| **決策邏輯** | 現實服從計畫 | **計畫服從現實** |

### 本質差異
- **傳統程式**：所有分支事先窮舉
- **Dynamic Workflows**：分支在執行中生成

---

## 🎯 核心特徵

✅ **蜂群式並行工作** - 多個 Sub-agent 同時執行不同任務
✅ **層次化指揮結構** - Lead Agent 統籌全局，Sub-agents 執行細節
✅ **自主協調與溝通** - Agents 之間可以互相傳遞信息
✅ **即時適應任務變化** - 根據執行結果動態調整策略

---

## 📍 實際例子

### 任務：「分析這個專案並修復所有 bug」

**傳統方式**：
1. 掃描代碼
2. 找到 bug
3. 修復 bug
4. 結束

**Dynamic Workflows**：
1. Lead Agent 啟動，分析任務複雜度
2. 召喚 3 個 Sub-agents 並行掃描不同模組
3. 發現 bug 比預期多 → 再召喚 2 個 Sub-agents 協助修復
4. 其中一個修復失敗 → Lead Agent 派另一個 agent 用不同方法重試
5. 最後一個 agent 負責驗證所有修復
6. Lead Agent 整合結果並報告

**用戶**：動態之意是什麼

**清晨6:25**
動態的意思是：編排計畫不是事先寫死的，而是執行中途會自我調整。

具體來說：

**靜態（Skill 時代）**
流程 A → B → C，寫死了，不管發生什麼都照跑。

**動態（WF 時代）**
Lead Agent 看到 B 回傳的結果，判斷「不對，要改跑 D」，或是「B 失敗了，派另一個 Sub-agent 重試」，或是「任務比預期複雜，再召喚兩個 agent 來幫」。

本質就是：計畫服從現實，而不是現實服從計畫。

這也是為什麼叫「動態」——指揮結構本身是活的，會根據中間狀態重新決策。
