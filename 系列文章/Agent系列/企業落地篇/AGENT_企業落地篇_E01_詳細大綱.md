#### 陷阱 1：技術迷戀症（550 字）

---

##### 3.1.1 陷阱描述（感性類比）100 字

**症狀**：
追求最新、最強的模型，忽略業務價值

**類比（日常經驗）**：
```markdown
這就像買車，你要的是「通勤工具」，
銷售員卻說服你買「超級跑車」。

結果：
- 車很酷（技術很先進）
- 油很貴（成本爆炸）
- 不實用（業務用不上）

最後你還是需要一輛「實用的通勤車」。
```

**為什麼這個類比有效？**
- ✅ 買車是讀者熟悉的場景
- ✅ 核心邏輯準確（過度投資 vs 剛好夠用）
- ✅ 激起共鳴（「我也被銷售員騙過」）

---

##### 3.1.2 真實案例（理性對比）200 字

**案例背景**：
- 公司：某 SaaS 企業（200 人）
- 目標：客服 FAQ 自動回覆
- 技術團隊決定用 GPT-4（「要用就用最好的」）

**過程對比表**：

| 時間線 | GPT-4 方案 | GPT-3.5 方案（正確） |
|--------|-----------|-------------------|
| **Month 1** | 研究 GPT-4 參數設定 | 快速 POC，2 週上線 |
| **Month 2** | 調試 prompt，準確率 85%→92% | 驗證業務價值，收集反饋 |
| **Month 3** | 優化速度，3秒→1.5秒 | 橫向擴散到其他部門 |
| **Month 4** | CFO 叫停（成本 $3,500/月） | 老闆滿意（成本 $500/月） |
| **準確率** | 92% | 87% |
| **成本** | $3,500/月（超預算 7 倍） | $500/月 ✅ |
| **ROI** | 114% | 800% ✅ |
| **結果** | ❌ 專案中止 | ✅ 成功導入 |

**教訓金句**：
> 技術團隊追求「最好」，老闆追求「夠用 + 划算」。

---

##### 3.1.3 痛點深掘（三層為什麼）100 字

**讀者問：為什麼會陷入技術迷戀症？**

**第 1 層：表面原因**
```
因為技術人員想用最先進的技術
→ 讀者：「嗯，聽起來對」
```

**第 2 層：機制原因**
```
因為缺乏「業務目標 → 成本上限 → 技術選型」的框架，
技術團隊習慣從「技術」出發，而不是從「業務」倒推
→ 讀者：「哦！原來是流程問題」
```

**第 3 層：哲學原因**
```
這反映了一個深層的轉變：
從「技術驅動」轉向「價值驅動」。
企業 AI 的目標不是展示技術，而是解決問題、創造價值。
→ 讀者：「這不只是技術問題，是思維模式問題」
```

---

##### 3.1.4 正確做法（工程細節）100 字

**決策框架**：

```
Step 1：定義業務目標
  例如：客服 FAQ 自動回覆率 > 60%

Step 2：設定成本上限
  例如：每月 AI 成本 < $1,000

Step 3：選擇最簡單的方案驗證
  例如：先用 GPT-3.5 做 POC

Step 4：不夠好再升級
  如果準確率 < 60%，再考慮 GPT-4

結果：業務達標 + 成本可控 = ROI 最大化
```

---

##### 3.1.5 金句總結（心靈雞湯）50 字

> **企業 AI 的目標不是「技術最先進」，而是「ROI 最高」。**
>
> 用 GPT-3.5 達到 85% 準確率，花 $500，ROI 是 800%。
> 用 GPT-4 達到 92% 準確率，花 $3,500，ROI 是 114%。
>
> **你選哪個？**
