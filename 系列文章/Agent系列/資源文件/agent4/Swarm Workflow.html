智慧請假審批 流程編排
a swarm of agents, working in concert.

一份請假單在系統內的旅程：四個階段、六個 agent、一條人工兜底路徑。 順序執行解析資料、並行對抗驗證合規、累積上下文生成決策、最後並行送達通知與歸檔。

Sequential / 序列
Parallel / 並行
Cumulative / 累積上下文
Fan-out / 通知扇出
HITL / 人工介入
Stage 01
資料整理 · DataCollection
執行模式 SEQUENTIAL

解析原始請假表單，將非結構化文字標準化為下游 agent 可消費的 JSON 物件。

FormParserAgent 提取姓名、請假天數、休假類型與請假事由
LLM · Extract
↓ 結構化 JSON 資料 / structured payload
Stage 02
合規校驗 · PolicyValidation
執行模式 PARALLEL · ADVERSARIAL

兩個 agent 獨立校驗不同層級的合規性，比對結果進行對抗驗證 — 一致即放行，意見不一則升級。

CompanyPolicyAgent 校驗公司內部規章：特休天數是否超出該員工剩餘額度
Rules · RAG
LegalComplianceAgent 校驗勞基法：生理假扣薪規定、事假連續天數限制
Rules · Statute
HITL Escalation
人工審查 / override

當兩個 policy agent 給出衝突判定時，請求由 HR 主管介入裁決，解決規則邊界、補上系統未覆蓋的判例。

OWNER · HR Lead SLA · 4h
✓ 一致無衝突 · proceed
⤴ 意見衝突 · escalate to HITL
Stage 03
審批決策 · ApprovalReasoning
執行模式 CUMULATIVE

在事件日誌中累積先前所有階段的狀態，整合上下文後生成最終的審批建議與證據包。

HRReasonerAgent 評估部門當期請假人數、員工假期餘額、過往出勤紀錄
Reason · Cumulative
↓ 審批建議 & 決策包 / decision bundle
Stage 04
通知與歸檔 · Notification
執行模式 PARALLEL · FAN-OUT

並行送出主管審核信，同時將完整事件日誌寫入歸檔表，兩條路徑互不阻塞。

EmailNotificationAgent 發送主管審核信，附上決策包與一鍵核可連結
Action · Email
GoogleSheetLoggerAgent 寫入 Sheet 總控表，保留完整審計軌跡
Action · Log
