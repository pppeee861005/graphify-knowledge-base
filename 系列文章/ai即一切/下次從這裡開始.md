**最後更新日期**：2026-08-09

## 今日學習主題

釐清 **Codex 桌面版、Codex CLI 與 Computer Use** 之間的能力邊界，避免在第六篇〈當 AI 開始替你操作整台電腦〉中，把外接能力誤寫成 Codex CLI 的原生功能。

## 核心觀念

### 1. 原生 Computer Use 目前屬於桌面版體驗

OpenAI 官方文件將 Computer Use 定義為桌面版中的插件能力。啟用後，AI 可以觀看圖形介面、移動滑鼠、點擊、輸入文字並操作 Windows 或 macOS 應用程式。

官方文件：<https://learn.chatgpt.com/docs/computer-use>

### 2. Codex CLI 本身沒有內建 Computer Use 指令

本機實際檢查的版本為 `codex-cli 0.147.0`。CLI 說明中有：

- `mcp`：連接外部 MCP servers。
- `plugin`：管理 Codex plugins。
- shell 與檔案操作能力。
- `app`：啟動 Codex 桌面版。

但沒有原生的 `computer-use` CLI 指令。

官方文件：<https://learn.chatgpt.com/docs/codex/cli>

### 3. CLI 可以擴充出類似能力，但必須精確署名

Codex CLI 可以透過外接的 MCP server、插件、瀏覽器自動化或作業系統自動化工具取得 GUI 操作能力。這時應寫成：

> Codex CLI 透過外接的 Computer Use／MCP 工具操作應用程式。

不能直接寫成：

> Codex CLI 原生就能看見畫面並操作整台電腦。

### 4. 系列文章的思想主張不必改變

「軟體退到幕後，人類只留下意圖、授權與結果」仍然成立。需要調整的是技術實現的署名與證據，而不是文章的哲學方向。

## 實際觀察、理論推論與待驗證問題

### 實際觀察

- 第六篇目前描述 AI 觀看 Tinkercad 畫面、移動滑鼠、輸入數值並完成房屋模型。
- 第六篇尚未明確寫出實際使用的是 Codex 桌面版，還是 Codex CLI 加外部工具。
- 草稿的發布前證據清單仍待補入原始指令、最終畫面、錄影、工具版本、執行環境、耗時與人工介入次數。

### 理論推論

- Computer Use 的重要性不只是「AI 會點滑鼠」，而是 Agent 能跨越原本為人類設計的多套軟體介面，逐步把 App 降為背後可調用的工具。
- 行動能力越強，越需要明確授權、高風險操作確認、可中止機制與完整日誌。

### 待驗證問題

1. 真實的 Tinkercad 案例究竟使用哪一種執行環境？
   - Codex 桌面版的 Computer Use plugin；或
   - Codex CLI 加外部 MCP／自動化工具。
2. 操作過程是否有完整截圖、錄影與提示詞可供公開？

4. 是否遇到登入、彈窗、介面辨識錯誤或操作失敗？如何恢復？
