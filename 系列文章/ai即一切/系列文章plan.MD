# 《AI 即一切》Substack 系列文章計劃

**系列名稱**：AI 即一切  
**系列副題**：當軟體退到幕後，人類只留下意圖與結果  
**預計篇數**：8 篇  
**建議頻率**：每週 2 篇，連載 4 週  
**原始素材**：[草稿.md](草稿.md)

---

## 一、系列核心定位

### 核心命題

AI 帶來的革命，不只是讓軟體變得更聰明。

它正在改變人類與電腦之間最基本的關係：

**過去，人必須學會操作工具；未來，人只需表達意圖，AI 負責調度工具並交付結果。**

軟體不會消失，但會逐漸離開人類的視線。App、網站、介面、平台與硬體，將從使用者必須親自進入的「產品」，退成 AI 背後隨時可以調用的「基礎設施」。

### 系列對讀者的承諾

這個系列不只談未來想像，也提供可驗證的真實作品與完整流程：

- AI 如何直接生成可編輯的 DXF 製圖初稿。
- Codex 如何進入 Godot，建立可運行的遊戲原型。
- computer use 如何讓 AI 操作既有軟體、跨越不同工具完成任務。
- 一次性介面、Agent 對 Agent、Agent 錢包與可程式化授權，將如何改變產品與市場。

### 目標讀者

- 正在思考 AI 產品方向的創業者與產品經理。
- 想理解 Agent、computer use 與生成式介面的技術讀者。
- 關注軟體產業、商業模式與人機關係變化的創作者。
- 不寫程式，但想知道 AI 將如何改變日常工作與生活的人。

## 二、為什麼改成八篇連載

原始草稿同時包含哲學命題、商業公式、介面革命、實證案例、軍事比喻與 Agent 經濟。每個主題都足以單獨成篇，集中在一篇文章裡會產生三個問題：

1. 讀者剛理解一個概念，就被帶往下一個世界。
2. 真實案例只能快速點名，無法建立可信度。
3. 最有力量的句子彼此競爭，反而削弱記憶點。

拆分後，每篇只回答一個核心問題，整季則形成三幕：

| 階段 | 篇數 | 讀者獲得的體驗 |
|---|---:|---|
| 第一幕：世界觀 | 1–3 | 從「我需要 App」走向「我真正需要的是結果」 |
| 第二幕：真實證明 | 4–6 | 親眼看見 AI 生成檔案、操作工具、接管電腦流程 |
| 第三幕：產業革命 | 7–8 | 理解 App 為何可能被繞過，以及 Agent 經濟如何出現 |

## 三、Substack 篇幅與閱讀規格

### 建議篇幅

- **思想／商業篇**：1,800–2,600 個中文字，約 6–8 分鐘。
- **真實實證篇**：2,500–3,500 個中文字，約 8–10 分鐘。
- **單篇上限**：原則上不超過 3,500 個中文字；超過時優先刪除旁支，必要時再拆篇。

### 單篇標準結構

1. **場景鉤子**：150–250 字，先讓讀者看見自己的問題。
2. **核心命題**：300–500 字，只提出一個反直覺觀點。
3. **機制拆解**：600–1,000 字，解釋為什麼會發生。
4. **案例或證據**：500–1,000 字，以作品、流程或計算建立可信度。
5. **限制與責任**：200–400 字，說清楚 AI 不能取代什麼。
6. **哲學收束與下集鉤子**：150–300 字，留下一個未完成的問題。

### 閱讀體驗規則

- 每段以 1–3 句為主，避免在手機上形成文字牆。
- 每 300–500 字安排一個小標題、粗體命題或視覺停頓。
- 思想篇配置 1 張封面與 1–2 張內文圖。
- 實證篇配置 1 張封面、3–6 張流程截圖，以及必要的 GIF 或短影片。
- 一篇只保留一個主要 CTA：訂閱、閱讀下一篇或查看真實作品，三者擇一。
- 每篇開頭標示「《AI 即一切》#X／8」，結尾提供上一集、系列目錄與下一集導航。

## 五、逐篇詳細規劃

## #1｜你真正需要的，從來都不是 App

**副題**：當 AI 開始理解意圖，產品的邊界正在消失

### 本篇只回答一個問題

人類真正需要的是軟體，還是軟體替我們完成的結果？

### 開場鉤子

沿用記帳場景：比較 App、註冊帳號、學習介面、設定分類，做完所有事情後，人才終於得到真正想知道的答案——這個月究竟花了多少錢。

### 內容骨架

1. 我們真正需要的從來不是記帳 App，而是把帳算清楚。
2. 過去的鏈條：需求 → 產品 → 工具 → 操作 → 結果。
3. AI 時代的鏈條：需求 → AI → 結果。
4. 軟體分類不是自然定律，而是上一個運算時代留下的行政區。
5. 定義「AI 即一切」：不是 AI 取代所有產品，而是所有產品都能被 AI 調度。
6. 公布八篇系列地圖，但不在本篇展開任何技術案例。

### 本篇不要放入

- DXF、Godot、computer use 的詳細流程。
- 3D 列印、自動駕駛與 Agent 錢包。
- 武功與火力系統的完整比喻。

### 結尾鉤子

> 如果人類真正購買的不是軟體，那麼下一代最重要的商品，究竟是什麼？

引向 #2〈結果，才是下一代真正的商品〉。

---

## #2｜結果，才是下一代真正的商品

**副題**：從功能競爭走向 Outcome 經濟

### 本篇只回答一個問題

當產品邊界消失，下一代公司究竟在出售什麼？

### 開場鉤子

農夫不需要智慧灌溉 App，他需要蔬菜健康生長並且少用一點水。老闆不需要會計 SaaS，他需要帳目正確、稅務安全，而且知道公司有沒有賺錢。

### 內容骨架

1. 消費者真正購買的是 Outcome，而不是 Software。
2. 三組生活案例：農場、會計與旅行。
3. 提出公式：**消費價值 ≈ 結果品質 ÷ 取得結果的總成本**。
4. 總成本包括金錢、時間、學習、等待、風險與注意力。
5. 以 3D 列印收納架說明「意圖如何越過螢幕，在現實中獲得形狀」。
6. 限制：AI 可以移除操作成本，但工程驗證、現場責任與結果驗收仍需人類承擔。

### 建議視覺

- 「需求 → 多層工具 → 結果」與「需求 → AI → 結果」對照圖。
- 3D 收納架從照片、模型到實物的流程意象。

### 結尾鉤子

> 當結果成為商品，介面還需要固定存在嗎？

引向 #3〈當介面成為一次性消耗品〉。

## #3｜當介面成為一次性消耗品

**副題**：未來的 UI，可能只活一分鐘

### 本篇只回答一個問題

如果 AI 能隨任務生成介面，產品還能由固定 UI 定義嗎？

### 開場鉤子

老師為了解釋一段複雜推理，讓 AI 即時生成一個動畫網頁。它在一秒內出現，幾乎沒有成本，完成一次教學後便可以被丟棄。

### 內容骨架

1. 固定 UI 為何是過去軟體成本的產物。
2. 記帳、農場與投資任務，各自生成不同的短命介面。
3. 一次性動畫網頁的真實案例與連結。
4. 介面不只是畫面，也包括手機、PC、車載系統、眼鏡、音箱、網站與平台。
5. 不同硬體外殼，逐漸連接同一個理解使用者的 AI。
6. 自動駕駛案例：乘客購買的不是導航功能，而是可靠抵達。
7. 必須保留的界線：**操作可以消失，責任不能消失。**
8. 未來 UI 從操作層轉為授權、風險、驗證與接管的治理層。

### 發布前所需素材

- 一次性動畫網頁的永久網址。
- 生成時間、使用工具與成本紀錄。
- 1 張動畫截圖或 5–10 秒 GIF。

### 結尾鉤子

> 如果介面可以被臨時生成，那麼專業檔案是否也能直接由意圖產生？

引向 #4 DXF 實證篇。

## #4｜我沒有打開 CAD，AI 卻交付了一份 DXF

**副題**：從自然語言到可編輯製圖初稿的真實紀錄

### 本篇只回答一個問題

AI 能否跳過專業軟體的操作過程，直接交付可用的工作成果？

### 開場鉤子

從實際需求開始，而不是先介紹模型功能：當時需要什麼圖、為何需要、傳統上必須經過哪些人與軟體。

### 內容骨架

1. 原始任務與驗收標準。
2. 第一次交給 AI 的自然語言指令。
3. AI 如何產生 DXF，以及檔案如何被打開與檢查。
4. 多輪修改：人類改的是意圖，不是逐點操作 CAD。
5. 傳統流程與 AI 流程的時間、步驟、成本對照。
6. 哪些部分成功，哪些部分仍然失敗或需要修正。
7. 責任聲明：這是可編輯製圖初稿，正式施工前仍須現場專業人員審核。
8. 深層意義：人類不再學習軟體語法，而是定義成果與驗收條件。

### 必備證據

- 原始提示詞與至少一次修改紀錄。
- DXF 在專業軟體中開啟的截圖。
- 可公開下載的範例檔案或精簡版本。
- 人工審核後發現的限制。

### 結尾鉤子

> 生成一份檔案只是第一步。如果 AI 可以自己走進創作工具，它還能完成多少事情？

引向 #5 Godot 實證篇。

---

## #5｜Codex 走進 Godot：當一句遊戲想法變成可運行原型

**副題**：AI 不只寫程式，它開始親自操作創作工具

### 本篇只回答一個問題

當 AI 能直接操作遊戲引擎，人類的角色會從製作者變成什麼？

### 開場鉤子

先展示遊戲可運行的最終畫面，再回到最初只有一句自然語言想法的時刻。

### 內容骨架

1. 最初的遊戲概念與完成標準。
2. Codex 如何理解場景、角色、規則與操作方式。
3. 它如何建立 Godot 專案、產生資源、修改程式與測試。
4. 遇到的錯誤、修復過程與人類介入點。
5. 從「生成程式碼」到「在創作環境裡完成作品」的差別。
6. 人類沒有消失：真正重要的工作轉為方向、品味、驗收與取捨。
7. 哪些成果可重現，哪些仍依賴特定環境。

### 必備證據

- 遊戲畫面 GIF 或短影片。
- Godot 專案樹與關鍵檔案截圖。
- 重要操作紀錄或時間線。
- 可公開的專案檔或 GitHub 連結。

### 結尾鉤子

> Godot 仍然只是一套工具。當 AI 不再被限制在單一工具裡，事情會變成什麼樣子？

引向 #6 computer use 實證篇。

## #6｜當 AI 開始替你操作整台電腦

**副題**：Computer use 如何讓 App 退成 Agent 背後的工具

### 本篇只回答一個問題

當 AI 能看見畫面、點擊、輸入、切換工具並處理錯誤，App 還是不是人類工作的基本單位？

### 開場鉤子

選擇一個必須跨越兩到三套軟體的真實任務，展示使用者只交代目標，AI 自行完成中間流程。

### 內容骨架

1. 任務原本需要人類完成哪些操作。
2. AI 如何觀察螢幕、選擇工具並執行步驟。
3. 它如何在錯誤、登入、彈窗或格式不一致時恢復。
4. computer use 與傳統腳本、自動化巨集的差異。
5. 真正的突破不是 AI 會點滑鼠，而是它開始理解「為什麼要點」。
6. 權限、安全、隱私、日誌與可中止機制。
7. App 不會消失，但可能不再直接面對人類。

### 必備證據

- 完整任務前後對照。
- 關鍵步驟截圖或螢幕錄影。
- 失敗與恢復案例，不能只展示成功片段。
- 權限設定及人工確認位置。

### 結尾鉤子

> 當所有軟體都能被 AI 調度，下一場競爭還會是誰的 App 功能更多嗎？

引向 #7 破壞式革命篇。

## #7｜武功再高，也敵不過一套系統

**副題**：為什麼最強的 App，也可能成為一座被道路繞過的城市

### 本篇只回答一個問題

既有產品為什麼可能在功能仍然優秀時，突然失去原本的位置？

### 開場鉤子

冷兵器時代，人們持續追求更鋒利的刀、更厚的盔甲與更高的武藝；火力革命卻沒有發明一套更強的武功，而是改變了戰爭的基本單位。

### 內容骨架

1. 個人武藝與偵察、通訊、計算、後勤、火力系統的差異。
2. 典範轉移不是強化舊單位，而是讓舊單位不再決定上限。
3. 今天的 App 是否就是那套登峰造極的武功？
4. 科技公司仍在優化 UI、功能、停留時間與封閉生態。
5. 城牆依然完整，但新的道路已經不再經過它。
6. 破壞式革命不必摧毀舊產品，只需讓使用者意圖繞過產品入口。
7. 新護城河：最接近意圖、最能調度資源、最少消耗注意力。

### 建議視覺

- 前景是精銳冷兵器戰士，背景是偵察、通訊與火力組成的系統。
- 一座由 App 介面構成的華麗城市，新的光路從旁繞過。

### 結尾鉤子

> 如果人類不再親自走進平台，那麼未來的交易，會由誰進場？

引向 #8 Agent 經濟篇。

## #8｜當 Agent 擁有錢包：下一代市場裡，人類甚至不必進場

**副題**：平台不一定消失，它只是退成 Agent 背後的基礎設施

### 本篇只回答一個問題

當 Agent 能彼此發現、協商、支付與交付，市場的基本單位會變成什麼？

### 開場鉤子

一個人想出售二手器材，另一個人剛好需要它。兩人沒有搜尋同一個平台、沒有互相聊天，甚至不知道彼此的存在；雙方 Agent 已經找到了可能的交易。

### 內容骨架

1. Agent 對 Agent：發現需求、比較條件、議價與安排交付。
2. 人類仍設定價格、額度、風險與允許自動執行的範圍。
3. 超出授權時，交易必須回到人類手中確認。
4. Agent 專屬錢包：行動能力與可程式化授權。
5. 錢包不等於無限制自主；需要護欄、審計、撤銷與責任歸屬。
6. 平台不一定消失，只是從人類造訪的市場退成 Agent 調用的基礎設施。
7. 下一代公司不一定擁有最大入口，而是最可靠地完成意圖。
8. 回到系列總命題：數位世界的基本單位，從產品轉為意圖與結果。

### 必備資料

- Agent 對 Agent 流程圖。
- Agent 錢包的官方資料與安全護欄說明。
- 「預先授權」與「必須人工確認」的交易對照。
- 清楚標記哪些能力已經存在，哪些仍是合理推演。

### 系列結尾

> 軟體不會消失。消失的，是人類必須先理解軟體，才能改變世界的那段距離。
>
> 文明真正轉彎的時刻，從來不是工具變得更強，而是人類突然不再需要，用舊時代的方式使用工具。

### 最終 CTA

邀請讀者回覆：在他的工作或生活裡，哪一套「必須親自操作的軟體」最應該先退到幕後？讀者回答可成為下一季案例來源。

## 八、Substack 串聯設計

### 每篇開頭固定格式

```markdown
《AI 即一切》#X／8

這是一個關於軟體如何退到幕後、人類如何只留下意圖與結果的系列。
```

### 每篇結尾固定格式

```markdown
---

### 《AI 即一切》系列導航

← 上一篇：〔標題／連結〕  
⌂ 系列目錄：〔連結〕  
→ 下一篇：〔標題／預告〕
```

### 交叉引流原則

- #1 公布八篇地圖，讓讀者知道訂閱後會得到什麼。
- #2、#3 只預告下一個問題，不一次列出所有文章。
- #4–#6 在開頭連回系列世界觀，在結尾串成「檔案 → 工具 → 整台電腦」三部曲。
- #7 回鏈 #4–#6，證明破壞式革命不是純推論。
- #8 回鏈 #3 的決定權與 #7 的道路改道，形成閉環。

## 十、發布前品質門檻

每篇發布前必須通過以下檢查：

- [ ] 只回答一個核心問題。
- [ ] 開場 250 字內出現具體人物、需求或衝突。
- [ ] 至少有一句可以獨立被引用的核心命題。
- [ ] 現實能力與未來推演有清楚分界。
- [ ] 所有產品能力、數據與外部案例都有來源或作品證據。
- [ ] 高風險成果標明人工審核、授權與責任邊界。
- [ ] 沒有網址占位符、作者筆記或尚未完成的提醒。
- [ ] 手機閱讀時沒有超長段落。
- [ ] 結尾只留下下一篇的一個問題。
- [ ] 上一篇、系列目錄與下一篇導航正確。
