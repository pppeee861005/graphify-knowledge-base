# 當 AI 開始替你操作整台電腦

## Computer use 如何讓 App 退成 Agent 背後的工具

瀏覽器裡開著 Tinkercad。

畫面中央是一塊空白的 3D 工作平面，旁邊排列著方塊、圓柱、屋頂等基本元件。

過去，如果我要建立一棟簡單房屋模型，得先理解如何拖曳物件、改變尺寸、對齊、旋轉、切換視角，再把不同形狀組合成牆壁、屋頂、門窗與空間。

但這一次，操作網頁版 Tinkercad 的不是我。

我把「建立一棟簡單房屋 3D 模型」的目標交給 AI，讓它直接面對那套原本為人類設計的介面。

它必須看見畫面、判斷下一步、移動滑鼠、輸入數值，然後觀察結果是否符合預期。

這就是 computer use 真正有意思的地方。

AI 不只知道 Tinkercad 是什麼。

它開始真的使用 Tinkercad。

### 過去，AI 被困在軟體門外

大型語言模型可以告訴你如何操作軟體。

它可以列出步驟、解釋功能，甚至替你寫一段自動化腳本。

但只要軟體沒有 API、沒有現成整合，或工作流程牽涉滑鼠、彈窗與視覺判斷，最後仍然需要人類親自接手。

AI 像一位站在你身後的顧問。

它知道答案，卻碰不到電腦。

Computer use 補上的，正是這雙手。

一個能操作電腦的 Agent，必須完成四個循環：

1. **看見**：辨識目前畫面、按鈕、欄位與任務狀態。
2. **判斷**：根據目標決定下一個動作，而不是死背固定座標。
3. **操作**：點擊、輸入、拖曳、切換視窗或開啟其他工具。
4. **驗收**：觀察操作後的結果，發現偏差，再調整下一步。

只會點擊，不是 Agent。

真正的關鍵是：它知道為什麼要點，也知道點完之後應該看見什麼。

---

### Computer use 與傳統自動化，有什麼不同？

傳統 RPA、巨集或腳本也能替人操作電腦。

但它們通常需要工程師事先定義每一條路徑：點哪個按鈕、輸入哪個欄位、遇到什麼畫面就走哪個分支。

介面位置改變、彈出意外視窗，或資料格式稍微不同，流程就可能中斷。

Computer use 的理想不是完全不寫規則。

而是讓 AI 在規則之外，理解畫面與任務意圖，對沒有被事先列出的情況做出調整。

傳統自動化像鐵軌。

它很快、穩定，但只能在鋪好的路線上行駛。

Computer use 更像一位剛開始學習開車的駕駛：速度可能還不夠快，也會看錯路標，但它能根據道路變化重新選擇方向。

兩者不一定互相取代。

成熟的系統更可能把它們組合在一起：固定、高頻、低變化的步驟交給程式；需要理解、例外處理與跨介面協調的部分交給 Agent。

---

### 真正的革命，不是 AI 會點滑鼠

如果 computer use 只被理解成「AI 幫我按按鈕」，我們會低估它。

一個真實工作很少只活在一套軟體裡。

需求可能從郵件進來，資料存在試算表，參考資訊要從瀏覽器搜尋，成果在專業工具裡製作，最後還要上傳到另一個平台並通知相關人員。

今天，人類是所有 App 之間的轉接頭。

我們複製、貼上、下載、上傳、重新命名、確認格式，再把上一套工具的結果搬到下一套工具。

當 Agent 能看見並操作整台電腦，這些原本必須由人類承擔的轉接工作，第一次可以被同一個執行者串起來。

使用者不必再說：

**「先打開 A，把資料貼到 B，再從 C 匯出檔案。」**

他可以直接說：

**「把這項工作完成，完成後讓我驗收。」**

App 沒有消失。

它們只是從人類每天必須造訪的目的地，退成 Agent 依任務調用的工具。

---

### 真實世界不會像展示影片那麼乾淨

Computer use 也有非常現實的限制。

介面可能更新，按鈕可能換位置，網路會延遲，登入可能要求多重驗證，畫面中的文字也可能被誤讀。

最危險的情況不是任務明顯失敗。

而是 AI 誤以為自己成功，實際上卻在錯誤欄位輸入資料、漏掉附件，或把結果上傳到不該出現的地方。

所以實證文章不能只剪出順利完成的最後十秒。

我們必須展示完整的工作紀錄：

- AI 看到了什麼？
- 它採取了哪些動作？
- 哪一步失敗？
- 它如何發現並恢復？
- 哪些動作需要人類確認？

> 【待補：本案例完整任務時間線，以及至少一次失敗與恢復過程】

能被審計，比看起來很聰明更重要。

---

### AI 可以使用電腦，但不能擁有無限權限

當 AI 只回答問題，最糟的結果可能是一段錯誤文字。

當 AI 可以操作電腦，它就可能寄出郵件、修改檔案、送出表單，甚至觸發付款。

行動能力越強，權限設計就越重要。

一套值得信任的 computer use 系統，至少需要：

1. 明確的任務範圍與可使用工具。
2. 高風險動作前的人工確認。
3. 完整、可回放的操作紀錄。
4. 隨時中止與撤銷的能力。
5. 失敗時不擴大損害的安全邊界。

AI 可以接管複雜度。

人類仍必須保留授權、驗收與責任。

這不是限制 Agent 的未來。

而是讓它有資格進入真實工作的前提。

---

### 當所有 App 都成為工具

從 DXF 到 Godot，再到 Tinkercad 與整台電腦，這三篇實證指向同一個方向：

AI 正從「告訴人怎麼做」，走向「自己進入工具，把事情完成」。

那麼，科技公司下一步還應該繼續問：如何讓自己的 App 擁有更多功能、讓使用者停留更久嗎？

還是應該開始問：如果未來的使用者根本不需要親自進入我的 App，我在新的價值鏈裡還剩下什麼？

下一篇，我們要離開操作現場，談一場更大的戰爭。

它不是誰擁有更漂亮的介面。

而是誰先發現：

**戰爭的基本單位，已經改變了。**
