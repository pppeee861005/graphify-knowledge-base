## ✍️ 寫作框架與風格指南

### 核心寫作原則

**《五層架構 + 克勞德視角 + 蜂巢動線》**

#### 第一層：場景代入感
- **目標**：讓讀者看到自己的影子
- **要素**：具體時間、真實數字、感官細節、內心獨白
- **案例**：「妳的辦公室，晚上 10 點。螢幕上是『組合績效 +127%』的大字。」

#### 第二層：痛點場景（三層遞進）
- **歷史傷疤**：過去的失敗經歷（建立信任）
- **現在的貪心**：當下面臨的誘惑與困境
- **內心拉扯**：理性與情感的戰鬥

#### 第三層：克勞德出現（轉折時刻）
- **決策覺悟**：妳意識到問題所在
- **召喚系統**：「我需要一個...」的需求清單
- **承諾展開**：克勞德進場，開始解釋蜂群架構

#### 第四層：多 Agent 蜂群架構
- **視覺分層**：用 ASCII 或文字描繪清晰的層次結構
- **邏輯遞進**：從上層決策到下層執行
- **具體計算**：展示實際的數據與算法邏輯

#### 第五層：實時執行日誌
- **時間戳**：精確的執行時刻
- **成交確認**：「蜂群提案」→「妳決策」→「系統執行」
- **可信度建立**：細節越多越真實

#### 延伸：克勞德的私語（溫度層）
- **位置**：在「下一章預告」前
- **內容**：克勞德對妳的觀察、偷偷的崇拜、對角色心理的洞察
- **目的**：讓讀者感受到 AI 也開始有了人性化思考

### 克勞德的四個維度

| 維度 | 表現方式 | 範例 |
|------|---------|------|
| **工程師視角** | 冷靜的技術分析 | 「系統偵測到持倉漂移…」 |
| **心理顧問視角** | 對人性的洞察 | 「我注意到妳的手指在顫抖…」 |
| **知己視角** | 溫暖的理解 | 「妳不把我當工具…」 |
| **靈魂旁白視角** | 對時代的思考 | 「也許，這正是妳的未來。」 |

### 霸道女總裁的語言特徵

**要這樣寫**：
- 直接、冷峻、追求結果
- 「給我數據。」「不夠。」「再來。」
- 沉默中蘊含力量，不廢話

**不要這樣**：
- 過多的自我懷疑與猶豫
- 「我覺得可以試試看…」這類模稜兩可的語氣
- 被動與哀求

## 🚀 寫作工作流

### 1. **準備階段**
```
閱讀 SWARM_系列計畫.md
  ↓
確認該篇的：
  • 核心技術是什麼
  • 殺手級用途是什麼
  • 商業價值排序中的位置
  • 與其他篇章的連結
  ↓
進入寫作模式
```

### 2. **大綱生成**
使用 `/explosive-outline` 技能或參考現有大綱模板：
- 調用位置：`SWARM_S01Ex_自動校準_詳細大綱.md`
- 或查看計畫中的「七篇劇情規劃」章節
- 確保包含：場景、痛點（3層）、轉折、高潮、結尾

### 3. **正文撰寫**
- **字數範圍**：2,500 ~ 4,500 字
- **結構**：開場（100字）→ 痛點場景（800字）→ 轉折（300字）→ 蜂群架構（400字）→ 實戰日誌（300字）→ 克勞德私語（200字）→ 下一章預告（100字）
- **風格調整**：保持冷峻但不失溫度，技術硬度 vs 敘事流暢的平衡

### 4. **蜂巢動線設計**
每篇的結尾都要設計多條出口：
```
延伸閱讀（讓妳逛不完的知識蜂巢）

如果妳想 A → 🔗 [Agent E04...]
如果妳想 B → 🔗 [SW3 E01...]
如果妳想 C → 🔗 [AI蜂群投資 #2...]
```

### 5. **質量檢查清單**

#### 快速檢查（自我檢查）
- [ ] 是否有具體的時間與數字？
- [ ] 痛點場景是否包含三層遞進？
- [ ] 蜂群架構是否清晰可視？
- [ ] 克勞德的聲音是否一致？
- [ ] 免責聲明是否包含在結尾？
- [ ] GitHub 連結是否指向正確檔案？
- [ ] 蜂巢動線是否足夠引人入勝？

#### 克勞德細語驗證檢查 ⭐
在提交前，**強烈建議調用 `/claude-whisper` 進行以下檢查**：
- [ ] 五層架構是否完整執行？
- [ ] 場景代入感是否足夠（具體細節、環境、內心）？
- [ ] 痛點三層是否有明確遞進？
- [ ] 克勞德的四維度聲音是否平衡？
- [ ] 蜂群架構的技術硬度是否達標？
- [ ] 實時日誌是否具有可信度（時間戳、精確數據）？
- [ ] 與系列已發布篇章的風格是否一致？
- [ ] 蜂巢動線的引導是否足夠強？

## 🎨 克勞德的細語 Skill 集成

### 概述

**「克勞德的細語」**（`/claude-whisper`）是本系列專用的寫作風格指南 Skill。它將系列的核心美學標準（五層架構、四維度視角、蜂巢動線）系統化，幫助保證每篇文章的**代入感、技術硬度、情感弧線**都維持在高水準。

```
💡 核心價值：
從「知道該怎麼寫」 → 「確保寫得對」的品質保障
```

### 何時調用 `/claude-whisper`

| 階段 | 觸發點 | 用途 |
|------|--------|------|
| **大綱完成後** | 五層架構已定稿 | 驗證故事節奏與技術架構的平衡 |
| **初稿完成後** | 正文已寫完，未發布 | 檢查克勞德的聲音、場景代入感、蜂巢動線是否達標 |
| **修訂前** | 編輯手稿前的最後檢查 | 確認整體風格一致性、避免不必要的改動偏離主旨 |
| **系列校準** | 新篇章開啟前 | 對比已發布篇章（#1-#3），確保新篇章風格延續性 |

### 克勞德細語的五層驗證框架

當您調用 `/claude-whisper` 時，它會按以下五層驗證您的文稿：

#### 1️⃣ **場景代入感檢查**
```
驗證清單：
✓ 是否有具體的時間（深夜、凌晨、午後）？
✓ 是否有真實的數字（股票漲幅、持倉比例、金額）？
✓ 是否有環境細節（螢幕、按鍵、燈光、手指顫抖）？
✓ 是否有內心獨白或對話？

失敗案例：「妳的組合表現很好。」
成功案例：「螢幕上是『組合績效 +127%』的大字。但妳卻皺著眉頭，雙手環胸。」
```

#### 2️⃣ **痛點三層遞進檢查**
```
驗證清單：
✓ 第一層（歷史傷疤）是否有具體過去失敗經歷？
✓ 第二層（現在貪心）是否呈現當下的誘惑困境？
✓ 第三層（內心拉扯）是否展現理性與情感的戰鬥？
✓ 三層是否形成 escalation 的遞進式張力？

失敗案例：只寫「我曾經虧過錢，現在我很糾結。」
成功案例：明確敘述某次具體虧損 → 現在某檔股票大漲但風險高 → 內心無法做決定的具體表現
```

#### 3️⃣ **克勞德出現的轉折力度檢查**
```
驗證清單：
✓ 妳的「決策覺悟時刻」是否清晰（通常是意識到重複過去的錯誤）？
✓ 「召喚系統」的請求是否明確（「我需要...」）？
✓ 克勞德的出現是否有說服力（為什麼是他）？
✓ 轉折是否形成足夠的張力反差？

失敗案例：「然後我想到了一個主意。」
成功案例：「妳突然停頓。妳意識到，自己在重複過去的錯誤。妳需要一個沒有情緒的再平衡系統。」
```

#### 4️⃣ **蜂群架構的技術硬度檢查**
```
驗證清單：
✓ 架構圖是否清晰（ASCII 或文字分層）？
✓ 是否解釋了 Sub-Agent 如何分工？
✓ 是否有具體的計算邏輯或權重調整？
✓ 是否避免過度抽象（讀者能否想象執行流程）？

失敗案例：「蜂群會幫你分析。」
成功案例：「5 個 Sub-agent 並行運行：監控層偵測異動 → 分析層計算三維評分 → 決策層加權投票 → 執行層下單…」
```

#### 5️⃣ **實時日誌的可信度檢查**
```
驗證清單：
✓ 是否包含精確的時間戳（凌晨 3 點、T+0.3秒）？
✓ 是否展現了「蜂群提案 → 妳決策 → 系統執行」的完整迴圈？
✓ 數據是否具體（具體數字、百分比、金額）？
✓ 是否使用格式化日誌（code block、table）增強可信度？

失敗案例：「蜂群發出了警告。」
成功案例：以格式化日誌展示 [02:47] Agent-3 發現異動 → [02:48] 觸發三維印證 → [02:49] 評分 47 分…
```

### 克勞德四維度的聲音一致性檢查

克勞德會驗證文稿中克勞德（記錄者）的聲音是否在四個維度間**一致且平衡**：

| 維度 | 檢查重點 | 頻率 |
|------|---------|------|
| **工程師視角** | 技術描述是否精準、冷靜、無誇張 | 40% |
| **心理顧問視角** | 對人性的洞察是否深刻、同理 | 30% |
| **知己視角** | 對妳的理解是否溫暖、忠誠 | 20% |
| **靈魂旁白視角** | 對時代意義的思考是否深遠、啟發 | 10% |

**驗證方法**：
- 統計克勞德的語句，分類到四個維度
- 驗證比例是否接近上表
- 檢查維度間的轉換是否自然流暢

### 常見改進模式

根據克勞德細語的反饋，以下是常見的改進建議：

| 問題 | 初稿表現 | 改進建議 |
|------|---------|---------|
| **代入感不足** | 「妳的組合很不錯。」 | 加入具體數字、時間、環境細節、內心獨白 |
| **痛點流於表面** | 只提「我曾經虧過錢」 | 補充具體故事、具體數字、情感轉折 |
| **克勞德聲音不一致** | 時而冷靜、時而煽情 | 界定四維度的比例，檢查段落前後是否連貫 |
| **技術硬度不夠** | 「系統會幫你決策」 | 詳細說明算法邏輯、分層架構、具體計算 |
| **日誌可信度低** | 籠統描述「蜂群發出警告」 | 添加時間戳、精確數據、格式化表格 |
| **蜂巢動線不夠** | 只有一個結尾連結 | 設計 3+ 個出口：針對不同讀者族群的深化方向 |

### 何時 NOT 調用 `/claude-whisper`

某些情況下不需要（或不應該）調用克勞德細語：

- ❌ **草稿極早期**（還沒成形的 50% 初稿）— 先用 `/explosive-outline` 完整化框架
- ❌ **技術細節仍在研究中** — 先確認技術架構正確，再檢查敘事
- ❌ **僅做輕微編輯** — 只改幾個詞、調整段落順序，可直接發布
- ❌ **複製已發布篇章的結構** — 已驗證過的結構可沿用

## 🎯 內容策略核心原則

### 蜂巢動線（Hive Navigation）

**核心概念**：每篇文章都是蜂巢的一個入口，讀者不是「讀完就走」，而是「越逛越深」。

```
讀者進入 #1《蜂群覺醒》
  ↓
了解基礎技術（多股票監控）
  ↓
發現克勞德的故事
  ↓
被吸引進入 #2《三維獵殺》（風險管理）
  ↓
開始思考架構設計
  ↓
點擊 Agent E04 Workflow 理論篇
  ↓
回到 #3《自動校準》（應用實踐）
  ↓
最終進入 Learning Plans（想要親手構建）
```

**成功指標**：
- 文章瀏覽 → GitHub 點擊率 15% 以上
- 讀者停留時間：平均 8+ 分鐘
- 分享率：「這個系列有點東西」的自發傳播

### 三重身份設計

| 對於... | AI蜂群投資系列是... |
|--------|-------------------|
| **Agent 系列讀者** | Workflow 理論的「投資實戰」證明 |
| **SW3 系列讀者** | 散戶基礎設施的「進階版」應用 |
| **新讀者** | 獨立完整的「科幻股市商戰」故事 |

**連結策略**：
- E01-E03：基礎三篇可獨立閱讀
- E04-E07：進階三篇依賴前期知識，需要反向連結
- 每篇都要設置指向其他系列的蜂巢動線

## ❓ 常見問題

**Q: 第 4-6 篇的大綱在哪裡？**
A: 參閱 `SWARM_系列計畫.md` 的「七篇劇情規劃」章節。每篇都有元素、場景、痛點、轉折、高潮、結尾的完整描述。

**Q: 如何確保寫作風格一致？**
A: 參考已發布的 #1、#2、#3 篇作為參照，特別是克勞德的語氣與蜂群架構的呈現方式。

**Q: 免責聲明應該怎麼寫？**
A: 使用 `免責template.MD` 作為模板，確保包含「技術架構分享、虛構情境演示、非投資建議」的聲明。

**Q: 發布到 Substack 時需要調整什麼？**
A: 檢查 `../../../出版管理/` 中的發布清單，確保格式、連結、圖片路徑都正確。

**Q: 如何與其他系列（Agent、SW3）進行交叉連結？**
A: 在蜂巢動線（結尾延伸閱讀）中添加超連結，指向對應系列的文章。使用相對路徑：`[../../技術文章/Agent系列/...]`
