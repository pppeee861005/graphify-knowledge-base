### Step 1：準備執行環境（2分鐘）

**確認以下信息已準備好**：

```

   D:\數位資產\graphify個人知識庫\系列文章\

   - Agent系列：25+

   - 其他系列：35+

✅ 定義書已讀：計劃11_提練金句_定義書.md ✓

✅ 預算書已讀：計劃11_提練金句_預算控制書.md ✓
```

### Step 2：提交執行指令給 Claude Code（3分鐘）

**複製以下指令，發給 Claude Code**：

```markdown
我要執行計劃11，提練所有系列文章的金句。

🎯 執行目標：
  • 掃描位置：D:\數位資產\graphify個人知識庫\系列文章\**\*.md
  • 文章預估：70+ 篇
  • 預期產出：200-300 條符合標準的金句
  • 分類方式：8 大系列
  • 預算：0.80單位

📋 執行標準（來自定義書）：
  • 簡潔性：≤30字
  • 深度性：超越常識的洞察
  • 通用性：適用2+場景
  • 記憶度：句式優美
  • 應用性：可指導決策

⚙️ 執行流程：
  1. 掃描所有文章，建立索引
  2. 自動提取候選金句（5維度評分）
  3. 初步篩選（過濾<3.5分）
  4. 人工審核邊界金句（3.5-4.0分）
  5. 按系列分類組織
  6. 生成8個系列文件+完整索引

⚠️ 請先生成詳細的執行計劃，包含：
  • 執行流程分解（每個環節的具體步驟）
  • 文章掃描範圍確認（哪些文章會被掃描）
  • 金句產量估計（每個系列預期多少條）
  • 成本明細清單（逐項成本和風險評估）
  • 質量保證方案（如何確保品質）
  • 輸出物確認（8個系列文件的結構）

然後提供執行確認清單：
□ A. 文章範圍 - 確認掃描範圍和文章數
□ B. 評分標準 - 確認5維度評分邏輯
□ C. 成本估算 - 確認成本分配和預留
□ D. 質量方案 - 確認審核機制和標準
□ E. 輸出物 - 確認最終產出物結構

等我確認無誤後再開始執行，不要直接執行分析。
```

## 第四部分：常見問題

### Q1：如果某個系列的金句特別少（<10條），怎麼辦？

**A**：有3個可選方案

```
方案1：合並到相近系列
  例如：逆向視覺解構系列（10條）+ 暗知識系列（20條）
  → 合並為「認知與視覺系列」（30條）

方案2：人工補充該系列金句
  1. 人工重新掃描該系列文章
  2. 找出自動化遺漏的金句
  3. 補充到該系列文件

方案3：降低該系列的入選標準
  原：≥3.5分入選
  新：≥3.0分入選（臨時放寬）

建議：採用方案2（人工補充），質量最好
```

### Q2：如何確保金句不重複？

**A**：已內置去重機制

```
自動去重規則：
  1. 完全相同：自動過濾
  2. 相似度>80%：標記為重複
  3. 同一概念多種表述：只保留最精煉版本

人工審核環節：
  再檢查一次有沒有遺漏的相似金句

預期重複率：<5%
```

### Q3：生成的金句評分不合理，怎麼調整？

**A**：有3個調整時機

```
時機1：執行前
  修改定義書中的評分規則
  例如：簡潔性的「≤30字」改為「≤40字」

時機2：執行過程中
  告訴Claude：「這條金句的評分太低/太高，原因是[原因]」
  Claude會調整規則重新評分

時機3：執行後（迭代v1.1）
  收集用戶反饋
  統計哪些金句被高頻引用
  根據實際使用調整評分

最容易的方式：執行前閱讀定義書，調整評分規則
```

### Q4：某條金句來源不清楚，怎麼處理？

**A**：3個解決方案

```
方案1：人工查找出處
  告訴Claude：「幫我找出這條金句來自哪篇文章」
  Claude會搜索並確認

方案2：標記為「出處待查」
  暫時不入選，後續補充
  標記為：[PENDING SOURCE CHECK]

方案3：刪除該金句
  如果無法確認出處，寧可刪除也不含糊

強烈建議：執行時開啟「可追溯性100%」的標準
```

### Q5：能否為金句增加「使用案例」？

**A**：可以，但需要額外成本

```
基礎執行（本計劃）：
  產出：[原文] + [出處] + [應用場景] + [相關概念]
  成本：0.80單位

增強版執行（可選）：
  +生成每條金句的「應用案例」
  例如：「現實必須服從計畫」
        → 應用案例：為什麼動態Workflow比固定計劃更優

額外成本：+0.20-0.30單位
執行時機：v1.1版本或後續迭代

建議：先完成v1.0基礎版，後續根據反饋迭代
```

### Q6：能否跨系列搜索金句？

**A**：能，分為2個版本

```
v1.0（基礎版，本計劃）：
  結構：8個系列文件 + 1個完整索引
  搜索方式：
    1. 按系列找金句
    2. 用Ctrl+F在完整索引中搜索

v1.1（增強版，後續迭代）：
  增加：多維度檢索
  例如：
    - 按主題檢索（「決策框架」相關金句）
    - 按應用場景檢索（「投資決策」相關）
    - 按系列對比檢索（Agent系列 vs Software3.0）

增強版成本：+0.15-0.20單位
建議時機：v1.0驗證成功後再做
```

## 故障排除

### 故障1：某個系列一直掃描不出金句

```
症狀：某系列的候選金句數=0 或極少

診斷：
  1. 檢查該系列文件是否存在
  2. 檢查文件中是否有足夠長的文本
  3. 檢查評分規則是否過嚴格

解決：
  1. 手動檢查該系列文件
  2. 調整該系列的評分標準（暫時降低）
  3. 人工補充遺漏金句

示例：
  原：簡潔性要求≤30字
  新：簡潔性要求≤35字（針對該系列調整）
```

### 故障2：成本突然飆升

```
症狀：執行過程中成本超支速度快於預期

診斷：
  可能原因：
  1. 某個系列文本量超預期
  2. 評分邏輯過於複雜
  3. 人工審核環節耗時過長

解決：
  Step 1：立即停止，分析超支原因
  Step 2：啟動成本控制（降級方案）
  Step 3：重新估算並提交新計劃
  Step 4：用戶確認後再繼續

參考：預算控制書 - 應急方案
```

### 故障3：生成的金句品質波動大

```
症狀：某些金句明顯不符合標準

診斷：
  可能原因：
  1. 評分規則不夠清晰
  2. 某些系列的文風偏離標準
  3. 邊界金句的判斷標準模糊

解決：
  1. 人工審核該系列的所有金句
  2. 調整該系列的評分參數
  3. 重新評分該系列
  4. 確認品質後再繼續其他系列

參考：定義書 - 評分規則調整
```
