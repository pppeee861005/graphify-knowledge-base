**狀態**：🔄 規劃中

**用途**：定義金句標準和分類邏輯，供 Claude Code 自動化提練

## 一、問題定義

### 1.1 問題陳述

✅ 清晰問題：
「從 70+ 篇系列文章中自動識別和提練符合標準的金句，按 8 大系列分類組織，建立一個可檢索、可引用、可持續更新的金句資產庫。」

### 1.2 背景與約束

**背景**：
- 知識庫已有 70+ 篇高質量系列文章
- 每篇文章都包含多個有價值的觀點
- 目前缺乏「可即時檢索的金句庫」
- 內容創作時需要頻繁查找靈感和論點

**約束條件**：
- 金句必須是原文摘錄（可略有調整，但不能改意）
- 必須能追溯到具體文章和位置
- 必須按系列分類組織
- 品質標準必須一致
- 支持未來新文章的金句自動新增

### 1.3 輸入與輸出

**輸入（Input）**：
- 類型：Markdown 文檔集合
- 規模：70+ 篇文章，約 80-100 萬字
- 格式：各系列文章的完整正文
- 位置：`D:\數位資產\graphify個人知識庫\系列文章\*\*.md`

**輸出（Output）**：
- 類型：分類組織的金句匯編
- 規模：200-300 條金句
- 格式：Markdown（每個系列一個文件）
- 結構：
  ```
  ## 金句標題
  > **原文**：[金句]
  > **出處**：[系列名] - [文章名] - [位置]
  > **應用場景**：[適用場景列表]
  > **相關概念**：[相關關鍵詞]
  ```

## 二、金句標準定義

### 2.1 「金句」的 5 維度判定標準

一句話必須同時滿足以下 5 個條件才能被認定為「金句」：

#### 維度1：簡潔性 （Conciseness）✅
- **標準**：句子長度 ≤ 30 個字（中文）
- **理由**：便於記憶和引用
- **判例**：
  - ✅ 「計畫永遠趕不上變化。」
  - ❌ 「當環境發生變化時，事先制定的計畫就會變得不再適用，因為原來的假設條件已經改變了。」

#### 維度2：深度性 （Depth）✅
- **標準**：包含非顯而易見的洞察，超越常識
- **理由**：提供思想增值
- **判例**：
  - ✅ 「你不是沉迷，你是被設計成沉迷的。」
  - ❌ 「使用手機時要控制時間。」

#### 維度3：通用性 （Universality）✅
- **標準**：能應用到多個場景，不過度特殊化
- **理由**：增加複用價值
- **判例**：
  - ✅ 「對抗是最弱的策略。」（投資、工作、人生通用）
  - ❌ 「買入價位是 150 元時應該如何操作。」（過於特殊）

#### 維度4：記憶度 （Memorability）✅
- **標準**：句式優美、比喻生動、節奏感強
- **理由**：便於記憶和傳播
- **判例**：
  - ✅ 「用更強的引力，吸走更弱的引力。」（有比喻）
  - ❌ 「應該採用更優的方法來替代劣方法。」（平淡）

#### 維度5：應用性 （Applicability）✅
- **標準**：讀者能立即應用到實際工作或思考中
- **理由**：實現知識到行動的轉化
- **判例**：
  - ✅ 「現實必須服從計畫。但市場從來不服從任何人的計畫。」（啟發決策思維）
  - ❌ 「過去發生過這樣的事情。」（陳述事實，無指導意義）

### 2.2 評分體系

每條金句在 5 個維度上評分（1-5 分）：

```
綜合評分 = (簡潔性 + 深度性 + 通用性 + 記憶度 + 應用性) / 5

≥4.5 分：★★★★★ 必須入選（核心金句）
4.0-4.4 分：★★★★☆ 強烈推薦入選
3.5-3.9 分：★★★☆☆ 推薦入選（可選）
<3.5 分：★★☆☆☆ 不推薦入選
```

### 2.3 入選標準

- ✅ **必須入選**：≥4.5 分的金句（無例外）
- ✅ **推薦入選**：4.0-4.4 分的金句（重點考慮）
- ⚠️ **人工審核**：3.5-3.9 分的金句（由人工判斷）
- ❌ **不入選**：<3.5 分的金句

## 四、提練流程

### 4.1 流程概述

```
Step 1: 文件掃描
  ↓ 識別所有 .md 文件
  ↓

Step 2: 自動提取（Claude 自動化）
  ↓ 基於 5 維度評分識別候選金句
  ↓

Step 3: 初步篩選（自動規則）
  ↓ 過濾低於 3.5 分的金句
  ↓

Step 4: 人工審核（精細化）
  ↓ 人工確認 3.5-4.0 分的邊界金句
  ↓ 確保品質一致性
  ↓

Step 5: 分類和標籤（自動化）
  ↓ 按系列和主題組織
  ↓

Step 6: 生成資產
  ↓ 8 個系列文件 + 1 個完整索引
```

### 4.2 自動評分規則

Claude 需要基於以下規則自動評分：

```
簡潔性評分：
  5分：≤15字，高度精煉
  4分：16-25字，簡潔清晰
  3分：26-35字，尚可
  2分：36-50字，略長
  1分：>50字，過長

深度性評分：
  5分：顛覆認知的洞察
  4分：超越常識的觀點
  3分：有一定深度的觀點
  2分：表面認知，缺乏深度
  1分：常識或陳述事實

通用性評分：
  5分：適用3個以上場景
  4分：適用2-3個場景
  3分：適用1個主要場景
  2分：適用場景有限
  1分：單點特殊場景

記憶度評分：
  5分：句式優美，易於記憶和傳播
  4分：有亮點，相對易記
  3分：清晰易懂
  2分：平淡無奇
  1分：冗長乏味

應用性評分：
  5分：可直接指導決策或思維
  4分：能啟發思考
  3分：有參考價值
  2分：啟發有限
  1分：無直接應用價值
```

## 五、驗證標準

### 5.1 成功指標

| 指標 | 衡量方式 | 目標 |
|------|---------|------|
| **金句總數** | 提練的金句條數 | 200-300 條 |
| **系列覆蓋率** | 涵蓋的系列數 / 總系列數 | 100% (8/8) |
| **自動識別準確率** | 自動提出的金句中符合標準的比例 | ≥85% |
| **人工審核通過率** | 人工確認的金句中最終入選的比例 | ≥90% |
| **重複率** | 重複或相似金句的比例 | <5% |
| **可追溯性** | 每條金句都有出處記錄 | 100% |

### 5.2 驗收條件

- [ ] 生成了 8 個系列的金句匯編文件
- [ ] 每個系列至少 20 條金句（軟體3.0等小系列可例外）
- [ ] 每條金句都包含：原文、出處、應用場景、評分
- [ ] 完整索引文件已生成
- [ ] 人工審核已完成，品質達標
- [ ] 金句可正確集成到 dw.md

### 5.3 失敗標準

- 若 自動識別準確率 < 70% → 需要調整評分規則，重新執行
- 若 人工審核發現大量重複 → 需要優化去重邏輯
- 若 某個系列金句 < 10 條 → 考慮是否應併入其他系列

## 六、執行策略

### 6.1 執行配置

```yaml
掃描範圍: D:\數位資產\graphify個人知識庫\系列文章\**\*.md
文章預估數: 70+
字數預估: 80-100萬字
預期金句數: 200-300條
分類系統: 8大系列 + 跨系列標籤

自動化程度:
  - 文件掃描: 100% 自動化
  - 金句提取: 80% 自動化 + 20% 人工
  - 分類組織: 100% 自動化
  - 品質審核: 50% 自動化 + 50% 人工
```

### 6.2 降級條件

若 Token 消耗達到 80% 時：
- 停止深度分析，只保留 ≥4.0 分的金句
- 跳過邊界金句（3.5-4.0）的人工審核
- 標記為 PARTIAL_COMPLETION（部分完成）
- 生成初稿金句庫，後續可補充完善

### 6.3 升級條件

若 發現某系列金句品質特別高（平均分 ≥4.5）：
- 增加該系列的金句提取數量
- 加深該系列的應用場景標籤
- 生成該系列的「深度金句」子集

## 七、預算分配

### 7.1 預算概況

**總預算**：0.50-0.70 單位
**預留率**：≥40%（應急費用）
**說明**：預算主要用於文本分析、金句評分、人工審核

### 7.2 成本估算

| 項目 | 成本 |
|------|------|
| 文件掃描和預處理 | 0.05 單位 |
| 自動金句提取（全文分析） | 0.15 單位 |
| 5 維度自動評分 | 0.10 單位 |
| 邊界金句人工審核（3.5-4.0分） | 0.10 單位 |
| 分類和標籤自動化 | 0.08 單位 |
| 最終審核和優化 | 0.05 單位 |
| 生成資產和整合 | 0.02 單位 |
| **小計** | **0.55 單位** |
| **應急預留（40%）** | **0.25 單位** |
| **總計** | **0.80 單位** |

### 7.3 監控機制

- 成本監控關鍵點：20%（初期掃描）、50%（自動提取）、80%（審核）
- 成本超支應急：
  - 若超過 60% → 減少邊界金句審核深度
  - 若超過 80% → 停止新增分析，完成初稿輸出
