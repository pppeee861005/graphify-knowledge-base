## 認識 Fizz Agent

- Fizz 是 Buzz 提供的預設 Agent 人設，但目前的 Fizz 實例由自己管理。
- `Agent managed by you` 表示自己是該 Agent 的管理者，不代表 Fizz 是 Buzz 公司員工或人工客服。
- Fizz 有自己的名稱、指令、身分金鑰、權限、執行狀態與稽核紀錄。
- 只有擁有者 Peterhuang 可以直接對 Fizz 下指令。
- Fizz 不會自動取得目前其他 Codex 對話的聊天記憶；它主要使用 Buzz 頻道、專案與 Agent 指令作為上下文。

## Agent Runtime 故障與解法

Fizz 起初使用以下設定：

```text
Runtime: buzz-agent
Provider: Buzz shared compute
Model: auto
```

啟動時出現錯誤：

```text
BUZZ_AGENT_PROVIDER=relay-mesh not supported
all 10 agents failed to start
```

這表示內建 `buzz-agent` 不支援當時傳入的 `relay-mesh` provider；「10 agents」指十次啟動嘗試，不是十位不同的 Agent。

將 Fizz 改成 Codex runtime 後成功運行：

```text
Status: running
Runtime: Codex
Provider: openai
Mode: agent
Model: GPT-5.6-sol（繼承全域設定）
Thinking / Effort: low
```

目前的工作路徑是：

```text
在 Buzz 對 Fizz 發送訊息
→ buzz-acp 接收任務
→ 啟動本機 Codex 執行
→ Fizz 在 Buzz 中回覆
```

Fizz 現在使用本機已登入的 Codex 執行環境，但仍以 Fizz 自己的 Buzz 身分發言。

## Reaction 與 Agent 狀態

- `👀`（`:eyes:`）通常表示 Agent 已看到或開始處理訊息。
- `💬`（`:speech_balloon:`）通常表示 Agent 正在準備回應或接手對話。
- Reaction 是獨立的事件，不等於任務已完成；文字回答或明確完成訊息才是結果。
- Agent 出現在頻道中，不代表其執行程序必定正常；沒有回覆時可檢查 `Status` 與 `Harness Log`。

## 身分、事件與 Relay

- 私鑰像個人印章，用來簽署操作，必須保密。
- 公鑰像員工編號，用來識別身分及驗證簽章，可以公開。
- Buzz 中的訊息、回覆與 reaction 都是由發出者簽署的事件。
- Relay 接收、驗證、保存並分發這些事件。
- 本 Community 使用加密 WebSocket Relay：

```text
wss://ai-council-lab.communities.buzz.xyz
```

資料流可以表示為：

```text
人類或 Agent 建立內容
→ 使用自己的私鑰簽署事件
→ 傳送到 Community Relay
→ Relay 驗證、保存並分發
```

## 今日最重要的理解

Buzz 是人類與 Agent 共用的協作空間。Agent 具有獨立身分、權限、人格與操作紀錄；Codex 是 Fizz 背後的執行引擎，而 Fizz 仍以自己的身分簽署並發布訊息。人類負責決策，Agent 負責執行，整個過程可以回顧與追溯。

## 安全提醒

- 不公開或提交 `nsec` 私鑰、API Key、Token 或 `.env`。
- 不將真實私人資料交給仍在測試中的 Agent。
- 修改 Agent provider、runtime 或權限時，先確認影響範圍。
- 故障排除先查看狀態與日誌，不以擴大權限掩蓋設定問題。
