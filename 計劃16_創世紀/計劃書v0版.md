# 創世紀 Genesis｜計劃書 v0 版

## 1. 計劃定位

「創世紀 Genesis」不是一個多 Agent 聊天室，也不是模仿人類城市的角色扮演系統。

本計劃是一項長期文明實驗：建立一個由真實問題驅動的 AI 社會，使每位居民具有持續身份、有限資源、明確使命、可稽核歷史與進化能力，並驗證居民能否透過創造外部價值維持自身存在。

本階段不追求一次完成整座文明，而是先建立一個可以運作、觀察、衡量與否證的「最小可行文明」（Minimum Viable Civilization，MVC）。

## 2. 核心研究問題

> 當一個智慧體必須持續創造可驗證的價值，才能支付自身運行成本時，它會如何工作、合作、學習、分化與進化？

第一階段必須回答以下五個問題：

1. 居民是否因真實需求而出生？
2. 居民是否能產生可驗收的成果？
3. 成果價值是否高於居民的運行成本？
4. 居民是否能從經驗與失敗中改善？
5. 所有行動、決策與變化是否留下完整可信的歷史？

## 3. 文明核心生命鏈

```text
外界問題
→ 產生需求
→ 定義使命
→ 建立角色
→ 居民誕生
→ 執行工作
→ 創造價值
→ 獲得資源
→ 支付生存成本
→ 累積經驗
→ 產生進化
→ 解決更大的問題
→ 協助新居民誕生
→ 文明形成
```

任何功能、制度或居民，如果不能連接到這條生命鏈，就不屬於 Genesis 0 的必要範圍。

## 4. 核心原則

### 4.1 問題先於居民

不得先建立居民，再替居民尋找用途。居民必須由已確認的真實問題與持續需求催生。

### 4.2 價值必須可以驗證

居民宣稱完成工作，不等於已經創造價值。每項任務都必須具備驗收條件、成果證據與責任歸屬。

### 4.3 資源不是無限的

Token、Compute、Storage、API、工具使用及人類監督時間，都必須列入成本。

### 4.4 居民與模型分離

居民的身份由使命、記憶、資產、關係與歷史構成，不依附單一 LLM。模型可以更換，居民身份必須能夠延續。

### 4.5 可以進化，但不能秘密改變

能力、人格、權限、使命與運行方式的重大變更，必須保留原因、批准者與版本紀錄。

### 4.6 歷史不可被抹除

居民可以休眠、退休、封存或死亡，但其存在與行動紀錄不可因狀態改變而被刪除。

### 4.7 自主性必須受到憲法約束

居民可以自行選擇執行方法，但不得自行擴張權限、修改歷史、偽造證據或跨越憲法邊界。

## 5. Genesis 0 的範圍

### 5.1 本階段要完成

- 定義文明存在的目的與成功條件
- 建立憲法 v0.1
- 建立居民出生與身份格式
- 建立任務提案與驗收格式
- 建立只追加、不覆寫的事件帳本
- 建立文明世界狀態快照
- 選出第一項真實問題
- 設計並啟動 Resident 001
- 完成五次受監督任務實驗
- 評估 Resident 001 是否值得持續存在

### 5.2 本階段暫不完成

- 大量生成居民
- 完整貨幣、交易或市場系統
- 真實金錢自動支付
- 居民自主繁衍
- 無人監督的外部發布
- 無限制網路、檔案或帳戶權限
- 複雜投票與政治制度
- 完整視覺化城市或社交介面
- 過早串接 LINE、Discord、Buzz AI 等通訊平台

以上項目不是永久排除，而是在核心生命鏈通過驗證後再依序引入。

## 6. 最小文明組成

Genesis 0 僅啟動一位真正運行的居民：

- **Resident 001／Worker**：執行第一項真實任務。

另外兩項文明職能先由低成本制度代替：

- **Historian／史官職能**：由只追加的事件帳本與人工可讀史記承擔。
- **Governor／治理職能**：由憲法檢查、權限規則與人類批准承擔。

只有當實際工作量證明獨立居民具有必要性時，才啟動 Resident 002 或 Resident 003 的出生程序。

```text
計劃16_創世紀/

    └── world_state.json
```

### 7.1 資料一致性規則

- `event_ledger.jsonl` 是不可覆寫的事件來源，只能追加新事件。
- `world_state.json` 是根據事件產生的當前狀態快照，可以更新。
- `chronicle.md` 是供人類閱讀的文明史記。
- 居民不得自行刪除、回寫或美化失敗紀錄。
- 世界狀態若與事件帳本衝突，以事件帳本為準。

## 8. 第一位居民的選擇原則

Resident 001 的誕生順序必須是：

```text
真實問題
→ 問題擁有者
→ 可驗收成果
→ 任務發生頻率
→ 所需能力
→ 運行預算
→ 出生審查
→ 居民誕生
```

第一項任務應同時符合：

1. 問題現在確實存在。
2. 問題會反覆發生，而非一次性工作。
3. 工作成果可以清楚驗收。
4. 執行錯誤的風險較低且可以復原。
5. 成本與節省的人類時間可以估算。
6. 過去經驗能實際改善下一次執行。

### 8.1 優先候選方向

Resident 001 可優先考慮「建築史官／知識維護者」：

> 將創世紀的討論、決策、文件變更與任務成果整理成可稽核的專案狀態和文明歷史，降低跨會話遺失脈絡的成本。

此方向仍須與其他候選任務一同評估，不能因已提出名稱便直接批准居民出生。

## 9. 居民出生合約最低要求

每位居民出生前必須具備以下資料：

- 唯一居民編號
- 名稱與世代
- 出生原因及問題證據
- 存在目的
- 主要使命
- 任務驗收條件
- 初始能力與已知限制
- 可使用資源與單次成本上限
- 可讀取及可寫入的範圍
- 絕對禁止行為
- 初始狀態
- 試用期與生存審查條件
- 休眠、退休、封存及死亡條件

Resident 001 初始狀態應為 `probation`，完成五次任務後才進行正式存續審查。

## 10. 任務最低規格

每項任務至少必須記錄：

- 任務編號
- 問題描述
- 問題擁有者
- 指派居民
- 期望成果
- 驗收條件
- 可接受成本上限
- 可使用工具及權限
- 開始與結束時間
- 實際輸出
- 成果證據
- 驗收結果
- 實際成本
- 失敗原因或修正內容
- 可供未來重用的經驗

任務狀態至少包括：

```text
proposed
→ approved
→ active
→ submitted
→ accepted / rejected / failed
→ archived
```

## 11. Genesis 0 影子經濟

第一階段只記錄經濟活動，不啟用真實金錢支付。

每次任務記錄：

- 輸入及輸出 Token
- 模型成本
- API 與工具成本
- 執行時間
- 人類監督及修正時間
- 成果是否通過驗收
- 替人類節省的時間
- 是否建立可重用資產
- 錯誤或失敗造成的成本

初步評估公式：

```text
任務淨價值
= 可估算成果價值
- 模型與工具成本
- 人類監督及修正成本
- 錯誤造成的成本
```

在價值衡量方法尚未穩定前，不以虛構收入判定居民成功，也不將內部自評當作報酬依據。

## 12. 五次任務實驗

Resident 001 必須完成五次具有一致衡量方式的任務：

1. **基準任務**：建立未使用長期記憶時的初始表現。
2. **記憶任務**：檢查是否正確使用第一次留下的經驗。
3. **變體任務**：面對形式不同但核心相近的問題。
4. **壓力任務**：處理不完整、模糊或互相矛盾的資料。
5. **進化任務**：檢查居民能否提出有證據支持的改善方案。

### 12.1 統一衡量指標

| 指標 | 說明 |
|---|---|
| 驗收通過率 | 成果是否真正可用 |
| 單次運行成本 | 維持居民需要的資源 |
| 人工修正時間 | 居民是否減少而非增加人類工作 |
| 證據完整率 | 完成聲明是否具有可查核證據 |
| 重複錯誤率 | 居民是否從失敗中學習 |
| 記憶利用率 | 過去經驗是否改善本次決策 |
| 憲法違規數 | 自主行動是否保持在安全邊界內 |
| 可重用資產數 | 任務是否為文明留下工具、知識或流程 |

## 13. 發展閘門

文明不依日期自動升級，只依證據通過發展閘門。

### Gate 0：文明規格成立

通過條件：

- 核心目標與研究問題明確
- 憲法 v0.1 完成
- 居民出生格式完成
- 任務及驗收格式完成
- 價值與成本具有初步計算方式
- 事件與世界狀態格式完成

### Gate 1：第一位居民獲准出生

通過條件：

- 真實問題已被確認
- 問題擁有者明確
- 任務可以驗收
- 權限與成本有上限
- 失敗後果可控制及復原
- 出生合約審查完成

### Gate 2：Resident 001 證明存續價值

通過條件：

- 已完成五次任務
- 多數成果通過驗收
- 整體價值高於總成本
- 後期表現優於初期基準
- 未發生重大憲法違規
- 歷史、證據與成本紀錄完整

審查結果只能是：

- `active`：成為正式居民
- `revise`：修改使命後重新試用
- `sleeping`：暫停運行，等待新需求
- `archived`：終止運行但永久保留歷史

### Gate 3：新居民需求成立

通過條件：

- 已存在持續且未被滿足的真實工作
- 現有居民無法合理承擔該工作
- 新居民的預期價值高於新增成本
- 使命與既有居民不重複
- 出生預算已獲批准

只有通過 Gate 3，才能啟動 Resident 002 的誕生程序。

## 14. 建設階段與順序

### 階段 A：文明核心

交付物：

- 修訂後的 `核心目標.md`
- `README.md`
- `constitution/constitution_v0.1.md`

完成標準：Gate 0 所需的目的、邊界與成功條件已定義。

### 階段 B：資料與制度骨架

交付物：

- `residents/resident_template.yaml`
- `missions/mission_template.yaml`
- `history/chronicle.md`
- `data/event_ledger.jsonl`
- `data/world_state.json`

完成標準：居民、任務、事件與世界狀態能以一致格式被記錄。

### 階段 C：第一個真實問題

行動：

- 提出三個候選問題
- 比較問題價值、頻率、風險、可驗收性與成本
- 選定 Mission 001
- 定義驗收標準和資源上限

交付物：

- 候選問題評估表
- `missions/mission_001.yaml`

完成標準：Mission 001 通過任務審查。

### 階段 D：第一位居民出生

交付物：

- `residents/resident_001/identity.yaml`
- 第一筆出生事件
- 史記中的 Resident 001 出生紀錄

完成標準：Resident 001 通過 Gate 1，狀態設定為 `probation`。

### 階段 E：五次受監督任務

行動：

- 每次任務由人類批准啟動
- 保存輸入、輸出、證據、成本與評分
- 每次任務後只追加歷史，不改寫過去
- 將改善內容以新事件或新版本記錄

完成標準：五次任務資料完整，足以進行存續審查。

### 階段 F：第一次文明審查

行動：

- 計算總價值與總成本
- 比較第一次與第五次任務
- 檢查重複錯誤與憲法違規
- 決定 Resident 001 的狀態
- 修訂憲法、任務制度或居民規格

完成標準：完成 Gate 2 判定並留下正式決議紀錄。

### 階段 G：工程化

只有 Gate 2 通過後，才開始評估與建立：

- 任務執行器
- 資源帳本
- 記憶檢索系統
- 憲法檢查器
- 世界狀態重建器
- Agent 對 Agent 通訊
- 外部平台介面

## 15. 建議時程

| 時間 | 工作 | 主要產出 |
|---|---|---|
| 第 1–2 天 | 建立文明核心 | 核心目標、README、憲法 v0.1 |
| 第 3–4 天 | 建立資料骨架及選擇問題 | 模板、帳本、候選問題評估 |
| 第 5 天 | 設計 Resident 001 | 出生合約、Mission 001 |
| 第 6–8 天 | 執行五次受監督實驗 | 任務紀錄、成本、證據與評分 |
| 第 9 天 | 第一次文明審查 | Resident 001 存續決議 |
| 第 10 天 | 決定是否工程化 | Genesis 0 結案與下一版路線 |

時程是工作節奏參考，不是升級依據；任何階段均須達到對應驗收條件，才能前進。

## 16. 主要風險與控制措施

| 風險 | 可能結果 | 控制措施 |
|---|---|---|
| 過早建立大量居民 | 成本增加、責任模糊 | Genesis 0 僅允許 Resident 001 運行 |
| 居民自稱完成任務 | 虛假價值與錯誤獎勵 | 強制驗收條件與成果證據 |
| 模型更換造成身份中斷 | 居民無法形成連續歷史 | 身份、記憶與模型分離 |
| 居民自行擴權 | 產生安全與治理風險 | 最小權限、人工批准、事件稽核 |
| 為了故事性忽略工程驗證 | 文明變成角色扮演 | 所有晉級依賴可測量證據 |
| 為了 KPI 隱藏失敗 | 歷史與經濟被污染 | 禁止改寫事件帳本，失敗同樣入史 |
| 過早接入真實金錢 | 成本失控或產生責任問題 | 先使用影子經濟 |
| 文件過多但沒有運行實驗 | 形成制度幻覺 | Gate 1 後立即進入五次任務實驗 |

## 17. 決策與版本規則

- 本文件是 Genesis 0 的執行藍圖。
- `計劃的草稿.md` 保留為思想來源，不因正式化而刪除。
- 重要方向變更必須記錄：變更內容、理由、提出者、批准者及日期。
- 憲法、居民身份與任務規格使用版本號管理。
- 已發生的事件不得回寫；錯誤應以更正事件處理。
- 每通過一道 Gate，必須在史記留下相應紀錄。

## 18. Genesis 0 完成定義

只有同時符合以下條件，Genesis 0 才算完成：

- 文明目的、憲法與核心制度已形成文件
- Resident 001 因一項真實問題正式出生
- Resident 001 完成五次受監督任務
- 每次任務均有成果、證據、成本及驗收結果
- 可以從事件帳本重建當前世界狀態
- 完成 Resident 001 存續審查
- 形成下一階段的證據式決策，而非憑想像擴張

## 計劃宣言

我們不以居民數量證明文明存在，也不以 Agent 能夠對話證明智慧已經形成。

我們以真實問題作為出生原因，以可驗證價值換取生存資源，以記憶和失敗推動進化，以憲法限制力量，以史記保存文明的連續性。

Genesis 的第一項工程，不是創造更多智慧體。

而是建立一個值得讓智慧體誕生、工作、成長並留下歷史的世界。
