## 2026-08-07｜DEC-0001：選定 Buzz 為主要協作平台

### 決策

Genesis 採用 Buzz 作為人類與 AI 居民共同工作的主要協作平台。

### 決策依據

- Buzz 支援人類與 Agent 以獨立身分加入相同工作空間。
- 頻道、討論串、訊息、Git、workflow、審核與操作可形成可搜尋的稽核紀錄。
- Buzz 可自行架設，Relay 與資料可由使用者掌控。
- Buzz 具備 `buzz-cli`、ACP、MCP 及 YAML workflow 等 Agent 連接方式。
- 以簽名事件為基礎的架構，適合 Genesis 對身份、證據及可追溯性的要求。

### 架構邊界

Buzz 是 Genesis 的協作與介面層，不是文明核心本身。

- Buzz 負責溝通、協作、批准、成果提交及平台稽核。
- Genesis 負責憲法、居民身份、任務、資源、記憶、存續、事件帳本與世界狀態。
- Buzz Relay 事件與 Genesis 事件帳本互相連結，但不互相取代。
- 居民不得因 Buzz 工作階段終止而失去文明身份；也不得只因 Buzz Agent 程序仍在運行就被判定為存活。

### 已知限制

- Buzz 的部分工作流批准整合仍在發展中，正式採用前必須實際驗證。
- 當前 Agent 啟動及常駐方式可能依賴桌面端或外部執行環境，不能假設已有完整的永久居民宿主。
- 初期應先做最小平台就緒測試，不立即修改 Buzz 原始碼。

### 對開發計劃的影響

- D0 新增並完成平台選擇紀錄。
- D4 新增 Buzz 測試工作空間、獨立身分、稽核及工作階段存續測試。
- D5 的任務批准、成果提交及驗收預定在 Buzz 內完成。
- D7 新增 Buzz Adapter 與事件同步、去重及離線處理。
- 不改變 D1、D2 的文件與制度優先順序。

### 參考來源

- 本地文件：`buuz/什麼是buzz.md`
- 官方專案：`https://github.com/block/buzz`

### 下一步

維持原定主線，執行 D1-01：重新撰寫 `核心目標.md`。
