# 📋 計劃9：PSA Viral Workflow DW 轉向詳細實施計劃

**版本**：1.0
**發佈日期**：2026-06-04
**狀態**：📋 規劃就緒，等待執行確認

---

## 🎯 核心轉向目標

### 從現狀到願景

**現狀**：
- PSA Viral Workflow 是一個「6 階段內容寫作自動化工作流」
- 提供完整的代碼實現
- 針對內容創作者（特別是 Substack 寫手）
- 用戶需要運行代碼來執行工作流

**願景**：
- 轉向為「**內容寫作和發佈的 DW 應用場景示範**」
- 提供「**定義書」而非「代碼」**
- 任何內容創作者（無需懂代碼）都能理解和使用
- Claude Code 自動生成工作流代碼

### 一句話轉向

```
從「我們提供完整的內容寫作代碼」
↓
變為「我們教你定義內容寫作流程，Claude Code 自動生成工作流」
```

---

## 📊 轉向前後對比

| 維度 | 轉向前 | 轉向後 |
|------|--------|--------|
| **定位** | 內容寫作自動化工具 | DW 應用場景示範（內容創作） |
| **交付物** | 6 階段工作流代碼 | 定義書 + 預算控制書 + 教學 |
| **目標用戶** | 技術用戶（懂代碼） | 所有內容創作者（無需懂代碼） |
| **複用方式** | 複製代碼、修改參數 | 修改定義書、自動生成代碼 |
| **社群參與** | Bug 報告、代碼改進 | 改進定義書、多內容類型實現 |
| **生態角色** | 獨立工具 | 計劃7 DW 生態的應用場景 |
| **時間到發佈** | 7-10 天（人工執行） | 7-10 天（自動工作流） |

## 🚀 6 個執行步驟

### Step 1：創建「內容寫作定義書」（5,000-6,000 字）

**內容範圍**：

#### Section 1：工作流概述
- PSA 工作流的 6 個階段
- 每個階段的目標和輸出
- 整體時間表（7-10 天）

#### Section 2：核心場景和配置
```
場景 1：Substack 内容寫作
  - 目標：30-40% 開啟率，2-3% 轉換率
  - 內容長度：1,200-1,500 字
  - 發佈平台：Substack + LinkedIn + Twitter
  - 目標受眾：科技、商業、自我提升

場景 2：產品發布公告
  - 目標：產品上市，建立話題
  - 內容長度：800-1,000 字
  - 發佈平台：公司博客 + 社交媒體

場景 3：課程模塊發布
  - 目標：課程宣傳，學生註冊
  - 內容長度：1,500-2,000 字
  - 發佈平台：社群 + Email
```

#### Section 3：6 個階段的決策規則

**Stage 1：規劃階段（Planning）**
```
決策規則：
  - 定義目標受眾
  - 確定內容角度（問題驅動 vs 故事驅動 vs 數據驅動）
  - 設置成功指標（開啟率、轉換率、新訂閱者）

輸入：主題、目標受眾、發佈平台
輸出：內容戰略、角度、目標指標
```

**Stage 2：大綱設計階段（Outline）**
```
決策規則：
  - 5 層框架（Opening → Comparison → Deep Dive → Case Studies → CTA）
  - 「金句」設計（引發共鳴的金句）
  - 內容長度檢查

輸入：內容戰略、核心觀點
輸出：詳細大綱、金句、預期字數
```

**Stage 3：寫作階段（Drafting）**
```
決策規則：
  - 寫作風格（專業 vs 對話式 vs 故事性）
  - 段落長度（短段落 = 易於閱讀）
  - 視覺元素（emoji、粗體、列表）

輸入：大綱、金句
輸出：初稿（1,200-1,500 字）
```

**Stage 4：審核階段（Review）**
```
決策規則：
  - 7 層質量檢查
    1. 邏輯檢查（論點是否連貫）
    2. 開啟率檢查（標題是否吸引人）
    3. 轉換率檢查（CTA 是否清晰）
    4. 長度檢查（是否符合目標字數）
    5. 風格檢查（是否符合作者風格）
    6. SEO 檢查（關鍵詞分佈）
    7. 最終檢查（語法、拼寫）

輸入：初稿
輸出：修改建議、修改後的稿件
```

**Stage 5：發布階段（Publishing）**
```
決策規則：
  - Substack 發布（設置標題、描述、類別）
  - 社交媒體發布（自動生成不同平台的文案）
    - LinkedIn：專業版本 + 見解
    - Twitter：3-5 條推文線程
    - Facebook：社群版本
  - 時間安排（最佳發布時間）

輸入：最終稿件
輸出：已發布文章 + 社交媒體帖子
```

**Stage 6：數據分析階段（Post-Review）**
```
決策規則：
  - 收集指標（開啟率、閱讀時間、轉換）
  - 對比目標（是否達到預期）
  - 識別成功要素（什麼有效、什麼無效）
  - 改進建議（下一篇如何優化）

輸入：發布後 3-7 天的數據
輸出：數據報告、改進建議
```

#### Section 4：配置參數

```javascript
// 時間參數
const TIMELINE = {
  planning: 1,      // 天

  post_review: 3-7, // 天後開始分析
  total: 7-10       // 總時間

  target_word_count: 1200-1500,
  opening_length: 100-150,      // 開場段落
  comparison_length: 300-400,    // 對比段落
  deep_dive_length: 400-500,     // 深度分析
  case_studies: 2-3,             // 案例數量
  cta_length: 50-100            // 行動呼籲
}

// 目標指標
const SUCCESS_METRICS = {
  open_rate: '30-40%',
  conversion_rate: '2-3%',
  new_subscribers: '15-25',
  completion_rate: '75-80%',
  avg_read_time: '5-8 minutes'
}
```

#### Section 5：異常處理

```
異常 1：寫作卡住（無法進展）
  → 建議：使用「故事驅動」框架或「對話式」風格
  → 重新開始第 3 階段

異常 2：內容超長（> 2,000 字）
  → 建議：分成 2 篇文章或刪除低價值內容
  → 返回第 4 階段（審核）

異常 3：開啟率低於預期（< 20%）
  → 分析：標題是否吸引人？受眾是否匹配？
  → 改進建議：A/B 測試標題

異常 4：發布時機不對
  → 建議：查看受眾最活躍時間
  → 重新安排發布時間
```

#### Section 6：成功指標

```
整體成功指標（Stage 6 數據分析）：

維度 | 目標值 | 度量方式
------|--------|--------
開啟率 | 30-40% | Substack 統計
轉換率 | 2-3% | UTM 追蹤、分析工具
新訂閱 | 15-25 | Substack 訂閱數
閱讀時間 | 5-8 分鐘 | 分析工具平均
完成率 | 75-80% | （完整閱讀 / 開啟）
社交參與 | LinkedIn 評論、shares | 社交媒體統計
```
